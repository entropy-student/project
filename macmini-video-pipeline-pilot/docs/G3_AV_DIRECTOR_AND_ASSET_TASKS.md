## 0. Reviewer 核心导演决策

**从“文字需要配什么图”，改为“观众此刻需要看见什么，才能理解并相信？”**

这期的中心视觉不是 Mac mini 的产品特写，而是一个反复出现的“真实任务选择器”：
- 起点：作者已经有一台电脑，却想买 Mac mini。呈现为**一台待购机器**。
- 关键发现：同一个盒子在屏幕中央分解成**三个不同任务**：A 本地桌面工作、B 本地 AI/常开程序、C 公网网站。
- 核心转折：选 C 时，Mac mini 即使显示「闲置 4W」，从“家里的机器”到“别人能打开的网站”之间仍存在供电、网络、路由/访问、维护等必经路径。
- 回收：三个任务分别落到「需求条件/可行方案」而不是毫无根据的“Mac mini 必买/必不买”。

**重要判断**：现有 G2 文案可以进入 G3，不先重写整篇。G3 发现 3 处配音/文案可能需要在 G4 做局部剪改：
1. 开场 A / B 的产品赞美、心动信息可能重复。画面如果已经证明体积和价差，**考虑删减「存在感不高，想象空间倒是挺大」或压短 B**，但本 Gate 不擅自改 G2 接受稿。
2. C/D 三种用途易变成“教科书列举”，**必须让同一个「我已经有电脑 / 我想做网站」的场景贯穿**；不以长参数表取代案例。
3. E 「我突然发现」是作者第一人称写作，不代表已经有真实体验。宜用**资料推理/画面演绎**而非伪造断电事故；若 Owner 不认可该经历口吻，G4 只改局部句子。

## 1. 版式系统：沿用此前用户视频模板意图，但不锁死未验证资产

- 目标：B站横屏 16:9，建议工作画布 `1920×1080`；30 fps 为候选，实际在 G4 渲染测试时确定。
- **一块主讲述区**：优先容纳产品官网截图、真实桌面录屏、三分流任务与路径动画。不能全程把主画面缩成很小的「PPT幻灯片」。
- **字幕区**：主画面下方 1–2 行口播字幕，较大简体中文、随音频对齐；不在 G3 伪造逐字时间戳。
- **左上角**：可沿用 `01 / N` 或 `01-05 / N` 分镜导航意图；N 应由实际分镜数量自动生成，不把 14 个语义节拍硬编码为最终镜头数。
- **角落解说小人**：可复用现有循环动画，前提是 G4 真正拿到可用文件与许可；人物始终允许隐藏/缩小，**证据特写时不挡原文和价格**。没有角色文件时不应阻断核心视觉预演。
- **视觉风格**：最小视觉系统 1 套；浅/深中性底 + 单色强调 + 大号事实数字/证据框，减少花哨转场。沿用用户既有品牌样式须以实际模板为准，G3 不凭记忆假设源文件已在仓库。
- **信息密度**：每一次主画面变化只承担一个新理解；持续存在的三用途图可以复用而非每次重画。避免机械「一句口播一张图片」与逐段清屏。
- **字幕/角标与事实截图冲突时**：隐藏角标/解说小人，放大证据优先。每处截图可显示来源名、日期、适用机型，但不能误导为真实购买页面或本人跑分。

**视听裁判原则**：
- 必须用画面看明白 AV05 三种任务分流与 AV11 访问依赖；旁白即使简化，也不能靠字幕补完逻辑。
- AV02/AV10 出现**截图与放大**，要有原页面上下文/来源标签；不能只动画生成「苹果官方声称」而不给证据。
- AV08/AV11 不能视觉暗示实测性能或真实宕机。
- AV13 不能一屏出现太多文字；每个条件卡只留一问+一条建议（完整边界由口播承担）。
- **14 只是语义节拍计数**，最终剪辑镜头数、每节拍时长、标题比例均待 G4 实际测试确认。

## 4. 核心动效方案：不是 AE 才能完成

### 方案 P1｜「一台设备 → 三个不相等的任务」(AV04→AV05→AV13)

**建议技术**：HTML/CSS 或 Remotion 轻量动画（以 G4 实际可用工具为准）；不依赖视频生成模型和付费 API。

动画语义：
1. 中心显示自制 Mac mini 简化矩形模型（不得当作官方照片），上方「一台 Mac mini」；
2. 其背后短暂叠加三种“我希望它替我做”的卡片；
3. 旁白到「都能做」时短暂停顿，三条分支从中心移到不同位置并各自长出目标标签；
4. 用**不同动作**区分：A「我坐在电脑前操作」、B「程序在本地运行」、C「访客在网上访问」；
5. 画面保留小型三分支导航，后续 C/D/E 讲哪类就高亮哪条。F 最后回收为选择树。

**QA**：不听声音的人能答出「为什么同一台机器的价值要按三种任务分别算」；两秒定格仍可辨识。

### 方案 P2｜「开机 ≠ 网站可靠在线」(AV10→AV11→AV12) — G4 优先首测

**建议技术**：用 5–7 个节点与连接线的 HTML/SVG/Remotion 图形，不动用 AE、3D 模型或生成视频。

**画面状态**（不是已经实测的网络故障）：
- S0：`Mac mini` 节点亮，旁边“4W / 官方闲置值”，右上小标签“设备运行”；
- S1：完整访问路径 `访客 → 互联网 → 家中网络 → Mac mini → 网站` 依次建立，几个节点均正常；
- S2：只把「家庭网络」节点变灰，标注“假设断网”；Mac mini 节点仍亮，但访客到网站的连线中断；
- S3：画面同时出现“静态网站可用托管服务”替代路径，标注静态托管 ≠ 所有后台服务；
- S4：出现一句总结 **「开机时间 ≠ 网站可用时间」**。注意这并不构成具体可用率统计。

**镜头准则**：以慢速高亮/短划线/节点状态变化表达因果，禁花哨爆炸特效和虚构监控图。解说小人在 S1–S3 隐藏以让关系链占足主画面。

**G4 最低成本验证步骤（只定义，不执行）**：
1. 搭一段 **约 12–20 秒** 可静态退化的动效草稿；不以秒数强卡，只要信息层级合理；
2. 截取 S0/S2/S3 三个稳定画面进行“无声阅读”检查：有没有把 4W 当负载/把断网演成实测；
3. 用临时旁白（现有 TTS 若可用）或者文本节拍预览，不在无录音时声称时间线通过；
4. 与低成本静态替代图做 A/B；如果动画难懂，**退回静态图**而不是堆特效。
5. 对比版本、生成方法、缺口/返工次数记录在 `EXECUTION_EVIDENCE.md`。

## 5. 技术执行与资产权利规则

- G3 **没有确认用户电脑上任何具体工具可用**。可用路线优先级（候选）：1）已有静态 HTML + 浏览器截图/录屏；2）已有剪辑器 + 字幕/关键帧；3）已有 Remotion/HyperFrames；不为单一转场先学习 AE 或付费模型。
- 视觉素材不是自动获得授权：Apple 官方照片/新闻稿截图/产品 UI，Cloudflare 文档，均需在 G4 标注**用途、可引用范围、来源、获取日期、许可状态**；公共可访问不等于商业可自由复用。
- 对产品页面的研究事实可以**自绘卡片并注明来源**；更复杂的截屏、高亮原文，应优先作评论/引用必要的最小范围，并在发布前核对平台政策与具体授权情况，不宣称绝对合规。
- 对他人的 B 站视频、推文截图：本期不是必要素材，不默认抓取他人全视频或直接剪为 B-roll。
- 音频与角色循环动画是原项目资源，当前可用性/肖像和音乐版权 `UNKNOWN`，不把它们列成 G3 PASS 必需的已存在资产。
- 示例动画/图形中的路由、设备、终端均为**自绘结构示意**，有清晰标签；不能使用截图外观欺骗观众认为是真实 Apple/Cloudflare UI。
- G4 生产时，模板应保留真实 16:9 画面与字幕区的足够可读范围；必须在实际截图/视频检查文字遮挡。
- 每个资产有 `REAL_PROOF | OFFICIAL_QUOTE | INDEPENDENT_DATA | MODEL_DIAGRAM | SCENE_ONLY` 来源标签；`MODEL_DIAGRAM` 不能用于“我实测发现”的证明。
