# ① 收款方案选择：我的生意应该选择哪种收款方案？

**先作决定，再认识工具：先确定谁向顾客销售、在哪里销售、卖什么，再决定由谁收单、谁结算、钱怎样到达有权使用的账户。** 每一条收款路线都是一套“销售合同 + 顾客付款 + 资金回流 + 退款责任”的组合，不能把 Stripe、支付宝、WorldFirst、银行卡和电商平台摆在同一层比较。

一套可靠的选型只需遵循五步：**建立业务画像 → 选销售与收款模式 → 验证主体/商品/资金闭环 → 用同一批订单比较可支配到账和风险 → 确定主备及转换条件**。这五步对应本章已冻结的五个问题；后面先把一张商业收款地图建立起来，再用于两条完整案例。

## 1. 我的生意需要满足哪些收款需求？

### 1.1 把生意写成一张“交易画像”，否则任何推荐都没有对象

对于同一业务，不同顾客、商品和交易模式可能需要多条收款路径。判断的最小单位不是“整个公司”，而是**一类可重复订单**。

| 画像维度 | 必须作出的描述 | 直接决定什么 |
|---|---|---|
| **销售责任人** | 谁在订单/合同/发票/退款条款中向顾客销售：商户自己、平台还是 MoR？ | 商户身份、争议与税务责任边界、可用合同 |
| **真实经营主体** | 大陆自然人、个体工商户、大陆企业，或确有经营事实的境外实体；主体与账户名义是否匹配 | 哪些服务商能受理申请、可使用哪一类账户 |
| **商品与风险** | 实物、软件/SaaS、数字文件、课程、人工咨询；是否订阅、预售、延迟发货、限制品类 | 商品许可、收单支持、退款/预留与 MoR 适配 |
| **顾客与销售地区** | 大陆/海外、个人/B2B、核心目标国家和常用付款方式 | 支付覆盖、跨境规则、消费者支付阻力 |
| **销售渠道** | 国内平台、跨境市场平台、独立站、自己的 SaaS、B2B 发票交易 | 谁掌握结账、是否允许外部支付、平台附加费 |
| **交易结构** | 典型客单价、月订单数、订阅周期、退款率区间与采购垫款需求 | 固定费敏感性、结算周期、风险准备金压力 |
| **资金终点** | 哪一个**有权接收经营收入**的账户，何种币种、何时要用于经营 | 结算、最低提现、汇率、银行成本和到账可行性 |

例子：同是“中国大陆主体卖给美国消费者”，**29 美元的软件月订阅**可能首先比较自己收单与软件 MoR；**29 美元的实体商品**应优先比较市场平台或允许实体商品的收单渠道；**5000 美元的企业服务订单**则应考虑依据合同收取合规银行汇款。不同选择源自合同与交易，而非支付品牌偏好。

画像要输出可检验的约束句，如“大陆企业在 Shopify 自营独立站向美国个人卖 $29 实物，单次付款，每月 100 单，人民币支付供应链费用，需在两周内动用回款”，这样才知道该比较哪些方案。

### 1.2 分两类门槛：不合格的路线不进入价格排名

**不可妥协的条件（缺一项即不视为可运营）：** 经营主体与实质经营地合法且被支持；商品/销售方式不在禁止范围；目标市场有可付款方式；卖方责任与合同不矛盾；结算/提现收款人及币种合法合规；必要的退款、拒付责任和偿付路径明确。

**可优化的条件（只在合格路线中比较）：** 支付转换/成功率、单笔与总成本、提现频率与资金占用、收银台体验、客户信任、账务与维护成本、切换弹性。

标记必须严格区分 **YES（官方规则支持并且本商户资格得到确认）/ NO（规则明确排除）/ UNKNOWN（资料不够、待审核或需报价）**。官网说明支持某国家是“可申请的线索”，不能直接填 YES；也不能把“尚未申请”误写成“不支持”。

本节可以形成一张决策前置卡：**这个业务想收谁的钱；谁负责销售；哪些条件绝不能改变；资金最晚什么时候必须能用**。之后任何服务商推荐都必须对应这张卡，而不是相反。

## 2. 国内外有哪些主要收款模式与方案？

### 2.1 核心分类依据不是“国内/海外”，而是“谁承担销售、谁完成收款”

先确定**对顾客的销售安排**，再在该安排下选择**收款/结算服务**。四个最常见的商业安排如下：

| 商业安排 | 顾客买单给谁/谁对顾客负责 | 常见支付和资金路径 | 适合、代价与排除边界 |
|---|---|---|---|
| **平台交易：平台控制收银台并向卖家结算** | 通常平台控制支付；**平台是否法律意义上的卖方（MoR）必须看具体合同**，不能一概而论 | 平台结账→卖家应得结算款→平台允许的银行/收款服务 | 国内电商及 Amazon 等跨境市场平台；获客和支付规则一体化，但有佣金、账期、平台限制；不能把 WorldFirst 等结算账户当成顾客支付网关。[S11] |
| **自己作为商家直接收单** | 商品/服务由商家卖给顾客；受理银行卡/钱包的是有资质的支付服务商或收单机构 | 自有站/商户工具→支付服务商→商户余额/待结算→合格银行账户 | 需要自有品牌、客户和订阅关系时常见；可用境内商业支付产品或符合主体资格的跨境服务；商家保留较多售后/税务责任。[S01][S02][S03] |
| **MoR（名义商家）代为销售适用品类** | MoR 就其覆盖交易作为面向消费者的法律销售方；原供应商按合同取得分成/货款 | MoR 结账→按合同处理间接税/退款等→结算供应商 | 面向软件/SaaS 的跨地区消费，值得与自收单比较；并非包办供应商所有税务、知识产权、交付及本国经营义务；实体货或纯人工服务可能不适用。[S06][S07][S08] |
| **合同/发票下的 B2B 银行收款** | 企业直接依据贸易/服务合同对企业客户销售 | 客户银行汇款→商家合规银行或允许的跨境收款服务→可用经营资金 | 订单少、客单高、可先后签约付款的 B2B；汇款手续、贸易资料和收款用途需符合银行要求；不适合几十元的即时零售自动交付 |

**五类业务要放在哪一层？**

1. **国内小店/本地自营网站：** 先判“平台托管结账”还是“自己作为境内商户接支付宝/微信支付等”。支付宝官方电脑网站支付产品适配网站交易；相应产品对网站、商家主体和资质有独立要求，不意味着普通个人收钱码可替代线上经营收单。[S12][S13]
2. **跨境平台卖货：** 先遵守 Amazon 等平台规则，重点比较**平台准许的卖家资金出口**；收款服务商通常不是你可以任意替换的平台支付收银台。[S11]
3. **跨境独立站卖实物：** 商家一般自己承担销售责任，需要可受理真实大陆主体的国际收单/支付提供商；Shopify 中国版受邀商户可能另有指定结算路径。[S03][S04]
4. **自营软件或订阅：** 同一个真实销售场景才有资格并列比较“自己收单 + 自担适用税务”与“符合业务准入的 MoR”，权责不同必须计入成本。[S06][S07]
5. **外贸 B2B 大额服务/供货：** 优先看合同、发票/贸易真实性、汇款目的、银行收款与换汇成本；没有必要为了一个企业转账场景购买面向散客的实时卡收银台。

这里真正值得先作的决定：**平台内卖货就先查平台资金路线；自己的消费级网页就先查商家收单资格；软件跨境复杂时增加 MoR 备选；高金额企业交易把银行路线纳入比较。** 不是所有场景都需要 Stripe/PayPal。

### 2.2 读懂两条相互独立但必须接通的链

**合同与付款链（顾客看到的一面）：**

`顾客（所在地/币种/付款工具） → 销售合同中的卖方（你/平台/MoR） → 收银台或发票 → 可接受该支付方式的服务商/收单机构 → 成功的交易记录`

**资金及责任链（商家真正要用钱的一面）：**

`成功交易 → 结算责任方（平台/PSP/MoR） → 商户可结算余额或供应商应得款 → 允许的提现/汇款路线 → 合规受款账户 → 经营中可支配币种`

退款和拒付还有反向流：`顾客退款/发卡行争议 → 合同中的处理方 → 账户余额/后续结算款/约定补款 → 商品权益和销售责任`。本章只用于核实“这条责任与资金链是否存在”，实际售后执行留给第⑥板块。

| 容易混淆的名称 | 位于模型的哪一层 | 它**不能**自动替代什么 |
|---|---|---|
| Visa / Mastercard / 银联 | 卡品牌与卡支付网络；顾客银行卡的一种基础设施 | 不是独立站商户账户或经营结算账户 |
| 支付宝 / 微信支付 / PayPal | 可以是顾客付款方式；其中支付宝、PayPal 等还经营商家支付产品，**要以具体产品/账户为准** | 顾客有这些钱包，不代表你的商家身份已开通相应跨境产品 |
| Stripe / PayPal 商户产品 / 合规境内收单服务 | 接受和处理顾客付款的服务能力 | 并不自动替你开立任何银行收款账户、批准所有商品 |
| Shopify / Amazon / 淘宝等销售平台 | 商品与订单场景；有的平台提供统一收银台、卖家结算 | 平台的卖家应收款不等于本人银行现款，也不自动等于 MoR |
| Paddle 等软件 MoR | 对其覆盖交易承担名义销售方及相应交易义务 | 不能替代供应商的所有税务与产品责任 |
| WorldFirst / Wise / 银行账户 | 依产品可能承担合法资金接收、结算、换汇、汇款等角色 | 有境外账号 ≠ 可用境外主体注册 Stripe ≠ 能替顾客完成商户收银台支付 |

**以 Shopify 实物独立站示范两条资金链：** 若用第三方卡支付，顾客银行卡→第三方收单→第三方结算→合格提现账户；Shopify 还可能在店铺账单收第三方交易费。[S09] 若获准中国版 Shopify Payments，则顾客卡→Shopify Payments 受邀计划→**经验证的 WorldFirst 账户**，再按 WorldFirst 实际合法路径到经营账户；该计划并不是大陆商家普遍可用的独立香港 Stripe 商户。[S03][S04]

**输出：** 你应当能把每个候选写成一整条链，而不是只报服务商名。任何一段写不出提供者、责任人、币种、账户名义或规则证据，就标 UNKNOWN。

## 3. 哪些方案符合我的经营条件？

### 3.1 用“实际主体 × 交易商品 × 销售地区 × 销售角色”排除路线

官方支持地区列表、商家合同、商品政策和终点账户必须一起核对。特别注意**“有合法境外银行账户”不是“有合法境外经营主体”**；也不能借用他人身份或虚构地址改变商户所在地。

| 经营条件 | 值得核验的收款组合 | 应明确排除或保留 UNKNOWN 的部分 |
|---|---|---|
| **大陆自然人，向海外卖自己制作的数字文件** | 若具体 PayPal 中国区账户/产品接受该身份与商品，可评估自己的商家收款；若是符合要求的软件产品，可评估 Paddle MoR；数字内容平台亦可评估其卖家/提现条件 | Stripe 一般自助商户地区清单不含中国大陆；不能用一个 Wise/HK 账户“创造”香港 Stripe 资格；PayPal 账户功能、MoR 个人身份批准与提现均未因注册页面存在就确定。[S01][S02][S06] |
| **大陆个体工商户、境内自营交易** | 与真实经营主体、网站/小程序资质和业务相符的支付宝/微信支付商户产品，或平台原生收银台 | 普通私人转账码不当然具备网站经营收单与对账等能力；跨境产品不能不经审核用于纯境内交易。[S12][S13] |
| **大陆企业，跨境实物独立站** | 真正接受大陆企业、商品与海外客户的第三方支付商；若 Shopify 特定商户获邀，可比较“中国版 Shopify Payments + WorldFirst” | Paddle 以软件为目标、不适用于实物；通用 Stripe 全球商户支持清单并不因 Shopify 中国版存在而自动放开。[S03][S04][S08] |
| **大陆企业，跨境平台经营** | 平台认可的卖家收款/结算方式，例如 Amazon 全球收款或合规指定服务 | 独立站插件、Stripe 收银台不能绕开平台控制的买家结账；平台卖家账户审核仍是前置条件。[S11] |
| **实际运营的香港公司/其他境外公司** | 可按**真实主体所在地及实际运营证据**研究所在地区 Stripe、PayPal 等 | 不能直接挪用大陆个人或大陆公司资格；境外公司也仍有税务、商品、银行和结算限制。[S01][S14] |
| **大陆企业，海外 B2B 合同大额交易** | 真实贸易/服务合同对应的合规银行收汇或被许可的企业跨境资金服务 | 不能把平台卖家钱包当作通用企业电汇账户；银行所需贸易真实性、结售汇或监管要求要以具体业务及银行为准，费率 UNKNOWN |

**Stripe 与 PayPal 的实质分界：** Stripe [全球商户国家地区清单](https://stripe.com/global)包含香港，但不列大陆一般独立商户；它的“可接受全球顾客支付”指**已有符合地区资格的商户**。PayPal 中国大陆官方有商家跨境收款服务，但公开价目表明确只适用于按**《PayPal中国跨境支付服务用户协议》及《PayPal全球服务条款》**在贝宝支付开立的账户，**不适用于按另一《PayPal支付服务用户协议》开户的账户**。因此不能泛称“所有中国 PayPal 账户手续费都是 4.4%”。其他特殊卡收单产品要额外申请和审批。[S01][S02]

**Shopify 中国计划是条件例外，不是偷换经营主体：** 其官方受邀抢先体验面向开展跨境销售且拥有大陆企业主体的合格商家；需验证 WorldFirst，并且不能做对中国大陆顾客的境内销售。是否获邀、实际 Shopify 套餐及卡费，都要按该商家真实状态核验。[S03][S04]

**经营判断：** 一条方案只要实际经营主体不合格、商品被禁止或无法到达合法资金终点，就从“可选”移入“排除”；有资格申请但未通过审核的，保持“候选 UNKNOWN”，不可宣称已可运营。

### 3.2 合规收款的终点不是“支付成功”，而是“可以用于经营的钱”

检查每条候选的六个连续节点：

1. **顾客受理：** 本地区顾客实际能用某种方式付款，且该方式在商户合同中可用。
2. **对顾客的销售：** 谁在订单上是卖方？能否销售这一商品和收费模式？退款说明由谁承担？
3. **付款处理：** 是扣款成功、待结算还是预授权？这里不展开支付状态技术机制。
4. **净可结算款：** 支付/平台扣费、可能的退款与预留金之后，哪些金额成为可提余额？余额可能因审核而被限制。
5. **提现通道：** 何种受益人名称、银行地区与币种允许提现？有哪些最低额、频次、固定费与审查？
6. **银行与可用货币：** 到银行后还需何种中转、入账或换汇处理，经营账户能否实际动用？争议时钱可能如何回流？

一个“YES”的闭环必须同时回答：**钱是什么币种，分别停留在哪个账户，谁有权把它转出，何时达到提现门槛，最终收款人是谁，退单资金从哪里来**。

举例：PayPal 中国区帮助中心记载，美元电汇到大陆银行的最低提现额是 **US$150**、通常 **3–7 个工作日**，并提示银行可能要求核验、处理和退汇；价目表对应企业 PayPal 账户的该提现路线收费 **US$35/次**。这证明某项公开规则存在，**不证明任何指定个人的账户和银行卡已经审核可提款，也不保证 3–7 天一定到账**。[S02][S05]

Lemon Squeezy 官方说明可用受支持银行或**已验证的 PayPal 账户**接收卖家款项，结算有持有期和半月周期；其银行提现国家名单未列中国大陆，不能把“支持全球卖家”理解为“中国大陆银行可直接提现”。个人 PayPal 账号是否在其风险/商品审批下实际获准，应记 UNKNOWN。[S10]

**本节交付的判断结果**不是一个打勾清单，而是把候选分成：
- **已验证闭环：** 主体、产品、支付、合同、提现终点已经有足够证据；进入实际费率比较。
- **条件性闭环：** 规则上可能支持，但身份审核、店铺激活、银行/提现授权或费率尚 UNKNOWN；只能进入备选研究，不能当成上线能力。
- **不能闭环：** 出现明确 NO；直接排除，不靠改地址、借账户补救。

## 4. 如何比较不同方案的费用、效率和风险？

### 4.1 先把“净收款”和“现金到账”定义清楚，再做同条件比较

只有满足**同一经营主体、商品、客户来源、价格/币种、订单量、退款假设、最终资金用途**，才可以把不同方案做成真正的“选型比较”。不同地区的报价可以用作知识说明，但不能直接排名。

四个**不同金额层级**必须分开：

| 金额 | 算的是什么 | 常漏掉什么 |
|---|---|---|
| **顾客付款金额 G** | 顾客实际支付的含税/不含税合同总额（应统一税价口径） | 不等于商家应得销售净额 |
| **交易后余额 T** | G − 支付百分比费 − 固定费 − 适用平台交易费 | 款项可能还未结算、尚有风险预留 |
| **可申请提现余额 A** | T − 已确定的平台佣金/调整/退款/预留与其他适用扣项 | 低于最低提现额就不能直接换成银行现金 |
| **银行实际入账 B** | 符合门槛的 A − 本批提现费 − 已知中间行/入账扣费 − 按**实际汇率**计量的换汇影响 | 银行尚未到账、目的币种不明时必须记作 UNKNOWN |

做比较时，把每个费用标为 **官方已知、商户合同待查、情景假设、无法核验 UNKNOWN**。换汇是一个有实际报价和币种转换方向的步骤，不能用“手续费 0”代替汇率差；退款/拒付是另一个有发生概率、退款时手续费返还规则与资金责任的问题，不能在已成功订单里默认已经发生。

#### 一笔 $29 订单：费率示范，不是跨地区服务商排名

这些官方标准价描述的是**不同资格与法律安排**，不能凭这三行决定大陆卖家最便宜的渠道：

| 价格结构的例子 | 前提 | 单笔交易费 | 仅扣交易费的余额 |
|---|---|---:|---:|
| PayPal 中国大陆国际商业交易 | **仅**符合 [S02] 指定双协议的 CN 账户，顾客国际 USD 商业付款 | 4.40%×29 + $0.30 = $1.576（例示按美分计 $1.58） | **约 $27.42** |
| Stripe 香港商户 USD 卡交易 | 真正具备 HK 商户资格，卡属于国际卡；无币种兑换 | 3.4%×29 + $0.30 + 0.5%×29 = $1.431（例示 $1.43） | **约 $27.57** |
| Paddle 软件 MoR 标准价 | 受 Paddle 接受的软件商品，由 MoR 销售 | 5%×29 + $0.50 = $1.95 | **$27.05** |

HK Stripe 另可有换汇与争议费用；上述数字均未包括任何平台费、提现费、银行费、消费者税、商品履约/客服成本或退款。[S02][S14][S07]

#### 相同大陆经营主体、同一批订单：PayPal 美元提现如何改变答案

现在锁定**一个有资格使用 [S02] 协议、且获准该提现路径的大陆商户**；每笔均为海外顾客支付 $29、成功无退款、USD 余额；为便于银行比较，按“每单扣款后余额约 $27.42”进行批次模拟。PayPal 官方提示大陆银行美元电汇**最少 $150**，本假设中企业账户按**每批 $35**扣提现费。[S02][S05]

| 一批成功订单数 | 顾客合计支付 | 支付费后可提现前余额* | 达到 $150 门槛？ | 只扣一次 $35 电汇费后的预计银行入账前金额* | 每单摊到的提现费 |
|---:|---:|---:|---|---:|---:|
| 1 | $29 | $27.42 | **否** | **当批无法按该路径提现** | 不适用 |
| 5 | $145 | $137.10 | **否** | **当批无法按该路径提现** | 不适用 |
| 6 | $174 | $164.52 | **是** | **$129.52** | **$5.83** |
| 10 | $290 | $274.20 | **是** | **$239.20** | **$3.50** |
| 100 | $2,900 | $2,742.00 | **是** | **$2,707.00** | **$0.35** |

\* 为便于阅读，此演算假设逐单费用先四舍五入到美分且本批无额外冻结、退款或差错；**不代表 PayPal 实际逐笔舍入算法、可提现审核状态或银行到账保证**。收到美元电汇的银行费、中转行费、结售汇汇率及其合规可用性 **UNKNOWN**。因此这里的 $129.52 等只是“扣已知两层费用后的预计到账前金额”，**不是已证实的银行实收、更不是人民币净利润**。

**由表直接得到选择条件：** 如果一个独立创作者每个月只有 1–5 单，又需要本月用现金采购/投广告，那么上述美元电汇路线**不能满足本月提现目标**；优先核验其他有资格、低门槛且可以形成合法到账闭环的方案，或接受多月攒单。若每月 100 单且允许一次批量提现，$35 固定费对每单影响较小，可继续评估该路径。不能因为单笔收款成功就说“可立即提现”。

#### 严格同条件选型：大陆商户同一 $29 商品的两种合规收银台

这里**固定：同一个大陆业务主体、同一海外顾客市场、同样 $29 商品、同样 USD 结算、同一个允许的大陆提现路线**。假设该商户通过 PayPal 对应产品审核，可以使用 (A) 标准国际商业收款与 (B) 经额外申请/批准的**PayPal 在线卡付款服务高级版**；B 的公开国际卡费率是 **4.10% + $0.30**，不是默认对所有商户开放的功能。[S02]

| 比较维度 | A：合格账户的 PayPal 国际商业收款 | B：获批的在线卡付款高级版 |
|---|---|---|
| 主体与价格 | 同一个真实大陆商户、同样 $29 | 完全相同 |
| 付款覆盖 | 适用于其获准的 PayPal 商业交易能力 | 须进一步获得在线卡付款批准；覆盖银行卡客群 |
| 交易费（示范） | $29×4.40% + $0.30 ≈ $1.58 | $29×4.10% + $0.30 ≈ $1.49 |
| 单笔费差 | 基线 | B 少约 **$0.09/单**（未含可选服务/风险附加价） |
| 提现与资金终点 | 若采用相同被认可的美元电汇路径，仍需满足门槛、$35 每批 | 同样；不能因为 B 交易费低就省略提现成本 |
| 决定主用的条件 | PayPal 顾客覆盖对销售更重要或 B 未获批 | B **确实获批**且更多目标顾客要直接使用银行卡，附加服务费等核实后有优势 |

**这才是同主体、同商品比较：** 并不以 HK Stripe 价格攻击大陆 PayPal；也不把两个不同付款方式的销售成功率假设为相同。若 B 未获批，则不列为“可选方案”。两种付款能力可能是互补而非互斥：当目标顾客群不同，正确结论可能是同时保留，而不是只以九美分差距替换。

另一个**同条件独立站比较**：同一家受邀大陆企业在同一个 Shopify 商店售卖同款实物，可比路径 A “已批准第三方收单 + Shopify 可能适用的第三方交易费 + 对应提现路径”与路径 B “**实际获邀且验证成功**的中国版 Shopify Payments + WorldFirst + 后续合规结算路径”。在同一张 $29 订单中：

- A 的净资金基数 = $29 − 第三方支付费 − Shopify 第三方交易费 − 适用货币费与该路线摊销提现费；
- B 的净资金基数 = $29 − 中国版 Shopify Payments **该计划实际卡费** − WorldFirst 后续实际收费/汇兑 − 该路线摊销提现费。

官方规定 Shopify 第三方交易费可能**另加在**第三方支付费之上；使用 Shopify Payments 作为唯一提供商时相应第三方交易费不收，但两条实际卡费、商户差异化费率、币种和 WorldFirst 结算报价尚须核验，**本例不给出虚构单笔净额**。[S03][S04][S09] 如该 Shopify 套餐实际第三方费率为 (t)，这层成本在单笔 $29 商品上是 **$29×t**；例如 (t)=2% 仅作为数学敏感性示例，就是 **$0.58/单**，**并非断言该大陆店铺当前实际被收 2%**。取得双方账户实价后再填入两式，辅以退款/通过率和到账期限确定胜出者。

#### 相同经营者的软件业务：为何 MoR 价格不能只与 PSP 抽成相比

假设同一大陆经营者向同一海外客群销售 $29/月的软件，并**分别获得**自己收单与 Paddle 的准入。PayPal 交易费的估算为每单约 $1.58；Paddle MoR 标准交易价 $1.95/单，差约 $0.37。若 10 单，Paddle 交易后应得基数约 $270.50，但其官方说明按月结算、可设置的最低门槛为 $100，部分国家/方式存在 $15 SWIFT 费用，银行及汇兑还需另算。[S07][S15] PayPal 同样 10 单走本例美元电汇，已知费后约 $239.20、仍有银行等 UNKNOWN。

**不能由 270.50＞239.20 就断言 MoR 赚更多：** Paddle 卖方身份、消费者税处理范围、收据/订阅运营、争议职责和资金路径与商户自行销售不同；两条路线的商品定价是否含税也要统一。应分别核验“相同含税顾客最终支付价下，MoR 应结算给供应商的最终对账单”与“商户自行销售后承担的适用税务/支付/争议成本”，然后比较可支配现金与实际工作量。如果个人卖的只是模板/课程而非 Paddle 支持的软件，**MoR 路线先被商品门槛淘汰**。[S06][S08]

### 4.2 交易费接近时，比较“能赚到”而不只是“扣得少”

真实比较按四种失败成本展开：

- **付款覆盖/成交损失：** 美国客户能否用习惯的银行卡、PayPal 或钱包，是否必须跳转？只有同一客群的**真实支付尝试和有效订单**才可比较转化率，不可把全球支持“195+ 国”视作该店铺成功率。
- **现金时间成本：** 采购型实物经营比软件更怕资金被预留、结算慢或达不到提现门槛；记录“交易日—可提现日—预计银行可用日”的区间，而不是一项“到账快”标签。
- **预期争议/退款占用：** 比较渠道规则、可能不返还的初始支付费、争议费和举证负担，未有商户数据时将发生率标 UNKNOWN，不用拍脑袋给风险费率。[S02]
- **中断与迁移成本：** 一个支付商停止服务能否改用另一独立受理方？同一账户换银行不算完整备用；MoR 迁移订阅付款凭据、平台换销售渠道，都可能不是即时切换。

可用一个**不伪装成运营实测的灵敏度检验**：在 $29 客单价、100 次同质量有意付款尝试下，若渠道 A 的实际成功成交比 B 多 3 笔，那么 **3×$29 = $87** 的额外成交额上限可能超过 A 每单高出的微小处理费；但它不是额外利润，必须再扣履约、税务和争议成本。没有成功率数据时只给“待观察”结论，不虚构转化率。这样才知道何时成本不应排在支付可用性前面。

**本节的输出应是一张同条件“净现金比较单”**：一批典型订单的顾客总付款、逐笔交易费、平台佣金/额外费、最低提现门槛、每次提现费、提现日期、银行与汇兑 UNKNOWN、争议/退款假设，以及营销获客方式是否改变。缺项越多，结论越应收敛为“优先核实 XX 两项”，不能把 UNKNOWN 当零。

## 5. 如何确定最适合自己的收款方案？

### 5.1 四轮决定主方案和真正的备用方案

**第 1 轮，锁定合同与渠道：** 你在市场平台内成交、自己网站成交，还是与企业签约收款？先选“平台、自己商户、软件 MoR、B2B 汇款”模式。若商业模式转换会改变获客与责任，不把两种路径的费率简单排名。

**第 2 轮，硬门槛淘汰：** 用第 3 节把真实主体、商品/地区、支付受理、销售职责、银行资金终点、退款责任逐项填 YES/NO/UNKNOWN。NO 淘汰，UNKNOWN 仅作**条件候选**。

**第 3 轮，同条件比“已能使用的现金”：** 用第 4 节的整批订单口径比较费率、附加平台费、提现批次和现金需要；将不能核实的银行费/汇兑/退款率保留 UNKNOWN，并用一项真实业务优先级打破微小费差平局。

**第 4 轮，选择两条相互独立的风险路径：** 主方案应是资格与现金闭环已可验证、符合当前订单模式的最简路径。备用方案必须能独立接受核心顾客付款、按自身合法主体结算与处理退款；仅换一张收款卡、同一 PayPal 账户换 HK 银行，或在同一个平台内开新店，都不等于支付收单层真正备援。

下列不是“万能推荐”，而是严格沿同一个模型推演的**可核验决策演练**。

#### 演练 A：大陆自然人向海外卖数字产品，单价 $29

**业务事实：** 无已证明的境外公司；在自己的网页面向美国个人销售 $29 的原创可下载设计模板，单次付款；先每月 5 单，后可能 100 单；经营资金希望汇入本人依法可收经营款项的账户。实际经营性质及收款主体合规资格仍需确认。

**模式顺序：** 顾客在自有站下单→可能由本人作为商户直接收款，或改为某个允许该产品的数字商品销售平台→再检查其结算安排；**不能预设软件 MoR 必然接受设计模板**。

| 候选与判定 | 准入/责任 | 资金闭环 | 决策 |
|---|---|---|---|
| 自己开户使用“香港 Stripe” | 大陆个人没有相应真实香港商户主体；HK 银行账号不改变资格 | 无合法已证实的商户开户前提 | **NO，排除** |
| Paddle 软件 MoR | 本例是设计模板，不是典型的软件/SaaS；官方主要针对软件，不是全部数字品 | 即使销售品类变为软件，也须验证卖家审批及收款账户 | **本例不作为主选；若以后改为软件产品才重新核验** |
| 按适用中国区协议经营的 PayPal 商户收款 | 须证明自然人/实际业务能使用所需的商户产品、商品符合规则，按真实身份审核 | 若账户允许美元电汇至同名合规大陆银行，存在 $150 门槛与 $35/次；本人的实际资格 UNKNOWN | **条件主选 P1：先核实个人商户能力和提款合法性** |
| 可销售原创模板的**数字商品平台** | 需核验该平台对数字模板、个人卖家身份、消费者交易与退款责任的具体合同 | 检查是否能真实提现到本人认可账户、最低额与平台佣金；本轮没有核验某个具体平台全链 | **备用方向 P2：找到具备已证实卖家资质和提现的具体平台才成立** |

**月 5 单的明确选择：** PayPal 本例最多只有约 $137.10 交易费后余额，**不达美元电汇 $150 门槛**。若必须本月获得经营现金，**不要选该电汇路径作本月唯一主线**；先核验有可用资金终点的数字商品平台或合法其他提现产品。若没有任何路径可验证，就明确判为 **“暂不能证明形成合法现金闭环，不应宣称准备好上线”**。这比错误推荐更有操作价值。

**月 100 单的条件变化：** 若商户资格、银行受款和提现审核已确认，每月合并一次提现，在不计银行额外收费/汇兑时，29×100 的交易费后约 $2,742，扣一次 $35 后约 $2,707。这时固定电汇费仅摊 $0.35/单，原本低频不适用的方案**可能成为合理主选**。若消费者主要愿用银行卡而非 PayPal，则同一主体优先核验 PayPal 在线卡付款资格及别的真实合格收单方案，而不是只追费差。

**最小剩余核验（顺序不可颠倒）：** ①本人的实际经营主体是否可合法销售及使用哪一协议/商户服务；②该服务是否允许原创模板和美国顾客付款；③账户的个人名义银行/跨境汇款受款条件、限额与费用；④若本月只有 5 单，备用平台是否提供更低门槛、合法到款路径。前两项不过关，费用计算无需继续。**当前状态：条件主选，非已获批或已支付验证。**

#### 演练 B：大陆公司向海外卖实物，$29/单，月 100 单

**业务事实：** 大陆注册公司拥有真实生产/供货与外贸资料，主要销售给美国个人，需垫付采购/物流，希望 14 天左右能动用资金。比较的两个**不同销售渠道**先分开建模：若在 Amazon 平台销售，按市场平台规则结算；若拥有 Shopify 品牌独立站，自己是卖方并需负责顾客结账及商品售后。**渠道改变同时改变获客、佣金和运营成本，不能把 Amazon 平台收入与 Shopify 交易费表直接相减。**

**路线 1：Amazon 等跨境市场平台为主营时。** 主选是**平台统一收银台 + 平台准许的中国银行/合规跨境收款服务**，因为买家付款并非自建收银台决定。Amazon 官方有“全球收款”帮助大陆卖家以人民币收到符合条件的跨境款项的产品。可比较的是该平台下实际被允许的两个资金出口，按**同一批平台净结算款**核算换汇、入账、提现时间；不能据此断言具体卖家账户已经获批或一定满足两周现金需求。[S11] 若平台结算周期不满足备货资金需求，需要调整营运资金，而不是换个 Stripe 插件解决。

**路线 2：Shopify 品牌独立站为主营时。** 商品是实体货，排除 Paddle 软件 MoR；大陆公司一般 Stripe 自助商户支持也不能直接按香港资格申请。现在剩两条真正可比的资金链：

| 同一大陆公司、同一 Shopify 订单 | 第三方被批准收单路径 A | 中国版 Shopify Payments 路径 B |
|---|---|---|
| **开通条件** | 必须有支持大陆公司、实物、美国买家及该店铺的**具体第三方提供商**；通过实际商户审核 | 必须**获得受邀资格**、符合跨境销售条件，完成 WorldFirst 验证 |
| **顾客结账** | 支付服务商允许的卡/钱包，实际支持由合同决定 | 官方说明 Visa/Mastercard、若符合条件的加速钱包；不支持对大陆消费者的境内销售 |
| **费用结构** | 该提供商处理费 + Shopify 可能收的第三方交易费 + 资金汇兑/转出费 | Shopify Payments 该店铺/套餐的实际交易费 + WorldFirst/银行后续费用与汇兑；不能把香港 Stripe 公价代入 |
| **资金终点** | 经该提供商认可并核实的企业提现/结算账户 | **指定经验证的 WorldFirst 账户**→允许的企业用途账户 |
| **到账和业务风险** | 第三方账户审核与预留、Shopify 额外费、平台依赖 | 受邀资格、WorldFirst 结算规则、付款方法与退款责任 |
| **可作主线的时点** | 收款产品及完整资金闭环都通过审核，能满足备货现金要求 | 真实收到邀请并验证成功、实价和资金周期符合业务要求后 |

**条件化结论（明确二选一）：** 若**未受邀**，B＝NO，**优先把 A 作为拟主线**，但在实际第三方提供商未确定且没有合法提现路径前，A 仍是 UNKNOWN、不能声称已经能上线。若**已经受邀且 WorldFirst 验证成功**，先用第 4 节表式计算 A/B **同一批 100 单** 的处理费、Shopify 附加费、汇兑和可用日，**在两周可用资金约束都满足的前提下**选净可支配款更高且支付覆盖不差的一条。若 A 是目前已运行路线，则 B 先作条件备用，不为未知的费率优势停掉有效收款。若其中一条资金周转超过业务容忍范围，无论手续费低多少都不当主线。

**真正的备用方向：** 在 Shopify 内另找**经过同一大陆主体/商品/提现审查的独立支付服务商**，而非把 WorldFirst 与 Stripe 当作同层替代；若长期兼营 Amazon，那是**业务渠道分散**，不是 Shopify 收银台即时备援。

**最小剩余核验：** ①当前店铺是否确实收到 Shopify 中国版邀请；②第三方具体商户主体和商品准入及真实报价；③ Shopify 套餐的第三方附加费与两种退款条款；④两条资金链的入账账户、汇兑报价、账期和是否适合 14 天备货。**未经实际运营数据，不能宣布哪个处理成功率更高。**

#### 其余三类常见生意的直接决策结果

| 业务 | 先选哪一类模式 | 何时换路线 |
|---|---|---|
| **大陆国内到店/网站卖货** | 在平台成交→平台原生收款；自营网站→真实境内主体符合资质的国内收单产品（支付宝/微信支付等），按线上与线下产品区分 | 当开始跨境经营，重新审核跨境产品，不套用本地收钱码资格 |
| **全球 SaaS $29/月** | 先比“符合主体资格的自收单”与“经审核的软件 MoR”：前者保留对消费者销售与税务责任，后者把覆盖交易中的部分销售/间接税运营交由 MoR | 如果无资格申请直接国际卡收单、各地间接税义务负担大且 MoR 已批准，优先 MoR；如果已经有合规收单能力、相应税务运营能力且综合费用明显低，则自收单可优先；资金结算仍需核验 |
| **企业对企业 $5,000 真实服务订单** | 以真实合同/发票为基础，与企业银行和合规跨境收款提供商确认可接受的对公收汇；比较中转行费、汇率与结算资料 | 若订单变成高频散客即时购买，才比较卡收单与在线收银台；银行实际入账费及外汇处理逐笔向银行确认，不可照搬消费级卡费 |

**最终写出而不是收藏工具名单：** “当前经营主体【X】、商品【Y】、主要顾客【Z】；选择【自己商户/平台/MoR/B2B】模式；拟主线为【具体责任方和资金终点】；明确排除【不合格路线】；尚需核验【最少必要事项】；当【订单量、销售渠道、现金时限、主体/商品或服务商政策】变化时重新评估。”如一切闭环仍 UNKNOWN，应输出**“当前没有已经证实的可运行方案”**，不是用不真实的境外身份填空。
