## 二、必须返修的事实/业务阻断（P0）

1. **P0-01，商家资质与支付工具的“实际上线”说得过早（新稿147–197、209–220行；执行记录第2、7节）**：两种情境均为大陆企业，但没有确定实际服务商的注册地支持、独立支付方式权限、币种、订阅或BNPL条件，就分别宣称“最终上线组合”。建议把最终组合改为“待验证上线候选”，对每项列 `YES（已核实）/NO/UNKNOWN` + 可核查官方商户资格与收单协议；未经实际测试不得把大陆主体直接接入 Apple Pay/PayPal/Klarna 等写成已生效。英国/德国支付习惯、PayPal“不可替代”等概括要收敛。**新稿有结构上的完整筛选，但事实证据未跟上。**
2. **P0-02，PCI SAQ资格与卡号处理边界错误（449、506–514、759行；执行记录F07）**：原文把 iframe/Elements 自动等同“只需SAQ A”，把PAN、到期日与CVV的读取、传输、存储不加区分视为全球绝对禁止。PCI SSC FAQ1588明确：SAQ A仍有商户页面脚本安全等完整资格要求，最终SAQ适用及提交由收单机构/接受合规证明者确定。应先推荐托管组件降低风险，再明确**不是自动合规或零责任**；不要以SAQ A-EP/D的范围作为“只要服务器接卡号”唯一确定推断。官方：https://www.pcisecuritystandards.org/faqs/1588/。
3. **P0-03，Apple Pay验证操作步骤写成所有场景的强制操作（102–104、159、698、744行；执行记录F01）**：作者要求所有商户必须手工在网站根目录上传固定 `.well-known` 文件，否则“绝对无法渲染”；实务取决于采用的收单平台托管/嵌入方式、域名注册及平台自动管理机制，不能用原生Apple Pay开发步骤概括Stripe Checkout/Elements、Shopify和第三方插件。应区分“原生直连/平台托管/嵌入式收单”，只要求验证**实际商户域名已注册/已激活**且满足所选集成的文档。官方：https://docs.stripe.com/payments/payment-methods/pmd-registration 和 https://docs.stripe.com/api/payment_method_domains。
4. **P0-04，iDEAL当前产品与订阅限制误导（61、114、162–163、726–759行）**：Stripe 2026的官方名称为 **iDEAL | Wero**，并提示2026–2027迁移，支持EUR的呈现币种；Stripe同时列出**通过SEPA Direct Debit支持订阅**。因此“iDEAL仅支持以EUR计费与结算”“无法原生支持月度循环订阅”要明确具体产品/方式与后续转换路径，不能一概排除。官方：https://docs.stripe.com/payments/ideal。
5. **P0-05，德美税费实例数学正确但经营事实未证实（266–318行，执行记录第6节）**：€27/1.19得到净价€22.69、VAT€4.31计算正确；$110×8.625%=$9.49、订单$134.49计算也正确。但例子未先证明“谁在德国缴VAT、是否MoR/已产生税务义务”，“东莞公司对美国邮编94103销售是否具有征收加州Sales Tax义务、实际适用税率/商品税基、是否DDP包括进口税”等条件；不能把模拟表称为“合规规范账单/真实税务事实”。应先写清假设（法律卖方、注册/税务阈值、税率是假设、进口关税承担），示例仅做价格透明展示；不符合条件时不得擅自征税。加州跨州销售税务入门：https://cdtfa.ca.gov/industry/out-of-state-retailers/。欧盟：https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:02011L0083。
6. **P0-06，未知付款结果下仍对顾客作无条件保证（520、605–612行）**：前端提示“数分钟内会自动确认订单、绝不会重复扣费、7×24小时客服”不是网站可无条件履行的事实。尤其含异步本地支付与人工排查，前端不应替服务端宣称确定性成功。改成“请勿再次提交；系统将核对结果，若有授权/扣款疑问通过订单号联系支持，并在明确服务承诺范围内通知”即可，具体订单状态由第四章后端核验保证。超时要用相同订单查单/安全恢复，不能把所有后台超时叫“静默重试”而忽略幂等/处理中的支付。
7. **P0-07，出处体系不闭环（正文102/257/512等行，附录726–759行）**：正文用 `[S01] [S02] [S03] [S05]` 等编号，附录却使用未编号的“1.、2.、3...”且排序不匹配。如[S01]在正文表示Apple Pay，而附录1为Stripe Checkout；[S02]正文托管字段，而附录2是Payment Element；[S05]正文参考PayPal提款费用但附录5是Apple Pay。必须**先统一引用编号、链接、适用事实**，再让执行记录逐条对照；不能仅堆十条网站泛链接后声称全文所有事实已核验。

## 三、重要定向修订（P1）

- **P1-01，真实依据与案例量纲（64、78、109、114、197、237、253–254行）**：“动态一定展示2–4种”“钱包必然倍增转化”“PayPal不可替代”“德国买家默认网银”“季度500台/35%即开启Klarna”“超过三分之一直接流失”“FTF普遍1–3%/DCC统一3–5%”均需要与真实来源/业务样本绑定；没有则改成变量或示意，强调应先从后台数据和商户资格求证。
- **P1-02，德国/美国消费价格逻辑（247–269行）**：三重币种模型可以保留，但展示价格和真实计费币种不一定相同；不能把“美元当地价”自动等同资金最终结算币种，也不能断言美国所有零售标价必然价外税、欧洲含税规则无需产品/地区条件即可直接套用。
- **P1-03，欧盟撤回权与美国自动续费（324–338行）**：FTC修订规则被撤销的事实方向正确；欧盟第16(m)条的事先同意、知悉与耐用介质确认也很有价值，但不得直接说“银行/监管必然认定”而混淆消费者撤回权、卡组织退款争议和正式裁决；美州自动续费规则需要具体州/版本/试用期条件。文中“必须在线一键取消/全部试用前提醒”应核实来源后条件化。
- **P1-04，3DS与风控（444–503行）**：SCA并非“所有线上扣款都必须三选二”且有范围及豁免；成功3DS不等于每次都发生责任转移，卡组织返回码和争议类型、适用例外等需收敛。不要用“商业履约争议责任完全由商户承担”替代商户举证争议结果。
- **P1-05，结账优化与未授权品牌标识（374–402、428–430行）**：数字商品必填“邮箱+付款方式+国家邮编”也不是所有市场固定三项；Apple Pay/Google Pay/PayPal钱包地址回填因买家授权而异；SSL和卡组织徽章只有具备真实合规资格才展示，不鼓励虚假贴标或依赖已失效“安全徽章”。A/B最小样本由统计功效而非固定两周决定。
- **P1-06，弃单触达与合规（615–622行）**：将软件2–4小时、硬件6–12小时/次日优惠券视为未经验证的实验起点，不说“通常效果更好”；GDPR与CAN-SPAM不同，营销邮件是否需要同意、何时可以联系、退订要求按辖区/合法依据/现行规定独立判断。
- **P1-07，篇幅和术语（整章）**：新稿文字从约2.35万扩到约4.10万字符，重复前两章支付产品接入、美国自动续费及第④幕后支付状态解释的比例增大。保留“两个案例+筛选表+真实订单拆分+失败分流”，删掉长段恐吓词、重复术语字典、没支持的零容忍/绝对/唯一；零基础卖家要先读到“怎么做”，工程细节链接附录即可。
- **P1-08，执行记录自评（第2、4、6、7节）**：原执行记录把“数据和法规100%严格确立”“旧稿只有单一场景/本稿完全无断言”评价过于满。实际不少场景主体是假设、税务资质未证明，且正文出现“绝对”承诺。记录应如实区分 `VERIFIED / EXAMPLE / UNKNOWN`，删除“100%无误/完美闭环”类自证。
