# ① 收款方案选择：我的生意应该选择哪种收款方案？

假设你做了一份原创设计模板，向美国顾客卖 **29 美元**。顾客点了付款，页面显示成功，你是不是已经有29美元可以拿去进货？不一定。支付成功只是顾客付出钱；服务商可能还要扣费、核对交易并把应得款划入待领取余额。**结算**是计算并安排商家应得款，**提现**是按允许的路线把这笔钱转到合格账户；直到银行真正入账并能用于经营，才算解决了“钱到手”的问题。

选方案可以先只做四步：**①说清订单**（卖什么、卖给谁、由谁卖）；**②查能不能用**（身份与商品能否被接受、客户能否付、钱能否合法到银行）；**③算真正到手的钱和日期**；**④准备能独立收款的备用路线**。不懂品牌也能先做这四步。比如29美元模板：若商家无法证明自己的账户有权收这类款，费率再低也不能进入第三步；若一批订单的余额达不到提现门槛，“已卖出”也不等于“本月有现金”。

下文把这些问题逐一拆开。Visa、PayPal、Stripe、银行、市场平台与第三方销售方各管不同环节；先看一张订单怎样成交，再认识它们，不用把所有名称背下来。完整合同条件、收费演算和两位假设经营者的主备选择仍会保留，方便有经验的卖家逐条核实。

## 1. 我的生意收钱时，首先要考虑什么？

### 1.1 卖什么、卖给谁、在哪里卖，会影响怎么收钱吗？

**会。** 先沿用开头的29美元模板：假设经营者在自己的网页销售，顾客住在美国，用当地常见的付款方式；卖家真正想要的是把销售收入合法转到自己能用于经营的账户。此时不能先问“Stripe与PayPal谁便宜”，而应先问：这份模板能否由该经营者合法销售？他是否有资格开通服务商的商家收款产品？顾客付完钱，哪个账户最终有资格接收经营收入？

把订单中的角色再分清一点：**销售责任人**是合同、收据及退款条款中实际向顾客销售的一方，不是网页上随意填写的名字。**收单**指有资质的机构或服务商帮助商家受理顾客银行卡等付款。若交易由另外一家服务商以自己的名义向顾客出售某种软件，它可能担当 **MoR（Merchant of Record，名义商家）**，即该交易中法律意义上的卖方；这不等于普通代收，也不意味着它包办供应商全部税务。**SaaS** 是通过网络持续提供的软件服务，常按月订阅；**B2B** 是企业对企业的订单，常通过合同和发票收汇。它们与一次性模板下载不是同一种交易安排。

现在才用下面七项清单给**同一笔订单**建档。初次填写时，可先填“商品与风险、顾客与地区、资金终点”，再补销售方、主体、渠道与交易数量。原表中的每一项都不可省，只是没必要在看懂示例以前记住所有术语。

| 画像维度 | 必须作出的描述 | 直接决定什么 |
|---|---|---|
| **销售责任人** | 谁在订单/合同/发票/退款条款中向顾客销售：商户自己、平台还是 MoR？ | 商户身份、争议与税务责任边界、可用合同 |
| **真实经营主体** | 大陆自然人、个体工商户、大陆企业，或确有经营事实的境外实体；主体与账户名义是否匹配 | 哪些服务商能受理申请、可使用哪一类账户 |
| **商品与风险** | 实物、软件/SaaS、数字文件、课程、人工咨询；是否订阅、预售、延迟发货、限制品类 | 商品许可、收单支持、退款/预留与 MoR 适配 |
| **顾客与销售地区** | 大陆/海外、个人/B2B、核心目标国家和常用付款方式 | 支付覆盖、跨境规则、消费者支付阻力 |
| **销售渠道** | 国内平台、跨境市场平台、独立站、自己的 SaaS、B2B 发票交易 | 谁掌握结账、是否允许外部支付、平台附加费 |
| **交易结构** | 典型客单价、月订单数、订阅周期、退款率区间与采购垫款需求 | 固定费敏感性、结算周期、风险准备金压力 |
| **资金终点** | 哪一个**有权接收经营收入**的账户，何种币种、何时要用于经营 | 结算、最低提现、汇率、银行成本和到账可行性 |

七项信息会影响两件事：顾客究竟向谁购买，钱最后怎样进入有权接收经营收入的账户。同样面向美国顾客，卖**29美元的软件月订阅**，可以研究自己收单和软件 MoR；换成**29美元实物**，就要看市场平台或允许实物销售的收单服务；一笔**5000美元的企业服务订单**，通常应先查合同下的合规银行收汇。单看支付费率，这些差别都看不出来。

画像可以写成一句能够用于比较的话：“大陆企业在 Shopify 自营独立站向美国个人卖29美元实物，单次付款，每月100单，采购和物流费用要用人民币支付，14天内需要动用回款。”其中月订单数决定固定提现费摊到每单有多重；14天的用钱期限，则决定某些看似便宜的结算方式是否来得及。

### 1.2 哪些条件必须满足，哪些可以按费用和方便程度来选择？

先看一个常见误会：大陆经营者有一个香港银行账号，是否就能以香港商家身份开通 Stripe？**不能据此判断能开通。** 银行账号解决的是特定条件下“钱往哪里去”，商户资格解决的是“谁有权使用这个收款产品”，二者必须分别审核；真实经营地区和身份不能靠填写另一地区地址改变。

因此把条件分两层。第一层是**不满足就无法营业**的门槛：服务商接受真实经营主体与商品，目标顾客有能用的付款方式，销售及退款责任能说明白，最后能按合同合法进入有权收营业款的账户。第二层才是**在可用路线之间取舍**的体验与成本：手续费、顾客结账是否顺手、等多久能动用资金、出问题时维护负担多大。对于29美元模板，假如自然人商品或提款资格还没核实，这条路线尚不能说“可用”，更谈不上把它选为主用。

通过这些门槛的方案，才值得比较哪一种更顺手、更省钱。买家的付款习惯、结账成功率、提现周期、实际总费用，以及日后维护或换渠道的麻烦程度，都会影响长期经营，且各商家看重的程度不同。

对照资格时，可在旁边写 **YES、NO 或 UNKNOWN**。YES意味着官方规则支持，而且这个商户的相应资格已经得到确认；NO意味着规则明确不接受；UNKNOWN则可能是尚未申请、审核中，或费用要等报价。官网写着支持某个国家，只能让人继续调查，不能据此认定自己的账户已开通。同样，没申请过也不能直接判成NO。

这样整理出来的需求卡不必复杂：顾客来自哪里，谁承担销售责任，必须满足哪些资格，资金最迟什么时候能用。带着这些条件认识收款模式，比看完服务商名单再回头猜用途要有效。

## 2. 商家常见的收款模式有哪些？

### 2.1 自己收款、在平台卖货、让第三方作为卖方，收钱有什么不同？

先比较两张顾客能理解的订单。**第一张**：你在自己的网页卖29美元模板；顾客购买的是你提供的商品，你要找到有资格替你处理付款的机构，也通常由你按销售合同负责售后。**第二张**：你在 Amazon 等市场平台卖货；顾客走平台指定的结账流程，平台再按合同把卖家应得的款项结算出来。这里你不能想换谁刷卡就换谁，平台是否真正作为法律卖方，还必须看具体合同。

再加入两种更专业的安排。**软件 MoR** 是由名义商家就其覆盖的软件交易直接成为面对顾客的卖方，再依约给原软件提供者结算；它不是所有数字文件通用的“收钱外包”。**企业对企业的合同收款**则不同：一家公司签合同向另一家公司提供大额服务，买方可能直接从银行汇款，不一定需要面对散客的即时收银台。四种模式先决定“谁卖、谁结账、谁退款”，之后才有意义比较各自的收费。下面保留完整责任与资金路径表供核验。

| 商业安排 | 顾客买单给谁/谁对顾客负责 | 常见支付和资金路径 | 适合、代价与排除边界 |
|---|---|---|---|
| **平台交易：平台控制收银台并向卖家结算** | 通常平台控制支付；**平台是否法律意义上的卖方（MoR）必须看具体合同**，不能一概而论 | 平台结账→卖家应得结算款→平台允许的银行/收款服务 | 国内电商及 Amazon 等跨境市场平台；获客和支付规则一体化，但有佣金、账期、平台限制；不能把 WorldFirst 等结算账户当成顾客支付网关。[S11] |
| **自己作为商家直接收单** | 商品/服务由商家卖给顾客；受理银行卡/钱包的是有资质的支付服务商或收单机构 | 自有站/商户工具→支付服务商→商户余额/待结算→合格银行账户 | 需要自有品牌、客户和订阅关系时常见；可用境内商业支付产品或符合主体资格的跨境服务；商家保留较多售后/税务责任。[S01][S02][S03] |
| **MoR（名义商家）代为销售适用品类** | MoR 就其覆盖交易作为面向消费者的法律销售方；原供应商按合同取得分成/货款 | MoR 结账→按合同处理间接税/退款等→结算供应商 | 面向软件/SaaS 的跨地区消费，值得与自收单比较；并非包办供应商所有税务、知识产权、交付及本国经营义务；实体货或纯人工服务可能不适用。[S06][S07][S08] |
| **合同/发票下的 B2B 银行收款** | 企业直接依据贸易/服务合同对企业客户销售 | 客户银行汇款→商家合规银行或允许的跨境收款服务→可用经营资金 | 订单少、客单高、可先后签约付款的 B2B；汇款手续、贸易资料和收款用途需符合银行要求；不适合几十元的即时零售自动交付 |

经营模式确定之后，常见的五类生意可以这样对照：

1. **国内小店/本地自营网站：** 先判“平台托管结账”还是“自己作为境内商户接支付宝/微信支付等”。支付宝官方电脑网站支付产品适配网站交易；相应产品对网站、商家主体和资质有独立要求，不意味着普通个人收钱码可替代线上经营收单。[S12][S13]
2. **跨境平台卖货：** 先遵守 Amazon 等平台规则，重点比较**平台准许的卖家资金出口**。收款服务商通常只能在平台允许的资金结算环节提供选择，不能自行替换买家结账系统。[S11]
3. **跨境独立站卖实物：** 商家一般自己承担销售责任，需要可受理真实大陆主体的国际收单/支付提供商；Shopify 中国版受邀商户可能另有指定结算路径。[S03][S04]
4. **自营软件或订阅：** 同一个真实销售场景才有资格并列比较“自己收单 + 自担适用税务”与“符合业务准入的 MoR”，权责不同必须计入成本。[S06][S07]
5. **外贸 B2B 大额服务/供货：** 优先看合同、发票/贸易真实性、汇款目的、银行收款与换汇成本；没有必要为了一个企业转账场景购买面向散客的实时卡收银台。

例如，Amazon 卖家不能因为喜欢另一家支付公司的费率，就把平台的买家收银台换掉；需要查的是平台允许的卖家结算出口。独立站商家应核实自身能否开户收单，软件订阅经营者可进一步比较 MoR 的销售责任与成本，而大额企业服务交易通常先咨询合同收汇要求。看似同属“收钱”，可选范围来自不同的销售关系。

### 2.2 Visa、PayPal、Stripe和银行账户分别是做什么的？

沿着刚才那张29美元订单，从顾客到商家看四次交接，就不会把每个名字当成同一类“收钱工具”。

**第一步，顾客选付款方式。** 他可能拿银行卡，也可能选择 PayPal 钱包。**Visa、Mastercard（万事达）、银联**主要是卡片背后的支付网络，帮助银行卡交易在相关机构之间传递和处理；它们不是一个商家可直接拿来申请的独立站银行账号。PayPal、支付宝、微信支付既可能出现在顾客付款选项中，也各有需按条件开通的商家产品。顾客可以使用某种钱包，不代表卖家已获批它的商家功能。

**第二步，有人替符合资格的商家处理付款。** 比如 Stripe 或获准的 PayPal 商户产品。行业里把部分提供此类服务的公司叫 **PSP（Payment Service Provider，支付服务商）**；具体收款还涉及有资格的收单机构和商家合同。**第三步，平台或服务商核算可划给商家的款**：这叫结算，看到可结算余额仍不是银行已经入账。**第四步，按合规条件划入最终账户**：银行账户以及 WorldFirst、Wise 的特定账户或汇兑服务可能参与这一段，但有一个境外账号不会凭空产生对应地区的商户资格。市场平台与软件 MoR 则可能在第二、第三步承担不同合同责任。

另有反方向：顾客申请**退款**是要求退还交易款；遇到银行卡持卡人经发卡行提出交易争议并追回款项的情况，通常称为**拒付（chargeback）**。发生争议时，钱未必只从这一笔付款直接退回，可能从商家余额或未来结算款扣回。理解了这几个角色，再读下面两条完整链与机构对照表，就能看出同一家公司在不同产品中也可能扮演不同角色。

**合同与付款链（顾客看到的一面）：**

`顾客（所在地/币种/付款工具） → 销售合同中的卖方（你/平台/MoR） → 收银台或发票 → 可接受该支付方式的服务商/收单机构 → 成功的交易记录`

收银台显示成功时，钱可能还在平台或支付服务商的结算余额里。WorldFirst、Wise 或银行账户涉及的是特定产品允许的收款、结算、换汇或转出服务，并不会仅凭一个账户就替商家收银行卡付款。看第二条链时，要核对谁结算、钱停在哪里，以及何时能合法转到最终账户。

**资金及责任链（商家真正要用钱的一面）：**

`成功交易 → 结算责任方（平台/PSP/MoR） → 商户可结算余额或供应商应得款 → 允许的提现/汇款路线 → 合规受款账户 → 经营中可支配币种`

退款或拒付发生后，钱还可能反向流动：`顾客退款/发卡行争议 → 合同中的处理方 → 账户余额/后续结算款/约定补款 → 商品权益和销售责任`。所以选方案时也要知道谁接收争议、从哪个余额扣回款项，以及商品权益由谁处理。具体售后流程在第⑥板块再展开；这里只核实责任关系能否说清楚。

| 容易混淆的名称 | 位于模型的哪一层 | 它**不能**自动替代什么 |
|---|---|---|
| Visa / Mastercard / 银联 | 卡品牌与卡支付网络；顾客银行卡的一种基础设施 | 不是独立站商户账户或经营结算账户 |
| 支付宝 / 微信支付 / PayPal | 可以是顾客付款方式；其中支付宝、PayPal 等还经营商家支付产品，**要以具体产品/账户为准** | 顾客有这些钱包，不代表你的商家身份已开通相应跨境产品 |
| Stripe / PayPal 商户产品 / 合规境内收单服务 | 接受和处理顾客付款的服务能力 | 并不自动替你开立任何银行收款账户、批准所有商品 |
| Shopify / Amazon / 淘宝等销售平台 | 商品与订单场景；有的平台提供统一收银台、卖家结算 | 平台的卖家应收款不等于本人银行现款，也不自动等于 MoR |
| Paddle 等软件 MoR | 对其覆盖交易承担名义销售方及相应交易义务 | 不能替代供应商的所有税务与产品责任 |
| WorldFirst / Wise / 银行账户 | 依产品可能承担合法资金接收、结算、换汇、汇款等角色 | 有境外账号 ≠ 可用境外主体注册 Stripe ≠ 能替顾客完成商户收银台支付 |

**以 Shopify 实物独立站为例。** 用第三方卡支付时，顾客银行卡→第三方收单→第三方结算→合格提现账户；Shopify 还可能在店铺账单另收第三方交易费。[S09] 另一种路线仅针对实际获邀并通过验证的中国版 Shopify Payments 商家，顾客卡→Shopify Payments→**经验证的 WorldFirst 账户**，再沿 WorldFirst 合规渠道到经营账户。该受邀服务有自己的一套大陆企业资格，不能凭它去申请香港 Stripe 商户。[S03][S04]

一条能用于比较的收款路线，应当交代顾客用什么付款、哪个机构受理、谁向商家结算、哪些账户能合法接款；退款时，还能找到相应的扣款和责任主体。如果其中某一站的受款名义、币种或合同规定查不到，就把那一站写作 UNKNOWN，避免把整条路线误记为已开通。

## 3. 我这样的卖家能用哪些收款方案？

### 3.1 我是个人还是公司、卖什么、卖到哪里，会限制能用的方案吗？

**会，而且应在看费率之前排除不合格组合。** 对那位卖29美元模板的大陆自然人，只检查三件事就能做第一轮筛选：①真实身份是否可以申请这家服务商的**这个商家产品**；②原创模板是否属于它同意受理的商品；③结算款是否有合法、同名且可使用的资金出口。哪项明确不支持就排除，哪项还在审核就保留“尚未知晓”，不要把申请页面等同于开户成功。

反过来，一家有真实大陆注册资料的实物出口企业，可能获得另一套产品资格；有真实经营活动的香港公司也不是“多了一个香港银行账号”的大陆自然人。这些主体并不能借用彼此的费率与许可。比如 Stripe 的通用商户地区规则、中国区特定协议的 PayPal 商户产品、受邀的 Shopify Payments 中国版，本来就是不同合同。下面再按六种经营条件列出应核验的可能路线，表格是筛选器，不是开户保证。

| 经营条件 | 值得核验的收款组合 | 应明确排除或保留 UNKNOWN 的部分 |
|---|---|---|
| **大陆自然人，向海外卖自己制作的数字文件** | 若具体 PayPal 中国区账户/产品接受该身份与商品，可评估自己的商家收款；若是符合要求的软件产品，可评估 Paddle MoR；数字内容平台亦可评估其卖家/提现条件 | Stripe 一般自助商户地区清单不含中国大陆；不能用一个 Wise/HK 账户“创造”香港 Stripe 资格；PayPal 账户功能、MoR 个人身份批准与提现均未因注册页面存在就确定。[S01][S02][S06] |
| **大陆个体工商户、境内自营交易** | 与真实经营主体、网站/小程序资质和业务相符的支付宝/微信支付商户产品，或平台原生收银台 | 普通私人转账码不当然具备网站经营收单与对账等能力；跨境产品不能不经审核用于纯境内交易。[S12][S13] |
| **大陆企业，跨境实物独立站** | 真正接受大陆企业、商品与海外客户的第三方支付商；若 Shopify 特定商户获邀，可比较“中国版 Shopify Payments + WorldFirst” | Paddle 以软件为目标、不适用于实物；通用 Stripe 全球商户支持清单并不因 Shopify 中国版存在而自动放开。[S03][S04][S08] |
| **大陆企业，跨境平台经营** | 平台认可的卖家收款/结算方式，例如 Amazon 全球收款或合规指定服务 | 独立站插件、Stripe 收银台不能绕开平台控制的买家结账；平台卖家账户审核仍是前置条件。[S11] |
| **实际运营的香港公司/其他境外公司** | 可按**真实主体所在地及实际运营证据**研究所在地区 Stripe、PayPal 等 | 不能直接挪用大陆个人或大陆公司资格；境外公司也仍有税务、商品、银行和结算限制。[S01][S14] |
| **大陆企业，海外 B2B 合同大额交易** | 真实贸易/服务合同对应的合规银行收汇或被许可的企业跨境资金服务 | 不能把平台卖家钱包当作通用企业电汇账户；银行所需贸易真实性、结售汇或监管要求要以具体业务及银行为准，费率 UNKNOWN |

Stripe 和 PayPal 正好说明为什么要核对到具体产品。Stripe 的[全球商户支持地区](https://stripe.com/global)有香港，未将中国大陆列为一般独立商户的开户地区；已经具备受支持地区商户资格，才谈得上向全球顾客收款。PayPal 在中国大陆有跨境商户服务，但 [S02] 所列公开费用仅适用于按**《PayPal中国跨境支付服务用户协议》及《PayPal全球服务条款》**开立的账户，**不适用于根据另一《PayPal支付服务用户协议》开户的账户**。这类国际商业交易比例费是4.40%，高级在线卡产品还要另行申请批准，不能把这组数字当成所有 PayPal 中国账户的统一报价。[S01][S02]

Shopify Payments 的中国版属于另一种特定产品安排。[S03][S04] 官方目前仍将它列为受邀早期体验，面向符合条件、开展跨境销售的大陆注册企业；商家需要接入并验证 WorldFirst，且不能用来处理面向中国大陆顾客的境内销售。即使公司主体符合描述，是否收到邀请、使用的套餐和实际卡费，仍要在自身店铺中确认。

读完六行矩阵后可以自己做一次检验：若一家企业确实是大陆注册，就不要直接取“香港公司”那一行的价格或资格；若一家公司卖实物，就不要用“软件 MoR”替代商品准入核验。**适用地区—主体—产品—商品—资金终点**五个条件，应沿着同一商家信息核对，任一 UNKNOWN 都要留下证据缺口。

矩阵的用法是筛掉明确被排除的主体、地区或商品组合。只看到可申请说明、还没拿到审核结果的，仍是 **UNKNOWN 候选**。确认可以受理付款并依法结算之后，比较费用才有实际意义。

### 3.2 怎么确认顾客付的钱能合法到账，退款时也有人负责？

设想美国顾客已成功支付29美元，你在后台看到一笔“余额”，但银行账户今天没有增加一分钱。**这不一定是系统出错：付款被接受、金额变成可结算款、达到可提款条件、实际进银行，是四件事。** 有的服务还要求达到最低余额才能提款，有的要先通过收款人或交易审查。

顺着这笔钱向前检查：顾客的付款方式真的能在该商品上使用吗？交易中到底谁是卖方？负责处理付款的机构有没有把它记为成功？扣掉费后是否成为可用的应结算款？是否达到最低提款额？最终银行是否有权接收这一类款项？**然后逆着路线检查退款与拒付**：谁受理请求、谁承担扣款、在哪个余额补回，以及电子商品下载权益怎么处理。只有正向与反向都说得清，才有可能形成可经营的闭环。下面把这条故事拆成可核对的六个节点。

1. **顾客受理：** 本地区顾客实际能用某种方式付款，且该方式在商户合同中可用。
2. **对顾客的销售：** 谁在订单上是卖方？能否销售这一商品和收费模式？退款说明由谁承担？
3. **付款处理：** 是扣款成功、待结算还是预授权？这里不展开支付状态技术机制。
4. **净可结算款：** 支付/平台扣费、可能的退款与预留金之后，哪些金额成为可提余额？余额可能因审核而被限制。
5. **提现通道：** 何种受益人名称、银行地区与币种允许提现？有哪些最低额、频次、固定费与审查？
6. **银行与可用货币：** 到银行后还需何种中转、入账或换汇处理，经营账户能否实际动用？争议时钱可能如何回流？

检查完六个节点，还得能说出每一步的币种、账户名义、负责机构、最低提现额和最终收款人。遇到退款或拒付，应在合同里找得到谁负责处理，钱从现有余额、后续结算款还是约定补款中扣回，商品权益由谁处理。任何关键一环尚不清楚时，预计到账只能作为估计，不能写成已经获保证的时间。

拿 PayPal 中国区美元电汇来试算就很清楚。[S05] 提现说明列出大陆银行电汇最低 **US$150**，一般为 **3–7 个工作日**，并提示审核和银行规则可能影响处理。[S02] 对应的**企业 PayPal 账户**费率表列出大陆电汇 **US$35/笔提现**。这些数字能用于条件模拟，个人或企业的真实账户是否获准使用该路径，仍须看审核与受款银行。[S02][S05]

Lemon Squeezy 官方说明可用受支持银行或**已验证的 PayPal 账户**接收卖家款项，结算有持有期和半月周期；其银行提现国家名单未列中国大陆，不能把“支持全球卖家”理解为“中国大陆银行可直接提现”。个人 PayPal 账号是否在其风险/商品审批下实际获准，应记 UNKNOWN。[S10]

如果前五个节点都能查到，仅最后“银行能否接收这一主体的这类营业款”还没有书面确认，闭环仍未验证。这也是为什么“后台有余额”不是可以向顾客保证退款资金或向供应商承诺付款日期的证据：要把资金流和责任流同时查通。

完成这六步检查后，可以按证据充分程度把候选分成三种状态：
- **已验证闭环：** 主体、产品、支付、合同、提现终点已经有足够证据；进入实际费率比较。
- **条件性闭环：** 规则上可能支持，但身份审核、店铺激活、银行/提现授权或费率尚 UNKNOWN；只能进入备选研究，不能当成上线能力。
- **不能闭环：** 出现明确 NO；直接排除，不靠改地址、借账户补救。

## 4. 不同方案的手续费、到账速度和风险怎么比？

### 4.1 一笔订单扣完手续费和提现等费用，到手还能剩多少？

先只算一笔，暂时别比较三个品牌。**假设**卖家有权使用[S02]所限定的 PayPal 中国区国际商业收款产品，美国买家支付29美元，交易收费按 **4.40%×29 + 0.30美元 = 1.576美元**，例示取到美分约**1.58美元**。扣掉这一层已知交易费，余额约 **27.42美元**。这一步能够算出，却仍**不能**回答“银行到账多少”：可能还要等余额满足最低提款额，另有平台费、银行费、汇率、退款或资金暂扣。此处绝不意味着任意大陆个人已获批使用这一产品。

再按钱走过的四道门做记录：**G** 是顾客付的总额（这里29美元）；**T** 是扣掉交易相关费用后的账面金额（这里只算已知费用，约27.42美元）；**A** 是经过平台调整、退款或预留金并满足条件后可以**申请**划走的金额；**B** 才是银行实际入账并可按经营需要使用的金额。G、T、A、B 不是四种名称的同一笔现款。同一笔订单可能 G 与 T 已知道，A 尚不够提现，B 只能填 **UNKNOWN**。下面的四行金额表适合在完整账单到手后逐栏填，而不是读完定义就假设每一栏已经有值。

复杂比较按这个顺序加变量：先看29美元一单的交易处理费，再看5单、6单、100单合批后最低额与固定提款费；随后才比较**同一大陆商户**的不同获批产品，以及自己收款和软件名义商家在责任上的差异。不同地区公开收费只用于学习怎么算，不能当作同一卖家的报价排名。

| 金额 | 算的是什么 | 常漏掉什么 |
|---|---|---|
| **顾客付款金额 G** | 顾客实际支付的含税/不含税合同总额（应统一税价口径） | 不等于商家应得销售净额 |
| **交易后余额 T** | G − 支付百分比费 − 固定费 − 适用平台交易费 | 款项可能还未结算、尚有风险预留 |
| **可申请提现余额 A** | T − 已确定的平台佣金/调整/退款/预留与其他适用扣项 | 低于最低提现额就不能直接换成银行现金 |
| **银行实际入账 B** | 符合门槛的 A − 本批提现费 − 已知中间行/入账扣费 − 按**实际汇率**计量的换汇影响 | 银行尚未到账、目的币种不明时必须记作 UNKNOWN |

从顾客付款金额 G 算到银行入账 B，官网收费标准、实际商户合同和演算假设必须分清楚，缺少的报价记 **UNKNOWN**。尤其是换汇，需要知道转换方向和真实汇率；“免提现费”并不表示换汇一定免费。退款、拒付可能带来费用，但是否发生、原收款费能否返还，要另按产品规则和实际订单判断。

#### 一笔 $29 订单：费率示范，不是跨地区服务商排名

**这一小节只回答“同一张29美元订单，不同报价结构怎样计算”，暂不回答“谁更适合你”。** 先选第一行练习：费率中“4.40%”随订单金额变化，“0.30美元”是不随这单价格变化的固定一笔，两项相加再从29美元扣除。第二行的香港 Stripe 要有真实香港商户资格，第三行的软件 MoR 是另一种销售合同。若没有这些前提，把三行按27.57、27.42、27.05美元排序，就会作出不成立的选择。

一笔29美元订单，可以用三种公开收费结构演算。但请留意每一行对应的商户资格：大陆的特定 PayPal 协议商户、真正具备香港商户资格的 Stripe 账户，以及被 Paddle 接受的软件 MoR 交易，承担的销售责任并不完全相同。因此这里比较的是费用如何计算，不据此排名实际可用的收款服务。

| 价格结构的例子 | 前提 | 单笔交易费 | 仅扣交易费的余额 |
|---|---|---:|---:|
| PayPal 中国大陆国际商业交易 | **仅**符合 [S02] 指定双协议的 CN 账户，顾客国际 USD 商业付款 | 4.40%×29 + $0.30 = $1.576（例示按美分计 $1.58） | **约 $27.42** |
| Stripe 香港商户 USD 卡交易 | 真正具备 HK 商户资格，卡属于国际卡；无币种兑换 | 3.4%×29 + $0.30 + 0.5%×29 = $1.431（例示 $1.43） | **约 $27.57** |
| Paddle 软件 MoR 标准价 | 受 Paddle 接受的软件商品，由 MoR 销售 | 5%×29 + $0.50 = $1.95 | **$27.05** |

HK Stripe 另可有换汇与争议费用；上述数字均未包括任何平台费、提现费、银行费、消费者税、商品履约/客服成本或退款。[S02][S14][S07]

#### 相同大陆经营主体、同一批订单：PayPal 美元提现如何改变答案

现在只改变**同一个企业账户一次提几单的款**，不更换商家所在地或产品。先看5单：费后余额137.10美元低于150美元门槛，所以即使订单成功，这批也不能按这个美元电汇路线立即提款。第6单进来后，164.52美元达到示范门槛，扣已知的企业固定电汇费35美元，才出现129.52美元的银行到账前估值。这里最重要的是**能不能提**先于**提走以后贵不贵**；仍不能把估值说成实收。

把订单合成一批，固定提现费的影响就明显了。29美元一单，示例支付费后约27.42美元；卖出六单，顾客总共付174美元，交易费后为164.52美元，刚过该美元电汇路线150美元的最低申请额。按对应**企业账户**每次电汇35美元再扣一次，银行费用与换汇之前只剩约129.52美元。若只盯着4.40%的比例费，这笔差额很容易漏算。

| 100 | $2,900 | $2,742.00 | **是** | **$2,707.00** | **$0.35** |

\* 表格按逐单先四舍五入到美分的简化方法计算，并假定没有预留、退款、拒付或其他余额调整。PayPal 实际逐笔舍入方式与账户可提状态需要另行确认。银行入账与中转费用、结售汇汇率和合法受款条件仍为 **UNKNOWN**；129.52 美元等数字仅表示扣除已知收款与企业电汇费用后的**银行入账前估值**，不能当作实际到账或人民币利润。

同样一条企业美元电汇路线，五单的费后余额137.10美元，低于150美元门槛，眼前没有可按这一路径申请的提现额。若商家本月就要付经营费用，要么接受继续攒单，要么核实其他有资格、门槛更合适的合法渠道；百单时35美元固定费摊到每单仅0.35美元，取舍可能随之改变。**35美元是这里特定企业账户的费用示例**。大陆自然人的适用协议、账户准入与电汇收费必须分别核验，不能照搬。

#### 严格同条件选型：大陆商户同一 $29 商品的两种合规收银台

**真正的比价从锁定交易条件开始。** 假设仍是一家大陆商户、同一商品、同样的美国买家、同样的提现用途；先问 A 与 B 哪些业务功能经批准，再比较费率。B 的在线卡高级产品如果没有获批，省9美分的报价对这家卖家没有现实意义。读下面的表时请把“能用吗”一列当作门槛，把“便宜多少”当作第二轮判断。

跨地区的三行公开价已经介绍了收费结构，实际选型要回到同一个商户。设想一家符合 S02 协议的大陆商户，销售同样29美元的商品，面对相同海外顾客，美元结算且使用已获准的提现路线。路径 A 是其已批准的 PayPal 标准国际商业收款；路径 B 则要求商户**另外申请并获准在线卡付款服务高级版**，其国际卡公开价为 **4.10% + $0.30**。[S02] 没有拿到 B 的批准，就不能把它当成现成的低费率选项。

| 比较维度 | A：合格账户的 PayPal 国际商业收款 | B：获批的在线卡付款高级版 |
|---|---|---|
| 主体与价格 | 同一个真实大陆商户、同样 $29 | 完全相同 |
| 付款覆盖 | 适用于其获准的 PayPal 商业交易能力 | 须进一步获得在线卡付款批准；覆盖银行卡客群 |
| 交易费（示范） | $29×4.40% + $0.30 ≈ $1.58 | $29×4.10% + $0.30 ≈ $1.49 |
| 单笔费差 | 基线 | B 少约 **$0.09/单**（未含可选服务/风险附加价） |
| 提现与资金终点 | 若采用相同被认可的美元电汇路径，仍需满足门槛、$35 每批 | 同样；不能因为 B 交易费低就省略提现成本 |
| 决定主用的条件 | PayPal 顾客覆盖对销售更重要或 B 未获批 | B **确实获批**且更多目标顾客要直接使用银行卡，附加服务费等核实后有优势 |

表里的每单约9美分差距只是已知处理费的差距。B 若没有获批，连候选都谈不上；若 PayPal 付款和直接银行卡付款分别服务不同的顾客，商家可能需要两种能力同时保留。需要顾客实际使用数据以后，才有理由为了这几美分改变主用方式。香港 Stripe 的价格不能挪来充当同一大陆账户的替代报价。

同样的比较方式也适用于 Shopify 实物独立站。把经营主体固定为同一家大陆企业，店铺和29美元订单不变：路径 A 由已经获准的第三方服务商收单，还可能支付 Shopify 另收的第三方交易费；路径 B 必须等企业**真实收到中国版 Shopify Payments 邀请、完成 WorldFirst 验证**才存在。获得商户实价以后，两种路线才能代入下面的费用式。

- A 的净资金基数 = $29 − 第三方支付费 − Shopify 第三方交易费 − 适用货币费与该路线摊销提现费；
- B 的净资金基数 = $29 − 中国版 Shopify Payments **该计划实际卡费** − WorldFirst 后续实际收费/汇兑 − 该路线摊销提现费。

官方规定 Shopify 第三方交易费可能**另加在**第三方支付费之上；使用 Shopify Payments 作为唯一提供商时相应第三方交易费不收，但两条实际卡费、商户差异化费率、币种和 WorldFirst 结算报价尚须核验，**本例不给出虚构单笔净额**。[S03][S04][S09] 如该 Shopify 套餐实际第三方费率为 (t)，这层成本在单笔 $29 商品上是 **$29×t**；例如 (t)=2% 仅作为数学敏感性示例，就是 **$0.58/单**，**并非断言该大陆店铺当前实际被收 2%**。取得双方账户实价后再填入两式，辅以退款/通过率和到账期限确定胜出者。

#### 相同经营者的软件业务：为何 MoR 价格不能只与 PSP 抽成相比

再改变的不是几美分费率，而是**谁向消费者销售**。同一个软件商家如果自己作为卖方，就要自己承担适用的消费者交易和相应税务处理；如果合格的软件订单由 MoR 作为卖方，覆盖交易的销售责任及部分税务工作会按合同转移。因此一个报价同时买了付款处理与部分销售运营，另一个可能只买付款处理。判断“谁更省”之前，必须把税价口径和双方实际承担的工作对齐。

卖软件时，选择 MoR 还意味着改变对消费者的销售安排。假设同一大陆经营者面向同一海外市场销售**29美元/月的软件**，而自己收单与 Paddle 软件 MoR 均已获准。按公开标准，本例 PayPal 产品每单约扣1.58美元，Paddle MoR 每单1.95美元，支付环节相差约0.37美元。十单的 Paddle 交易后供应商应得初步基数约270.50美元；官方列有月度结算、最低100美元门槛，部分方式可能另有15美元 SWIFT 费用，银行与换汇还需另算。[S07][S15] 同样十单，PayPal 沿本例对应**企业账户**美元电汇路线扣完两层已知费用约239.20美元，仍未计入银行收费。

270.50 美元和 239.20 美元还不能直接用来宣布哪个更划算。Paddle 在覆盖交易里承担面向顾客的销售方身份与相应消费者税处理、收据、订阅及争议工作；自己收单的商家承担另一套责任。先把消费者支付价统一到同样的含税口径，分别向 MoR 索取供应商最终应结算对账单，并算上自己收单时的税务、支付和争议成本，再比较银行可用款和日常工作量。若销售的是 Paddle 不接受的模板或课程，商品资格已将其排除。[S06][S08]

### 4.2 除了手续费，还要比较哪些会影响成交和到账的因素？

假设两条合格收款路线的纸面手续费只差几美分，但第一条允许目标客户直接使用熟悉的银行卡，第二条只能让某些买家换一种付款方式；或者第二条费率较低，却让需要14天内补货的商家等更久。哪一条更好，不能靠“费率最低”回答。对同一批顾客和同样的订单，先问**能否成交、何时能动用款、出退款争议后谁承担损失、主渠道中断以后还能否收款**，再把这些结果和费用放在一张决策记录里。

这里的**付款成功率**指同一口径的有效付款尝试中最终成功的比例，不能由“支持多少国家”推断；**资金预留**意味着服务商暂时留住部分资金以处理风险，账面余额不代表立刻能用。退款是按交易或合同退钱，银行卡拒付则可能引入发卡行的争议流程及其他费用。备用不是同一个支付账户改绑银行卡，而是另一条有资格接单并合法结算的路线。

- **付款覆盖/成交损失：** 美国客户能否用习惯的银行卡、PayPal 或钱包，是否必须跳转？只有同一客群的**真实支付尝试和有效订单**才可比较转化率，不可把全球支持“195+ 国”视作该店铺成功率。
- **现金时间成本：** 实物卖家可能要先付采购和物流款，资金预留、提现门槛与结算等待会影响下一次备货。记录交易发生日、可申请提现日和预计银行可用日，逐项核对，别只填一个“到账快”。
- **预期争议/退款占用：** 比较渠道规则、可能不返还的初始支付费、争议费和举证负担，未有商户数据时将发生率标 UNKNOWN，不用拍脑袋给风险费率。[S02]
- **中断与迁移成本：** 一个支付商停止服务能否改用另一独立受理方？同一账户换银行不算完整备用；MoR 迁移订阅付款凭据、平台换销售渠道，都可能不是即时切换。

可以假设一组数据看看支付成功率值得多少关注：客单价29美元，100次同质量的真实付款意向中，若 A 比 B 最终多完成3笔交易，A 多出的销售额就是 **3×29 = 87美元**。这只是条件演算，并没有真实测到两家的通过率；87美元也不是利润，履约、税务、退款和争议成本都要扣除。实际选择仍需要同一客群的支付尝试和有效订单记录来验证。

给14天内需要进货的企业一个实用顺序：先排除**不能满足资金期限**的路线，再对剩余可运行方案记录同样100单的费用；若另一路线顾客付款成功率确实更高，还应比较**真实多成交订单带来的贡献**能否覆盖多出的收款费。此时才轮到更高阶的交易成本、切换风险和付款方式分布，而不是先争论某个公开费率小数点。

最后把这些条件落到同一批订单里：顾客总付款、支付费、平台佣金、最低提现额和每批固定费、预计可用日期，以及退款和争议假设。银行费、汇兑报价与获客方式若有差别，也要分别列出。重要项目没有数据就写 UNKNOWN；关键资格或成本还没查清时，暂时保留候选，比依据不完整报价宣布胜出更可靠。

## 5. 到底该怎样选定主用的收款方案？

### 5.1 怎么从真正能用的方案里选主用和备用？

回到开篇29美元模板：最终要做的不是凭一个品牌名称拍板，而是交出一张**有依据的主用/备用判断卡**。写清四格即可：**订单是什么**（商品、买家、卖方、渠道）；**谁真的允许收**（真实主体/商品、客户付款方式、银行出口核验）；**按同样订单实际能用多少钱、何时能用**；**如果主线失效，另一家能否单独受理并退款、结算**。前面四节已经分别准备了这四格需要的数据。

先强调结果分类：某条路线有官方通用介绍，或你已经递交开户申请，都不等于它真的可运行。**NO** 立即排除；**UNKNOWN** 是待核实，不是已经可以上线；只有条件与实际审核都支持时才考虑把它升为已验证的主用。备用也要独立完成支付与合法入账，**同一商户账户换提现银行卡不是备用**。接着用四轮细化选择，并让两个完整假设案例走一遍。

**第1轮，定销售合同与成交渠道。** 订单发生在平台、自有网站，还是对公合同？由此决定研究平台卖家结算、自己商户收单、软件 MoR 或 B2B 银行收汇。换销售模式也会换获客成本和责任，不能只减几笔手续费就作结论。

**第2轮，把不能用的路线排掉。** 按第3节核对实际主体、商品和目标顾客、销售责任及最终合法受款账户。NO 立即排除；还没获批的 UNKNOWN 只能留下来继续查。

**第3轮，算同一批订单什么时候能真正用钱。** 除付款手续费，还要填 Shopify 等平台附加费、提现次数、时间和本月采购需求。退款率、银行费和汇兑费查不出来就写 UNKNOWN；碰到小幅费差，优先满足业务最不能拖的条件。

**第4轮，准备真正能独立收钱的备用。** 主用渠道应能证明资格及资金去向。备用服务商也要能独立受理核心顾客、履行退款责任并合法结算。换银行卡、同一 PayPal 账户换香港受款银行，或者同一平台再开一家店，都不足以替代独立收单方。

用两份不同生意来检验这套方法：一位大陆自然人向美国买家卖29美元设计模板，一家大陆企业销售29美元实物。两者的付款资格、资金期限和可用业务模式不同。以下只是条件化教学案例；任何尚未实际批准的收款与提款路径，都不能当作已经可用。

#### 演练 A：大陆自然人向海外卖数字产品，单价 $29

**先读判断，不急着读产品名：** 这位假设卖家既没有香港真实经营主体，也没有获确认的海外商户提款资格，故不能凭香港银行账号选择香港 Stripe；他卖的是设计模板，不能把“数字文件”当作已经符合软件 MoR 审核。可能的 PayPal 商户方案与原创模板平台，都需要分别证明真实个人身份、具体商品及合法银行终点。月5单如果急用钱，先看最低提款额而不是只看单笔费；没有任何一条获确认时，结论就是**仍未找到已验证主用**。

假设有一位大陆自然人，在自己的网站向美国个人销售原创设计模板，买家付款后下载文件，每份29美元，没有订阅。他没有实际经营的境外公司，刚开始每月只有5单，后来可能达到100单，销售所得希望进入本人依法可以接收经营款的账户。这里尚不知道他符合哪一种经营及商户开户资格，因此只能按条件推演。

在自有网站出售模板，他就是需要向买家负责的卖家，必须找到接受其真实主体的商户收单产品。若搬到数字商品平台销售，谁作为卖家、退款由谁处理、款怎样结算，都要看平台合同。**Paddle 这类软件 MoR 不保证接收设计模板**；“数字商品”四个字并不能替代产品类别审核。

| 候选与判定 | 准入/责任 | 资金闭环 | 决策 |
|---|---|---|---|
| 自己开户使用“香港 Stripe” | 大陆个人没有相应真实香港商户主体；HK 银行账号不改变资格 | 无合法已证实的商户开户前提 | **NO，排除** |
| Paddle 软件 MoR | 本例是设计模板，不是典型的软件/SaaS；官方主要针对软件，不是全部数字品 | 即使销售品类变为软件，也须验证卖家审批及收款账户 | **本例不作为主选；若以后改为软件产品才重新核验** |
| 按适用中国区协议经营的 PayPal 商户收款 | 须证明自然人/实际业务能使用所需的商户产品、商品符合规则，按真实身份审核 | 若账户确实允许以个人名义将经营款合法美元电汇至合规大陆银行，需要核验 $150 最低额与**本人真实费率**；$35/次来自特定企业账户，不能照搬，个人实际资格 UNKNOWN | **条件主选 P1：先核实个人商户能力和提款合法性** |
| 可销售原创模板的**数字商品平台** | 需核验该平台对数字模板、个人卖家身份、消费者交易与退款责任的具体合同 | 检查是否能真实提现到本人认可账户、最低额与平台佣金；本轮没有核验某个具体平台全链 | **备用方向 P2：找到具备已证实卖家资质和提现的具体平台才成立** |

**月5单时的选择。** 若个人确有权使用 [S02] 对应的商业付款产品，按29美元、4.40%加0.30美元的示例费率计算，五单交易后约137.10美元，仍达不到[S05] 美元电汇150美元的最低额。若本月必须拿这笔钱经营，该美元电汇**不能是唯一主用路线**。先核验允许个人卖原创模板且可合法提现的数字商品平台，或者其他实际获准、门槛合适的付款产品；也可以明确接受继续攒单。若这些都核实不了，现阶段只能判为**尚未证明有能合法到款的运营方案**。

**月100单时再判断一次。** 若符合适用 PayPal 账户、商品与提款资格，按照这一单价和收款费示例，一百单交易费后约2742美元。**企业账户**如果走同一条每批35美元电汇路线，一次提取的银行费用前估值约2707美元，每单摊0.35美元；这个企业数字只能说明订单量对固定费的影响，**不能作为该自然人可获得同费率或可提款的证明**。个人应拿自己的批准产品与真实收费重新估算。如果买家更希望直接刷卡，还要核实本人能否获批在线卡付款或另一家真正接受其身份的服务商，再决定主用方式。

这份参考案例的判断因而带有前提。本人首先需要核实适用的合法经营身份、商户协议和设计模板面向美国顾客销售的准入，再向银行确认同名账户可接收的经营款种类、限额与费用。月5单且本月急需经营现金，还得比较数字商品平台是否有更低的合法提现门槛。**PayPal 商户路线只是资格成立后的拟主用方向，数字商品平台只是待证实的备用方向；两者均未经过真实批准或支付验证。**

#### 演练 B：大陆公司向海外卖实物，$29/单，月 100 单

**先看现金期限，再看收银台。** 这家假设公司每月100单、每单29美元，却必须在约14天内筹备下一批货。若交易在 Amazon，先看平台允许的结算出口；若发生在 Shopify 自有站，才比较第三方收单与真正获邀且完成 WorldFirst 验证的中国版 Shopify Payments。只要任何路线不能按真实条件让经营款在需要时可用，费率低也不足以选为主用。

再换一家大陆公司。它有真实供货和经营资料，向美国消费者销售单价29美元的实物，预计每月100单。采购和物流需要先付款，所以回款最好在约14天内能够动用。它可能在 Amazon 市场平台成交，也可能经营 Shopify 品牌独立站；这两种成交方式会改变谁控制付款和结算。

在 Amazon 成交，平台依据合同安排买家结账并向卖家结算；Shopify 自营站通常由公司向顾客销售并承担售后，还需要合格的收单服务。平台佣金、获客成本和运营工作随销售渠道一同变化，不能只拿 Amazon 的最终结算和 Shopify 的支付费率作简单减法。

**路线1，在 Amazon 等跨境市场平台成交。** 先沿用**平台统一收银台和平台允许的卖家收款方式**。Amazon 有“全球收款”产品，可让符合条件的大陆卖家以人民币取得符合规则的跨境结算款。[S11] 真正要比较的，是同一批**平台净结算款**经不同允许出口到银行后，哪条换汇、入账时间和费用更适合14天采购期。真实账户获批及账期必须另查。若平台结算赶不上采购时间，需要安排周转资金，换一个独立站支付插件不会改变 Amazon 的卖家结算规则。

**路线2，在 Shopify 品牌独立站成交。** 这家公司卖实物，Paddle 软件 MoR 不适用；有大陆企业资格也不能因此直接按照香港主体申请通用 Stripe 商户。留下两种值得核验的收单路径，比较对象始终是同一家公司、同一29美元商品及同一批美国消费者订单。

| 同一大陆公司、同一 Shopify 订单 | 第三方被批准收单路径 A | 中国版 Shopify Payments 路径 B |
|---|---|---|
| **开通条件** | 必须有支持大陆公司、实物、美国买家及该店铺的**具体第三方提供商**；通过实际商户审核 | 必须**获得受邀资格**、符合跨境销售条件，完成 WorldFirst 验证 |
| **顾客结账** | 支付服务商允许的卡/钱包，实际支持由合同决定 | 官方说明 Visa/Mastercard、若符合条件的加速钱包；不支持对大陆消费者的境内销售 |
| **费用结构** | 该提供商处理费 + Shopify 可能收的第三方交易费 + 资金汇兑/转出费 | Shopify Payments 该店铺/套餐的实际交易费 + WorldFirst/银行后续费用与汇兑；不能把香港 Stripe 公价代入 |
| **资金终点** | 经该提供商认可并核实的企业提现/结算账户 | **指定经验证的 WorldFirst 账户**→允许的企业用途账户 |
| **到账和业务风险** | 第三方账户审核与预留、Shopify 额外费、平台依赖 | 受邀资格、WorldFirst 结算规则、付款方法与退款责任 |
| **可作主线的时点** | 收款产品及完整资金闭环都通过审核，能满足备货现金要求 | 真实收到邀请并验证成功、实价和资金周期符合业务要求后 |

**如果企业没有收到中国版 Shopify Payments 邀请**，B 直接记 NO。先找确实接受大陆企业、美国顾客及该实物品类的第三方收单 A，作为**拟主用**；尚未找到并通过审核之前，A 仍是 UNKNOWN，不能宣布独立站已具备收款能力。

**如果已经收到邀请且 WorldFirst 验证通过**，才把 B 加进来。固定这100单订单，比较 A/B 的真实交易费、Shopify 额外费用、实际汇兑及退款条件，关键还要看两条路线能否在14天内形成可用经营资金。如果现有 A 已稳定运营，B 可以先作为符合条件的备用，不能为尚未核实的费差贸然停掉 A。任何一条超过现金周转期限，即使交易费较低，也不当主用。

**备用要能单独接受付款。** 在 Shopify 中找另一家真正接受这家大陆企业、这一实物品类，并有独立合法提现路径的支付服务商，才能在主要收单方停用时继续接订单。WorldFirst 结算账户与卡收单产品分处不同环节；另外经营 Amazon 能分散销售渠道，但不能立即代替 Shopify 站内收银台。

对这家公司而言，决定前仍要核实四件事：是否已获 Shopify 中国版邀请并完成 WorldFirst 验证；第三方收单方是否接受该企业及实物商品、报价多少；Shopify 套餐的额外交易费与两条路线的退款条款；钱最终进哪个合法账户，换汇及到款日能不能满足14天备货。两家谁的实际支付成功率更高，仍得有可比交易数据才能回答。

#### 其余三类常见生意的直接决策结果

| 业务 | 先选哪一类模式 | 何时换路线 |
|---|---|---|
| **大陆国内到店/网站卖货** | 在平台成交→平台原生收款；自营网站→真实境内主体符合资质的国内收单产品（支付宝/微信支付等），按线上与线下产品区分 | 当开始跨境经营，重新审核跨境产品，不套用本地收钱码资格 |
| **全球 SaaS $29/月** | 先比“符合主体资格的自收单”与“经审核的软件 MoR”：前者保留对消费者销售与税务责任，后者把覆盖交易中的部分销售/间接税运营交由 MoR | 如果无资格申请直接国际卡收单、各地间接税义务负担大且 MoR 已批准，优先 MoR；如果已经有合规收单能力、相应税务运营能力且综合费用明显低，则自收单可优先；资金结算仍需核验 |
| **企业对企业 $5,000 真实服务订单** | 以真实合同/发票为基础，与企业银行和合规跨境收款提供商确认可接受的对公收汇；比较中转行费、汇率与结算资料 | 若订单变成高频散客即时购买，才比较卡收单与在线收银台；银行实际入账费及外汇处理逐笔向银行确认，不可照搬消费级卡费 |

无论经营哪类生意，最后都可以留下这样一份简短的选择记录：真实主体【X】经营商品【Y】，面向顾客【Z】，由谁签销售合同、谁受理付款、经营款最后进入哪个合法账户；哪些路线已排除，哪条拟主用、哪条可独立备用，还缺哪些官方或银行答复。订单量、销售渠道、现金期限或产品规则变了，再按这些条件重新比较。如果目前所有关键资金环节都还是 UNKNOWN，就应写明**“尚未证明存在可运行且能合法到账的方案”**，不要把申请意向当作开通结果。
