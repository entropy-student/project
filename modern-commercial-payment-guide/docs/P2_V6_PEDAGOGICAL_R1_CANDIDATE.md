# ① 收款方案选择：我的生意应该选择哪种收款方案？

假设你在自己的网站上卖一份29美元的设计模板，美国顾客点了付款。接下来你最想知道的，大概是两件事：顾客能不能顺利付钱？钱什么时候才真正能用？这两件事不能只看付款页面的“成功”二字。款项可能还在平台或支付公司那里，也可能暂时达不到转进银行的条件。

我们先不比较Stripe、PayPal、WorldFirst谁更好。你可以先把收钱想成三件不同的事：**顾客用什么付钱、谁帮你的生意接下这笔钱、钱最终能不能合法进你的经营账户。** 银行账户只负责其中一部分；有银行卡并不等于网站就能让顾客刷卡付款。后面再解释这些机构和支付品牌各自负责什么。

这一章按四步来判断：**①你卖什么、卖给谁；②哪些收款办法真的允许你使用；③扣完费用、等到结算后你能拿到多少、何时能用；④怎样选主用与备用。** 每一步我们都回到这笔29美元的假设订单。等你理解这条简单路线，再读各类合同、费率和退款规则，就知道为什么要查它们。文末还有大陆自然人卖数字模板、大陆公司卖实物的两份完整演练。

## 1. 我的生意收钱时，首先要考虑什么？

### 1.1 卖什么、卖给谁、在哪里卖，会影响怎么收钱吗？

会。想象同样卖一份29美元的设计模板：卖给国内顾客，顾客也许习惯支付宝；卖给美国顾客，他可能想刷卡或用PayPal；放到第三方商品平台上卖，付款页面可能由平台决定。你卖的商品、卖给谁、在哪个网站或平台成交，会改变“能用哪些办法收钱”。

先不用学所有支付名词。拿出一笔会重复发生的订单，只回答三个问题：**顾客在哪里、你卖的是什么、钱最后要进入谁名下的合法账户？** 例如，你是大陆自然人，在自建站卖数字模板，希望收入进入自己有权接收经营款的账户。现在我们还不知道哪一家支付公司会批准你，这正是下一步需要查的。


仅凭刚才三个问题，就已经能排除一些不合适的比较。例如卖29美元软件订阅，要考虑顾客能不能按月支付；卖29美元实物，还要考虑采购款什么时候拿到；做一笔5000美元的企业服务单，顾客可能直接按合同汇款。这些生意不能拿同一张手续费排行榜决定。

为了继续比较，再把刚才的生意描述得具体一点：“一家大陆公司在Shopify自营店向美国顾客卖29美元实物，每月约100单，采购和物流款主要用人民币支付，14天内需要钱采购下一批货。”现在你已经知道顾客在哪里、谁卖货、单价多少、何时需要钱。

下面才是**完整的七项检查表**。第一次看不用背：只要知道它是在补齐上面那些信息。表内会出现几个专业名词：**收单**就是商家使用获准的服务来接受顾客付款；**SaaS**是通过网络持续提供的软件服务；**B2B**是企业卖给企业；**MoR**是某个服务商在它承接的交易中直接作为对顾客的卖方，而不只是帮你代收钱。先理解大意，后面会分别展开。

| 画像维度 | 必须作出的描述 | 直接决定什么 |
|---|---|---|
| **销售责任人** | 谁在订单/合同/发票/退款条款中向顾客销售：商户自己、平台还是 MoR？ | 商户身份、争议与税务责任边界、可用合同 |
| **真实经营主体** | 大陆自然人、个体工商户、大陆企业，或确有经营事实的境外实体；主体与账户名义是否匹配 | 哪些服务商能受理申请、可使用哪一类账户 |
| **商品与风险** | 实物、软件/SaaS、数字文件、课程、人工咨询；是否订阅、预售、延迟发货、限制品类 | 商品许可、收单支持、退款/预留与 MoR 适配 |
| **顾客与销售地区** | 大陆/海外、个人/B2B、核心目标国家和常用付款方式 | 支付覆盖、跨境规则、消费者支付阻力 |
| **销售渠道** | 国内平台、跨境市场平台、独立站、自己的 SaaS、B2B 发票交易 | 谁掌握结账、是否允许外部支付、平台附加费 |
| **交易结构** | 典型客单价、月订单数、订阅周期、退款率区间与采购垫款需求 | 固定费敏感性、结算周期、风险准备金压力 |
| **资金终点** | 哪一个**有权接收经营收入**的账户，何种币种、何时要用于经营 | 结算、最低提现、汇率、银行成本和到账可行性 |

### 1.2 哪些条件必须满足，哪些可以按费用和方便程度来选择？

你可以把收款渠道想成一家要申请合作的店铺服务：**如果它不接受你的真实身份、不允许卖这种商品，或者钱不能按规定转进你有权使用的账户，那它再便宜也不能选。** 另外还要检查顾客是否有可用付款方式，以及发生退款或付款争议时谁负责。拿上面的大陆自然人模板生意来说，有香港银行账户并不会让他自动获得香港地区的Stripe商户身份。这是“必须满足”的条件，不是手续费问题。

只有确认可以申请、可以销售、可以合法拿到钱，才轮到比“哪家更好用”。比如两种都能收美元，都允许你提现到合适账户，再比顾客付钱是否方便、手续费、等待时间，以及以后换渠道有多麻烦。请先分开**能不能用**与**用哪家更划算**。

查规则时先用三句中文做记录：**确定可用、明确不能用、还没弄清楚**。行业对照表有时写成 YES、NO、UNKNOWN，意思就是这三种情况。“官网写支持某个国家”只是值得继续申请，**不等于你这个卖家的账户已经获批**；没申请过也不算“明确不能用”。只有实际产品、身份、商品和受款路线相符，且这个商家的对应审核已确认通过，才能把关键一项标为“确定可用”。

到这里，你只要能写下一句话就够了：“我卖什么、买家在哪、经营身份是什么、钱什么时候要用。”后面遇到Visa、PayPal或各种收款服务商，就拿这句话去问：它真的能帮助我完成其中哪一步？

## 2. 商家常见的收款模式有哪些？

### 2.1 自己收款、在平台卖货、让第三方作为卖方，收钱有什么不同？

接着看**谁实际在卖东西**。假设你在自己的网站卖模板，顾客是向你购买，通常也由你负责销售和售后；如果你到Amazon等市场平台卖货，顾客使用平台安排的结账方式，平台再按合同把卖家的应得款结算给你。平台控制付款，不代表它在所有交易里都是法律上的卖方。

还有一种情况：一家服务商自己作为面向顾客的销售方，负责其承接交易中的一部分销售、税务和退款事务，之后再按合同给原产品提供者结算。软件行业常把这种身份叫 **MoR（Merchant of Record，名义商家）**，它不是普通的“代收款账户”。如果你接的是企业对企业大额订单（B2B），也可能直接按贸易或服务合同收银行汇款。这样就有了四种不同安排，下面的完整表格再看各自的责任与代价。

| 商业安排 | 顾客买单给谁/谁对顾客负责 | 常见支付和资金路径 | 适合、代价与排除边界 |
|---|---|---|---|
| **平台交易：平台控制收银台并向卖家结算** | 通常平台控制支付；**平台是否法律意义上的卖方（MoR）必须看具体合同**，不能一概而论 | 平台结账→卖家应得结算款→平台允许的银行/收款服务 | 国内电商及 Amazon 等跨境市场平台；获客和支付规则一体化，但有佣金、账期、平台限制；不能把 WorldFirst 等结算账户当成顾客支付网关。[S11] |
| **自己作为商家直接收单** | 商品/服务由商家卖给顾客；受理银行卡/钱包的是有资质的支付服务商或收单机构 | 自有站/商户工具→支付服务商→商户余额/待结算→合格银行账户 | 需要自有品牌、客户和订阅关系时常见；可用境内商业支付产品或符合主体资格的跨境服务；商家保留较多售后/税务责任。[S01][S02][S03] |
| **MoR（名义商家）代为销售适用品类** | MoR 就其覆盖交易作为面向消费者的法律销售方；原供应商按合同取得分成/货款 | MoR 结账→按合同处理间接税/退款等→结算供应商 | 面向软件/SaaS 的跨地区消费，值得与自收单比较；并非包办供应商所有税务、知识产权、交付及本国经营义务；实体货或纯人工服务可能不适用。[S06][S07][S08] |
| **合同/发票下的 B2B 银行收款** | 企业直接依据贸易/服务合同对企业客户销售 | 客户银行汇款→商家合规银行或允许的跨境收款服务→可用经营资金 | 订单少、客单高、可先后签约付款的 B2B；汇款手续、贸易资料和收款用途需符合银行要求；不适合几十元的即时零售自动交付 |

学会区分“谁在卖、谁在收”，就能理解为什么不同生意会选择不同路线。下面五类业务只是帮助你找到接近自己的情景，不是要你一次记住所有服务商：

1. **国内小店/本地自营网站：** 先判“平台托管结账”还是“自己作为境内商户接支付宝/微信支付等”。支付宝官方电脑网站支付产品适配网站交易；相应产品对网站、商家主体和资质有独立要求，不意味着普通个人收钱码可替代线上经营收单。[S12][S13]
2. **跨境平台卖货：** 先遵守 Amazon 等平台规则，重点比较**平台准许的卖家资金出口**。收款服务商通常只能在平台允许的资金结算环节提供选择，不能自行替换买家结账系统。[S11]
3. **跨境独立站卖实物：** 商家一般自己承担销售责任，需要可受理真实大陆主体的国际收单/支付提供商；Shopify 中国版受邀商户可能另有指定结算路径。[S03][S04]
4. **自营软件或订阅：** 同一个真实销售场景才有资格并列比较“自己收单 + 自担适用税务”与“符合业务准入的 MoR”，权责不同必须计入成本。[S06][S07]
5. **外贸 B2B 大额服务/供货：** 优先看合同、发票/贸易真实性、汇款目的、银行收款与换汇成本；没有必要为了一个企业转账场景购买面向散客的实时卡收银台。

回到最初29美元模板订单：如果放在平台销售，先看平台规定的卖家结算办法；如果继续自己开网站卖，先查你作为真实卖家能不能申请接受国外顾客付款的产品。软件订阅再考虑是否有合格的软件MoR；企业之间的大额服务交易则可能走合同收汇。这里最重要的不是品牌，而是**不同经营方式下到底由谁向顾客卖东西，钱又怎样到卖家**。

### 2.2 Visa、PayPal、Stripe和银行账户分别是做什么的？

还是那笔29美元的模板订单。美国顾客打开付款页，输入银行卡信息。**Visa、Mastercard、银联**是常见的银行卡支付网络，帮助银行卡付款在相关机构间处理；**Stripe**等支付服务商为经过审核的商家提供接受和处理付款的能力，这种服务行业里常叫“商户收单”，也会听到PSP（支付服务商）。

如果顾客选择**PayPal**，它可以是顾客的付款方式，而PayPal也有需要另外核实资格的商户收款产品。**银行账户**则是经营款按允许的路线最终进入的地方：有银行账号，不等于你的网站已经能够接受银行卡付款。支付宝、微信支付也分别有顾客付款工具和商家产品。先记住这三类——**付款工具、商家收款服务、资金最终去处**——下面的网络、平台和MoR只是把这张图补齐。

刚才说的是顾客这边。用更完整的支付合同语言表示，顾客先向实际销售方买东西，再通过收银台把付款交给被允许受理的机构。它不是一张必须背下来的术语图；用来检查顾客究竟付给了谁：

**合同与付款链（顾客看到的一面）：**

`顾客（所在地/币种/付款工具） → 销售合同中的卖方（你/平台/MoR） → 收银台或发票 → 可接受该支付方式的服务商/收单机构 → 成功的交易记录`

再看卖家这边。顾客收到“支付成功”，你却可能仍要等待平台或收款服务商把钱结算出来，再按规定申请转账到银行。**WorldFirst、Wise**等服务提供特定的资金接收、换汇或转出能力，实际用途和可用地区看产品；它们不会因为给了你一个账户号码，就自动替网站完成银行卡收单。

下面这条较完整的路线，可以拿来查“钱现在在哪儿、谁负责把它转到下一站”：

**资金及责任链（卖家真正要用钱的一面）：**

`成功交易 → 结算责任方（平台/PSP/MoR） → 商户可结算余额或供应商应得款 → 允许的提现/汇款路线 → 合规受款账户 → 经营中可支配币种`

如果顾客要求退款，钱可能要从你已收到的款或以后结算的钱里退回。还有一种叫**拒付**的情况：顾客通过发卡银行争议银行卡交易，银行和支付机构按规则处理，可能把交易款倒扣回来。哪一家机构受理争议、谁负担损失、商品或会员权益要不要撤销，都取决于具体合同。完整的反向路线是：

`顾客退款/发卡行争议 → 合同中的处理方 → 账户余额/后续结算款/约定补款 → 商品权益和销售责任`。

目前只要知道“钱不一定只往卖家账户一个方向流”，具体争议处理留到第⑥板块。

| 容易混淆的名称 | 位于模型的哪一层 | 它**不能**自动替代什么 |
|---|---|---|
| Visa / Mastercard / 银联 | 卡品牌与卡支付网络；顾客银行卡的一种基础设施 | 不是独立站商户账户或经营结算账户 |
| 支付宝 / 微信支付 / PayPal | 可以是顾客付款方式；其中支付宝、PayPal 等还经营商家支付产品，**要以具体产品/账户为准** | 顾客有这些钱包，不代表你的商家身份已开通相应跨境产品 |
| Stripe / PayPal 商户产品 / 合规境内收单服务 | 接受和处理顾客付款的服务能力 | 并不自动替你开立任何银行收款账户、批准所有商品 |
| Shopify / Amazon / 淘宝等销售平台 | 商品与订单场景；有的平台提供统一收银台、卖家结算 | 平台的卖家应收款不等于本人银行现款，也不自动等于 MoR |
| Paddle 等软件 MoR | 对其覆盖交易承担名义销售方及相应交易义务 | 不能替代供应商的所有税务与产品责任 |
| WorldFirst / Wise / 银行账户 | 依产品可能承担合法资金接收、结算、换汇、汇款等角色 | 有境外账号 ≠ 可用境外主体注册 Stripe ≠ 能替顾客完成商户收银台支付 |

**进一步看看具体的Shopify产品差异。** 如果同一家大陆企业在Shopify卖实物，顾客银行卡可能经其获批的第三方服务商付款，之后按合同结算到合法账户；Shopify还可能额外收第三方交易费。[S09] 只有真正获得中国版Shopify Payments邀请并通过审核的企业，才可能采用该产品规定的付款安排，结算到**经验证的WorldFirst账户**。[S03][S04] 这两种不是所有商户都可任选的套餐，更不能据此推断大陆个人能开通香港Stripe。

到这里，新手可以先用四个问句核对一条收款路线：**顾客怎样付？谁负责处理付款？钱最后进谁的账户？退款时又找谁？** 如果真实主体、金额币种、合同条件还没核实，就写“尚不确定”，不要因为看见某家服务商的广告或账户注册入口，就认为整条路线可用。

## 3. 我这样的卖家能用哪些收款方案？

### 3.1 我是个人还是公司、卖什么、卖到哪里，会限制能用的方案吗？

会，而且有时直接决定能不能申请。继续用大陆自然人卖模板举例：**顾客在美国能使用某种付款方式，并不等于支付公司允许这位大陆卖家注册商户**；有香港银行账户，也不等于他有香港公司或香港Stripe商户资格。想判断一条路线能否使用，先查三件事：它收不收你的真实经营身份，允不允许你卖这种商品，收进来的款能不能合法进入有权使用的账户。

此外还要查销售合同和买家地区。软件、实物和数字模板可能面对不同规则，借用别人身份或编造地址也不能解决资格问题。下面的矩阵是完整参考表：先看与你最像的一行，不必第一遍把所有经营主体都研究一遍。

| 经营条件 | 值得核验的收款组合 | 应明确排除或保留 UNKNOWN 的部分 |
|---|---|---|
| **大陆自然人，向海外卖自己制作的数字文件** | 若具体 PayPal 中国区账户/产品接受该身份与商品，可评估自己的商家收款；若是符合要求的软件产品，可评估 Paddle MoR；数字内容平台亦可评估其卖家/提现条件 | Stripe 一般自助商户地区清单不含中国大陆；不能用一个 Wise/HK 账户“创造”香港 Stripe 资格；PayPal 账户功能、MoR 个人身份批准与提现均未因注册页面存在就确定。[S01][S02][S06] |
| **大陆个体工商户、境内自营交易** | 与真实经营主体、网站/小程序资质和业务相符的支付宝/微信支付商户产品，或平台原生收银台 | 普通私人转账码不当然具备网站经营收单与对账等能力；跨境产品不能不经审核用于纯境内交易。[S12][S13] |
| **大陆企业，跨境实物独立站** | 真正接受大陆企业、商品与海外客户的第三方支付商；若 Shopify 特定商户获邀，可比较“中国版 Shopify Payments + WorldFirst” | Paddle 以软件为目标、不适用于实物；通用 Stripe 全球商户支持清单并不因 Shopify 中国版存在而自动放开。[S03][S04][S08] |
| **大陆企业，跨境平台经营** | 平台认可的卖家收款/结算方式，例如 Amazon 全球收款或合规指定服务 | 独立站插件、Stripe 收银台不能绕开平台控制的买家结账；平台卖家账户审核仍是前置条件。[S11] |
| **实际运营的香港公司/其他境外公司** | 可按**真实主体所在地及实际运营证据**研究所在地区 Stripe、PayPal 等 | 不能直接挪用大陆个人或大陆公司资格；境外公司也仍有税务、商品、银行和结算限制。[S01][S14] |
| **大陆企业，海外 B2B 合同大额交易** | 真实贸易/服务合同对应的合规银行收汇或被许可的企业跨境资金服务 | 不能把平台卖家钱包当作通用企业电汇账户；银行所需贸易真实性、结售汇或监管要求要以具体业务及银行为准，费率 UNKNOWN |

Stripe 和 PayPal 正好说明为什么要核对到具体产品。Stripe 的[全球商户支持地区](https://stripe.com/global)有香港，未将中国大陆列为一般独立商户的开户地区；已经具备受支持地区商户资格，才谈得上向全球顾客收款。PayPal 在中国大陆有跨境商户服务，但 [S02] 所列公开费用仅适用于按**《PayPal中国跨境支付服务用户协议》及《PayPal全球服务条款》**开立的账户，**不适用于根据另一《PayPal支付服务用户协议》开户的账户**。这类国际商业交易比例费是4.40%，高级在线卡产品还要另行申请批准，不能把这组数字当成所有 PayPal 中国账户的统一报价。[S01][S02]

Shopify Payments 的中国版属于另一种特定产品安排。[S03][S04] 官方目前仍将它列为受邀早期体验，面向符合条件、开展跨境销售的大陆注册企业；商家需要接入并验证 WorldFirst，且不能用来处理面向中国大陆顾客的境内销售。即使公司主体符合描述，是否收到邀请、使用的套餐和实际卡费，仍要在自身店铺中确认。

如果读者此刻只想要一个结论：**不符合真实身份、商品或收款终点要求的，排除；还不知道能不能开户的，先调查；证据齐全后，才算费用。** 上面的矩阵给出了不同身份需要查哪些合同或官方产品，不表示其中任何服务已为某个读者开通。

### 3.2 怎么确认顾客付的钱能合法到账，退款时也有人负责？

还是回到顾客付29美元的场景：付款页面出现“成功”，商家可能只得到一条交易记录，钱并没有进银行。之后还要有机构确认可结算的金额、达到可转出条件，再按规定进入卖家有权使用的账户。**能在网站收款，和钱能合法到银行，是两道不同的检查。** 另外要倒过来想：顾客退款或发卡银行提出交易争议时，谁负责、钱从哪里退回、商品权益怎么处理？

把这些看得见的步骤拆开，就得到下面六个检查节点。它们不是六个新服务商，而是同一笔钱经过的六次核对：

1. **顾客受理：** 本地区顾客实际能用某种方式付款，且该方式在商户合同中可用。
2. **对顾客的销售：** 谁在订单上是卖方？能否销售这一商品和收费模式？退款说明由谁承担？
3. **付款处理：** 是扣款成功、待结算还是预授权？这里不展开支付状态技术机制。
4. **净可结算款：** 支付/平台扣费、可能的退款与预留金之后，哪些金额成为可提余额？余额可能因审核而被限制。
5. **提现通道：** 何种受益人名称、银行地区与币种允许提现？有哪些最低额、频次、固定费与审查？
6. **银行与可用货币：** 到银行后还需何种中转、入账或换汇处理，经营账户能否实际动用？争议时钱可能如何回流？

六步走完后，试着回答一句话：**谁收到了顾客的钱、现在停在哪、什么条件下能转入哪个合法银行账户？** 再问退款时从现有余额还是后续结算里扣款，谁负责取消商品或服务权益。银行费用、实际到账日和账户审批任何一环还没核实，就只能说“估计”或“尚不知道”，不能把商家的计划写成服务商的保证。

拿 PayPal 中国区美元电汇来试算就很清楚。[S05] 提现说明列出大陆银行电汇最低 **US$150**，一般为 **3–7 个工作日**，并提示审核和银行规则可能影响处理。[S02] 对应的**企业 PayPal 账户**费率表列出大陆电汇 **US$35/笔提现**。这些数字能用于条件模拟，个人或企业的真实账户是否获准使用该路径，仍须看审核与受款银行。[S02][S05]

Lemon Squeezy 官方说明可用受支持银行或**已验证的 PayPal 账户**接收卖家款项，结算有持有期和半月周期；其银行提现国家名单未列中国大陆，不能把“支持全球卖家”理解为“中国大陆银行可直接提现”。个人 PayPal 账号是否在其风险/商品审批下实际获准，应记 UNKNOWN。[S10]

到这里可以把查到的路线分成三种，先看中文含义，再看后面的完整判断规则：
- **已验证闭环：** 主体、产品、支付、合同、提现终点已经有足够证据；进入实际费率比较。
- **条件性闭环：** 规则上可能支持，但身份审核、店铺激活、银行/提现授权或费率尚 UNKNOWN；只能进入备选研究，不能当成上线能力。
- **不能闭环：** 出现明确 NO；直接排除，不靠改地址、借账户补救。

## 4. 不同方案的手续费、到账速度和风险怎么比？

### 4.1 一笔订单扣完手续费和提现等费用，到手还能剩多少？

先算最容易理解的一步：顾客付了**29美元**，假设某个**符合下文特定PayPal中国区协议及交易条件的商户**按示范费率扣掉约**1.58美元**，平台上看见的费后金额约**27.42美元**。这时还不能说商家的银行卡到账27.42美元；它可能要继续等结算、满足最低提现额、支付转账或换汇费用。

真正要比不同方案，得把**顾客付的钱、扣完付款处理费的余额、目前能申请转出的金额、银行最后实际收到的金额**分开。我们给这四个数分别起一个简短符号：G、T、A、B。后面才进一步比较不同企业资格、不同平台费用及税务/责任安排；**这些并不是每个大陆个人都能开的收款账户**。

把这四层放进一条路线：**G=顾客付款；T=扣除当笔已知交易费后的余额；A=按结算及余额规则可申请转走的金额；B=真正到达合法银行账户的钱。** 数值不一定相同。先看下面完整对照表，记住“平台显示余额不等于银行实收”就够了；复杂费用以后再加。

| 金额 | 算的是什么 | 常漏掉什么 |
|---|---|---|
| **顾客付款金额 G** | 顾客实际支付的含税/不含税合同总额（应统一税价口径） | 不等于商家应得销售净额 |
| **交易后余额 T** | G − 支付百分比费 − 固定费 − 适用平台交易费 | 款项可能还未结算、尚有风险预留 |
| **可申请提现余额 A** | T − 已确定的平台佣金/调整/退款/预留与其他适用扣项 | 低于最低提现额就不能直接换成银行现金 |
| **银行实际入账 B** | 符合门槛的 A − 本批提现费 − 已知中间行/入账扣费 − 按**实际汇率**计量的换汇影响 | 银行尚未到账、目的币种不明时必须记作 UNKNOWN |

新手到这里先掌握一个判断：**商家后台的金额、可以点提现按钮的金额、银行真正入账的钱，不要直接画等号。** 详细计算时才逐一查平台佣金、每批固定提现费、退款、银行中间行费、换汇实价与税价口径。缺少合同报价时应记录为“尚不知道（UNKNOWN）”，不要硬算出一个看似精确的数字；所谓“免提现费”也不代表换汇免费。

#### 一笔 $29 订单：费率示范，不是跨地区服务商排名

**下面进入深入对比。** 都标着29美元的订单，不代表适用同一类商家。表里同时列出特定中国区PayPal协议商户、真实香港Stripe商户、获准的软件MoR交易，目的只是教你怎么算百分比费和固定费，**不是推荐大陆卖家任选这三家**。如果你只想学初步算法，先看交易后余额；如果你想学选型，务必再核实表格的适用身份、商品和责任。

| 价格结构的例子 | 前提 | 单笔交易费 | 仅扣交易费的余额 |
|---|---|---:|---:|
| PayPal 中国大陆国际商业交易 | **仅**符合 [S02] 指定双协议的 CN 账户，顾客国际 USD 商业付款 | 4.40%×29 + $0.30 = $1.576（例示按美分计 $1.58） | **约 $27.42** |
| Stripe 香港商户 USD 卡交易 | 真正具备 HK 商户资格，卡属于国际卡；无币种兑换 | 3.4%×29 + $0.30 + 0.5%×29 = $1.431（例示 $1.43） | **约 $27.57** |
| Paddle 软件 MoR 标准价 | 受 Paddle 接受的软件商品，由 MoR 销售 | 5%×29 + $0.50 = $1.95 | **$27.05** |

HK Stripe 另可有换汇与争议费用；上述数字均未包括任何平台费、提现费、银行费、消费者税、商品履约/客服成本或退款。[S02][S14][S07]

#### 相同大陆经营主体、同一批订单：PayPal 美元提现如何改变答案

**第一处容易让新手算错的地方是：订单太少时，即使交易已经扣了手续费，钱也未必达到提现门槛。** 仍按一单29美元、约1.58美元支付费的教学数字，六单交易后约164.52美元，刚超过下文这类美元电汇150美元的最低额。若**该账户确实是适用协议的企业账户**、电汇收费为每批35美元，那么扣掉这笔已知费用后、银行其他费用之前，还约129.52美元。这里的35美元**不能用于推断大陆自然人的收费**，所以个人卖模板的案例后面要另外核实自己的真实账户。

下表明确假设**一家符合 [S02] 指定协议、已获准国际美元收款和大陆银行美元电汇的大陆企业商户**，每笔商品和付款都合规，订单全部成功且没有退款、预留或其他扣款。逐单费先按美分取整，余额约27.42美元。PayPal 帮助页给出 **US$150** 最低电汇额，特定企业账户价目表给出 **US$35/批**。真实资格、到账与汇兑仍需分别核实。[S02][S05]

| 一批成功订单数 | 顾客合计支付 | 支付费后可提现前余额* | 达到 $150 门槛？ | 只扣一次 $35 电汇费后的预计银行入账前金额* | 每单摊到的提现费 |
|---:|---:|---:|---|---:|---:|
| 1 | $29 | $27.42 | **否** | **当批无法按该路径提现** | 不适用 |
| 5 | $145 | $137.10 | **否** | **当批无法按该路径提现** | 不适用 |
| 6 | $174 | $164.52 | **是** | **$129.52** | **$5.83** |
| 10 | $290 | $274.20 | **是** | **$239.20** | **$3.50** |
| 100 | $2,900 | $2,742.00 | **是** | **$2,707.00** | **$0.35** |

\* 表格按逐单先四舍五入到美分的简化方法计算，并假定没有预留、退款、拒付或其他余额调整。PayPal 实际逐笔舍入方式与账户可提状态需要另行确认。银行入账与中转费用、结售汇汇率和合法受款条件仍为 **UNKNOWN**；129.52 美元等数字仅表示扣除已知收款与企业电汇费用后的**银行入账前估值**，不能当作实际到账或人民币利润。

理解上面这张表，只需看两行：**五单余额137.10美元，达不到150美元最低提现额；六单余额164.52美元，符合这个金额门槛，但仍不代表银行已经收款。** 批次越多，企业每批35美元的固定费用摊到单笔就越低；一百单仅摊0.35美元。商品销售资格、到账时间、银行和汇兑费仍要核实，个人账户更不能直接用这张企业收费表作保证。

#### 严格同条件选型：大陆商户同一 $29 商品的两种合规收银台

如果你已经看懂一笔钱为何从29美元变成27.42美元，又可能无法马上提现，就可以进一步比较**同一家商户的两种真实合格收款方案**。前面的香港Stripe和软件MoR只是收费结构示例，不能直接与大陆企业合同互换。下面把经营主体、商品、客群都固定下来，只改变一件事：同一家大陆商家获准使用的PayPal收款能力是否包含另一种在线卡付款产品。后者仍需另外批准。

| 比较维度 | A：合格账户的 PayPal 国际商业收款 | B：获批的在线卡付款高级版 |
|---|---|---|
| 主体与价格 | 同一个真实大陆商户、同样 $29 | 完全相同 |
| 付款覆盖 | 适用于其获准的 PayPal 商业交易能力 | 须进一步获得在线卡付款批准；覆盖银行卡客群 |
| 交易费（示范） | $29×4.40% + $0.30 ≈ $1.58 | $29×4.10% + $0.30 ≈ $1.49 |
| 单笔费差 | 基线 | B 少约 **$0.09/单**（未含可选服务/风险附加价） |
| 提现与资金终点 | 若采用相同被认可的美元电汇路径，仍需满足门槛、$35 每批 | 同样；不能因为 B 交易费低就省略提现成本 |
| 决定主用的条件 | PayPal 顾客覆盖对销售更重要或 B 未获批 | B **确实获批**且更多目标顾客要直接使用银行卡，附加服务费等核实后有优势 |

读这张表不必立刻选择B。**少9美分只有在B真的获批、支付方式适合顾客、附加费用没有抵消好处时才有意义。** 两种付款方式也可能服务不同顾客，值得同时保留。若尚无同一客群的真实付款数据，就只能得到“值得调查”，而不是“立即切换主力渠道”的结论。

同样的比较方式也适用于 Shopify 实物独立站。把经营主体固定为同一家大陆企业，店铺和29美元订单不变：路径 A 由已经获准的第三方服务商收单，还可能支付 Shopify 另收的第三方交易费；路径 B 必须等企业**真实收到中国版 Shopify Payments 邀请、完成 WorldFirst 验证**才存在。获得商户实价以后，两种路线才能代入下面的费用式。

- A 的净资金基数 = $29 − 第三方支付费 − Shopify 第三方交易费 − 适用货币费与该路线摊销提现费；
- B 的净资金基数 = $29 − 中国版 Shopify Payments **该计划实际卡费** − WorldFirst 后续实际收费/汇兑 − 该路线摊销提现费。

官方规定 Shopify 第三方交易费可能**另加在**第三方支付费之上；使用 Shopify Payments 作为唯一提供商时相应第三方交易费不收，但两条实际卡费、商户差异化费率、币种和 WorldFirst 结算报价尚须核验，**本例不给出虚构单笔净额**。[S03][S04][S09] 如该 Shopify 套餐实际第三方费率为 (t)，这层成本在单笔 $29 商品上是 **$29×t**；例如 (t)=2% 仅作为数学敏感性示例，就是 **$0.58/单**，**并非断言该大陆店铺当前实际被收 2%**。取得双方账户实价后再填入两式，辅以退款/通过率和到账期限确定胜出者。

#### 相同经营者的软件业务：为何 MoR 价格不能只与 PSP 抽成相比

**复杂一些的对比是：为什么支付费便宜，不一定代表整笔生意更省钱。** 假设同一家大陆企业已经获准两条路线，面向同一海外市场每月卖29美元的软件。自己作为卖方收款时，可能要负责更多消费者付款、退款和间接税事务；如果由软件MoR在其覆盖交易里成为卖方，部分事务按合同改由MoR承担。这时比较的就不是“两张收费价目表”而是两种销售关系。按前述公开标准，PayPal示例每单约1.58美元，Paddle约1.95美元；十单Paddle初步应得基数约270.50美元，但还要等待按月结算及最低100美元支付门槛，部分转账方式可能另有15美元SWIFT费用。符合条件的**企业PayPal美元电汇路径**扣除两层已知费用后约239.20美元；其他银行、税务、汇兑及商品准入仍待核实。[S07][S15]

比处理费更深入一步，还要追问：**谁是交易的法律卖方？消费者税和争议谁处理？供应商到手款还要经历哪些结算？** 因此270.50和239.20美元不能直接宣称前者赚得更多；必须把买家含税价、适用税务责任、银行实际款和经营工作量放在同一口径比较。Paddle也不保证接受设计模板或课程等任意数字商品。[S06][S08]

### 4.2 除了手续费，还要比较哪些会影响成交和到账的因素？

只比手续费，就像买一个看起来便宜却让顾客付不了款的收银台。对上面的29美元订单，先回答四件事：**美国顾客习不习惯这种付款方式？钱何时真正能用于下一笔经营支出？退款或银行卡争议会不会占用余额？主渠道暂停时，还有没有独立的办法继续接单？** 只有同一客群真实尝试过的付款记录，才能比较通过率；不该拿全球支持国家的数量猜自家转化率。

- **付款覆盖/成交损失：** 美国客户能否用习惯的银行卡、PayPal 或钱包，是否必须跳转？只有同一客群的**真实支付尝试和有效订单**才可比较转化率，不可把全球支持“195+ 国”视作该店铺成功率。
- **现金时间成本：** 实物卖家可能要先付采购和物流款，资金预留、提现门槛与结算等待会影响下一次备货。记录交易发生日、可申请提现日和预计银行可用日，逐项核对，别只填一个“到账快”。
- **预期争议/退款占用：** 比较渠道规则、可能不返还的初始支付费、争议费和举证负担，未有商户数据时将发生率标 UNKNOWN，不用拍脑袋给风险费率。[S02]
- **中断与迁移成本：** 一个支付商停止服务能否改用另一独立受理方？同一账户换银行不算完整备用；MoR 迁移订阅付款凭据、平台换销售渠道，都可能不是即时切换。

例如，两家同样合法可用的支付服务，面对同样的100次付款意向。如果A最终比B多完成3笔29美元订单，它就多产生**87美元销售额（3×29）**。这是解释“顾客能不能顺利付款也值钱”的假设，不是实际测得的支付成功率；扣完货款成本、税、退款等费用后，新增利润可能远低于87美元。

最后把这些条件落到同一批订单里：顾客总付款、支付费、平台佣金、最低提现额和每批固定费、预计可用日期，以及退款和争议假设。银行费、汇兑报价与获客方式若有差别，也要分别列出。重要项目没有数据就写 UNKNOWN；关键资格或成本还没查清时，暂时保留候选，比依据不完整报价宣布胜出更可靠。

## 5. 到底该怎样选定主用的收款方案？

### 5.1 怎么从真正能用的方案里选主用和备用？

现在回到开头的四步路线，按你的一笔订单填答案：卖什么、卖给谁？哪条收款办法确实接受这种经营身份和商品？扣完手续费与转出成本后，钱是否能在需要的日期合法到账？如果主用服务停了，能不能独立接下一笔订单？

只有每一项都核实为“能够使用”的收款方案，才可能成为主用；备用也必须自己能接顾客付款并依法结算。**同一个支付账户只换一张提现银行卡，不能算独立备用。** 接下来把这四问细化成四轮判断，然后用两种经营者的完整例子再检验一次。

**第1轮，定销售合同与成交渠道。** 订单发生在平台、自有网站，还是对公合同？由此决定研究平台卖家结算、自己商户收单、软件 MoR 或 B2B 银行收汇。换销售模式也会换获客成本和责任，不能只减几笔手续费就作结论。

**第2轮，把不能用的路线排掉。** 按第3节核对实际主体、商品和目标顾客、销售责任及最终合法受款账户。NO 立即排除；还没获批的 UNKNOWN 只能留下来继续查。

**第3轮，算同一批订单什么时候能真正用钱。** 除付款手续费，还要填 Shopify 等平台附加费、提现次数、时间和本月采购需求。退款率、银行费和汇兑费查不出来就写 UNKNOWN；碰到小幅费差，优先满足业务最不能拖的条件。

**第4轮，准备真正能独立收钱的备用。** 主用渠道应能证明资格及资金去向。备用服务商也要能独立受理核心顾客、履行退款责任并合法结算。换银行卡、同一 PayPal 账户换香港受款银行，或者同一平台再开一家店，都不足以替代独立收单方。

如果上面的四轮仍显得抽象，就看两位经营者为什么会得出不同结果。第一位是**大陆自然人**：自建站卖29美元原创设计模板，每月可能只有五单，连最低提现门槛都可能成问题；第二位是**大陆企业**：卖29美元实物，每月约100单，约14天就要付下一批货款。下面按这些已声明的假设演练，不虚构任何一家支付公司已经批准他们开户或提现。

#### 演练 A：大陆自然人向海外卖数字产品，单价 $29

先看第一位：他在自己的网站面向美国顾客卖原创设计模板，顾客付款后下载，每份29美元，不是订阅。他是大陆自然人，没有实际经营的境外公司，刚开店每月只有5单，未来可能增加到100单。**此刻最先问的不是Stripe和PayPal哪个好，而是有没有接受其真实经营身份、允许卖模板、最终能把钱合法转入其账户的方案。** 没查到真实批准结果之前，下面的服务商都只能按条件分析。

在自有网站出售模板，他就是需要向买家负责的卖家，必须找到接受其真实主体的商户收单产品。若搬到数字商品平台销售，谁作为卖家、退款由谁处理、款怎样结算，都要看平台合同。**Paddle 这类软件 MoR 不保证接收设计模板**；“数字商品”四个字并不能替代产品类别审核。

| 候选与判定 | 准入/责任 | 资金闭环 | 决策 |
|---|---|---|---|
| 自己开户使用“香港 Stripe” | 大陆个人没有相应真实香港商户主体；HK 银行账号不改变资格 | 无合法已证实的商户开户前提 | **NO，排除** |
| Paddle 软件 MoR | 本例是设计模板，不是典型的软件/SaaS；官方主要针对软件，不是全部数字品 | 即使销售品类变为软件，也须验证卖家审批及收款账户 | **本例不作为主选；若以后改为软件产品才重新核验** |
| 按适用中国区协议经营的 PayPal 商户收款 | 须证明自然人/实际业务能使用所需的商户产品、商品符合规则，按真实身份审核 | 若账户确实允许以个人名义将经营款合法美元电汇至合规大陆银行，需要核验 $150 最低额与**本人真实费率**；$35/次来自特定企业账户，不能照搬，个人实际资格 UNKNOWN | **条件主选 P1：先核实个人商户能力和提款合法性** |
| 可销售原创模板的**数字商品平台** | 需核验该平台对数字模板、个人卖家身份、消费者交易与退款责任的具体合同 | 检查是否能真实提现到本人认可账户、最低额与平台佣金；本轮没有核验某个具体平台全链 | **备用方向 P2：找到具备已证实卖家资质和提现的具体平台才成立** |

**每月只有五单时，到账门槛比差几毛手续费更紧迫。** 在“该个人确实符合[S02]特定PayPal协议和相应交易条件”的前提下，按29美元、4.40%加0.30美元的示例收款费，五单费后约137.10美元，仍不足[S05]所示的150美元电汇最低额。如果他本月就要拿钱，不能把这条美元电汇路线当作唯一已经可运行的主力。要继续调查是否有允许本人卖模板、能合法较低门槛提款的数字商品平台或其他合格服务；否则应坦白写“尚未证明本月能拿到钱”。

**单量增长到一百单时，固定提现费的影响可能明显变小，但商户资格不会因为订单多而自动放宽。** 若适用前述示例收费，一百单支付费后约2742美元。只有对于符合规定的**企业账户**，沿每批35美元的对应企业美元电汇路径，扣费后银行其他费用之前才是约2707美元，单笔摊0.35美元；这个数字**绝不能套给本例的大陆自然人**。他仍要拿自己的协议、账户审批及提款费用重新计算，再考虑买家是否更愿意刷卡，以及是否有真正独立的备用。

这份参考案例的判断因而带有前提。本人首先需要核实适用的合法经营身份、商户协议和设计模板面向美国顾客销售的准入，再向银行确认同名账户可接收的经营款种类、限额与费用。月5单且本月急需经营现金，还得比较数字商品平台是否有更低的合法提现门槛。**PayPal 商户路线只是资格成立后的拟主用方向，数字商品平台只是待证实的备用方向；两者均未经过真实批准或支付验证。**

#### 演练 B：大陆公司向海外卖实物，$29/单，月 100 单

再看第二位：一家有真实经营与供货资料的大陆企业，向美国顾客卖29美元实物，每月约100单，**约14天后就需要资金采购和支付物流**。它可能把商品放在Amazon等平台，也可能开Shopify自营店。两条路线的第一道区别仍是“谁决定买家的付款页面”；第二道区别才是“钱什么时候结算到公司”。

在 Amazon 成交，平台依据合同安排买家结账并向卖家结算；Shopify 自营站通常由公司向顾客销售并承担售后，还需要合格的收单服务。平台佣金、获客成本和运营工作随销售渠道一同变化，不能只拿 Amazon 的最终结算和 Shopify 的支付费率作简单减法。

**路线1，在 Amazon 等跨境市场平台成交。** 先沿用**平台统一收银台和平台允许的卖家收款方式**。Amazon 有“全球收款”产品，可让符合条件的大陆卖家以人民币取得符合规则的跨境结算款。[S11] 真正要比较的，是同一批**平台净结算款**经不同允许出口到银行后，哪条换汇、入账时间和费用更适合14天采购期。真实账户获批及账期必须另查。若平台结算赶不上采购时间，需要安排周转资金，换一个独立站支付插件不会改变 Amazon 的卖家结算规则。

**路线2，在 Shopify 品牌独立站成交。** 这家公司卖实物，Paddle 软件 MoR 不适用；有大陆企业资格也不能因此直接按照香港主体申请通用 Stripe 商户。留下两种值得核验的收单路径，比较对象始终是同一家公司、同一29美元商品及同一批美国消费者订单。

| 同一大陆公司、同一 Shopify 订单 | 第三方被批准收单路径 A | 中国版 Shopify Payments 路径 B |
|---|---|---|
| **开通条件** | 必须有支持大陆公司、实物、美国买家及该店铺的**具体第三方提供商**；通过实际商户审核 | 必须**获得受邀资格**、符合跨境销售条件，完成 WorldFirst 验证 |
| **顾客结账** | 支付服务商允许的卡/钱包，实际支持由合同决定 | 官方说明 Visa/Mastercard、若符合条件的加速钱包；不支持对大陆消费者的境内销售 |
| **费用结构** | 该提供商处理费 + Shopify 可能收的第三方交易费 + 资金汇兑/转出费 | Shopify Payments 该店铺/套餐的实际交易费 + WorldFirst/银行后续费用与汇兑；不能把香港 Stripe 公价代入 |
| **资金终点** | 经该提供商认可并核实的企业提现/结算账户 | **指定经验证的 WorldFirst 账户**→允许的企业用途账户 |
| **到账和业务风险** | 第三方账户审核与预留、Shopify 额外费、平台依赖 | 受邀资格、WorldFirst 结算规则、付款方法与退款责任 |
| **可作主线的时点** | 收款产品及完整资金闭环都通过审核，能满足备货现金要求 | 真实收到邀请并验证成功、实价和资金周期符合业务要求后 |

**如果企业没有收到中国版 Shopify Payments 邀请**，B 直接记 NO。先找确实接受大陆企业、美国顾客及该实物品类的第三方收单 A，作为**拟主用**；尚未找到并通过审核之前，A 仍是 UNKNOWN，不能宣布独立站已具备收款能力。

**如果已经收到邀请且 WorldFirst 验证通过**，才把 B 加进来。固定这100单订单，比较 A/B 的真实交易费、Shopify 额外费用、实际汇兑及退款条件，关键还要看两条路线能否在14天内形成可用经营资金。如果现有 A 已稳定运营，B 可以先作为符合条件的备用，不能为尚未核实的费差贸然停掉 A。任何一条超过现金周转期限，即使交易费较低，也不当主用。

**备用要能单独接受付款。** 在 Shopify 中找另一家真正接受这家大陆企业、这一实物品类，并有独立合法提现路径的支付服务商，才能在主要收单方停用时继续接订单。WorldFirst 结算账户与卡收单产品分处不同环节；另外经营 Amazon 能分散销售渠道，但不能立即代替 Shopify 站内收银台。

这家企业的结论不应是一句“推荐Shopify Payments”或“推荐第三方”。先确认有没有收到中国版Shopify Payments邀请、WorldFirst是否通过要求；再查哪家第三方真正接受该公司卖这类实物，费用、风险和退款条款分别是什么；最后看哪条资金路线能合法满足14天备货需要。**还没拿到批准和真实费用，就不能把条件候选写成已能收钱。** 这也是经营已有订单的卖家需要判断的事：什么时候值得迁移现有渠道，什么时候更应该保留已经验证能用的路线。

#### 其余三类常见生意的直接决策结果

| 业务 | 先选哪一类模式 | 何时换路线 |
|---|---|---|
| **大陆国内到店/网站卖货** | 在平台成交→平台原生收款；自营网站→真实境内主体符合资质的国内收单产品（支付宝/微信支付等），按线上与线下产品区分 | 当开始跨境经营，重新审核跨境产品，不套用本地收钱码资格 |
| **全球 SaaS $29/月** | 先比“符合主体资格的自收单”与“经审核的软件 MoR”：前者保留对消费者销售与税务责任，后者把覆盖交易中的部分销售/间接税运营交由 MoR | 如果无资格申请直接国际卡收单、各地间接税义务负担大且 MoR 已批准，优先 MoR；如果已经有合规收单能力、相应税务运营能力且综合费用明显低，则自收单可优先；资金结算仍需核验 |
| **企业对企业 $5,000 真实服务订单** | 以真实合同/发票为基础，与企业银行和合规跨境收款提供商确认可接受的对公收汇；比较中转行费、汇率与结算资料 | 若订单变成高频散客即时购买，才比较卡收单与在线收银台；银行实际入账费及外汇处理逐笔向银行确认，不可照搬消费级卡费 |

无论你卖什么，读完这一章，都应该能给自己写出一段不需要专业名词的判断：**我卖【什么】给【哪里的谁】；我作为【什么经营身份】销售；我查过【哪条渠道】是否允许我收；一单扣费后约余【多少】，银行实际能拿到多少/何时能拿到还缺【哪些条件】；备用方案【是否真正独立】。** 然后再去查商户合同中的销售方、付款方式、退款责任和合法账户。如果这些关键项还是UNKNOWN，就写“尚未证明存在能运行、能合法到账的方案”，不能用别人的批准或公开费率替代自己的证据。
