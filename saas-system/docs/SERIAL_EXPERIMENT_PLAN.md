# SaaS System Lab — 三模板串行实验计划（2026-10-17）

## 定义与冻结顺序

业务目标：快速获得能反复适配新产品的公开前台、用户 Dashboard、**真实 Admin**、Stripe 订阅与一次性支付、可用的客户裂变和奖励处理。**Docker 不是硬门槛**，部署总步骤/是否需要外部账号/成本/资源和维护复杂度才是指标。

**严格顺序：** `01 Velobase Harness` → `02 Open SaaS` → `03 Wave`。前一实验的 Gate 和 Reviewer 结论才允许决定下一实验如何进入。即使第一个足够好，也先记录结论；是否跳过剩余候选由 Owner 决定，不默认变更清单。

| 序号 | 上游仓库 | 现有证据带来的优势 | 已知缺口与风险 | 预期演示方式 |
| --- | --- | --- | --- | --- |
| 01 | [velobase/velobase-harness](https://github.com/velobase/velobase-harness) | Stripe、额度账本、Affiliate 佣金、真实用户/Admin 页面；`compose.demo.yml` 全栈演示 | 规则硬编码；部分退款处理与事件失败重试风险；演示环境非生产；资源消耗未知 | 优先选择最轻量、可隔离的本地演示（Docker Compose 或 Node+pnpm） |
| 02 | [wasp-lang/open-saas](https://github.com/wasp-lang/open-saas) | Stripe、订阅、Admin 页面、基础额度、更新较活跃、MIT | 无原生免费营销裂变；依赖 Wasp；官方云部署需评估账户与成本 | Wasp 本地运行或经 Owner 同意的 Railway/Fly.io 私有环境 |
| 03 | [thedevdojo/wave](https://github.com/thedevdojo/wave) | Laravel、Filament Admin、Stripe/Paddle、套餐与权限、MIT | 无免费裂变；额度按产品扩展；Stripe Webhook 去重缓存可能影响重试 | Laravel Herd/原生 PHP 开发环境，必要时单独设计容器 |

## 三组实验采用相同判分问题

| 维度 | 具体检查 | 最小可接受结果 |
| --- | --- | --- |
| **快速使用** | 依赖/账号/命令数量、首次打开时间、冷启动内存、持久化与关闭方式 | 私有场景可重复运行，明确资源、费用与失败恢复 |
| **前台和后台** | 公开产品页、真实注册登录、独立用户 Dashboard、平台 Admin 的管理读写权限 | 4 类页面均能操作；安全负例拦截非管理员 |
| **Stripe** | 免费核心源码，TEST Checkout、Webhook 签名、订单/订阅状态、幂等与重放 | TEST 单笔链路吻合；失败/伪签名不误交付；无 Live 交易 |
| **裂变** | 链接/推荐关系、首单、续费、计佣/积分、全额和部分退款撤销、失败重试、报表 | 免费实现与缺口逐项定性；不能把静态源码当成功能 PASS |
| **奖励** | 现金佣金（含结算）、SaaS 积分、调用次数、会员时间分别验证 | 不支持就标需开发；自动银行/Connect 打款未经审查不执行 |
| **多项目复用** | 关闭原业务、改换演示 SKU/权益，不侵入通用支付与账户 | 记录改造文件数、插件授权、升级冲突、代码复杂度 |
| **运维/安全** | 私网暴露、端口/数据/卷/秘钥隔离、备份/恢复、资源/性能及依赖 | 不触碰其他项目，不开启公网演示管理员 |

**闸门**：必须先通过只读预检才能提出运行 Gate。需要真实 TEST 交易、任何支付/退款或激活 Provider 时，后续单独定义对象、环境、最大次数、金额、签名、脱敏证据、补偿/恢复和 Owner 权限边界。

## 决策分层

1. **先确认模板身份**：能够复用代码开发新 SaaS；非 ERP/商城/纯推广 SaaS 成品。
2. **区分“可查看、可支付、可自动奖励”**：四类页面齐全且可用，比只有 README 宣传更重要。
3. **免费内置优先**：原生功能 → 已验证的兼容免费插件/SDK → 小范围 Codex 集成 → 商业服务（须 Owner 批准费用）；不默认购买插件、迁移项目或重造架构。
4. **风险排序**：真实资金/退款/权益错误 > 对外泄漏/认证 > 现成能力缺失 > 部署麻烦 > Stars。任何支付和奖励不一致时不得生产上线。
5. 统一呈现结论：`PASS / PARTIAL / UNVERIFIED / BLOCKED / NOT_APPLICABLE`，注明来源是源码静查、OWNER_REPORTED、本机 DIRECT_READBACK 还是实测 BEHAVIORALLY_VERIFIED；问题与修复估计（小/中/大）分栏记录。
