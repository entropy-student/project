# 项目立项书：Birthday Magazine Studio（生日纪念杂志）

立项日期：2026-09-26  
项目状态：Discovery / Validation pending  
Owner：用户（商业目标、市场、价格和风险决策）  
Reviewer / Executor：按阶段任务指定；尚未进入开发执行

## 1. 一句话目标

让用户上传照片、回答几道关于寿星的问题，就能得到一本可预览、可购买的个性化生日纪念杂志；目标是替用户完成构思和排版，而不是要求用户学会 Canva。

## 2. 用户与问题假设

### 初始用户假设

首轮聚焦“正在为重要朋友或家人准备生日礼物，但不擅长/没有时间设计”的送礼者。这个细分尚未验证，首发国家、年龄层、语言与购买触发点待确认。

### 待验证的问题假设

- 用户想送一份比普通礼品更私人、有故事感的生日礼物。
- 用户手上已有照片和回忆，但整理成完整成品很费时。
- Canva、相册、贺卡或普通礼物要么需要自己设计，要么缺少完整杂志叙事。
- 用户愿意为“代整理、代写/编辑、代排版、可按时送达”付费。

这些是假设，不应直接当成广告事实或已证明的市场需求。

## 3. 价值主张与产品体验

核心表达假设：**把你们的照片和回忆，变成一份可以送出去的生日杂志；不用从空白画布开始。**

期望流程：

1. 选择主题、页数、语言和电子版/实体版选项；
2. 上传照片，并填写关于寿星、关系、共同回忆、语气等问答；
3. 系统将素材整理成封面、人物简介、故事页、祝福/问答页等版式；
4. 生成可浏览的逐页预览，用户确认后提交最终制作；
5. 用户下单支付；
6. 已支付订单自动取得电子 PDF；实体版由经验证的供应链印刷并寄送。

首版后台允许人工或 AI 辅助生成和质检。对用户而言仍应是清晰的提交—预览—付款/确认—交付流程。未经样品和履约验证前，不承诺“全自动”“几分钟完成”或特定到货时效。

## 4. 范围与非目标

### 项目最终能力范围

- 移动端友好的产品页和购买说明；
- 图片上传与问卷；
- 每个订单的素材与成品关联；
- 可分享/可保护的成品预览，确认或修改反馈；
- 商品选项、购物车、支付、订单通知；
- 逐单电子版生成并在付款后安全授权下载；
- 实体版的印刷、寄送、状态追踪和异常处理；
- 照片、故事文本和订单数据的权限、保留、删除说明。

### 第一阶段 MVP 建议边界

- 先以人工/AI 辅助制作验证完整样品和小规模付费订单；
- 先实现最短可用的问卷、照片收集、预览确认、支付和成品交付；
- 若先卖电子版，用 WooCommerce 下载权限发放逐单生成 PDF；逐单文件生成和授权衔接仍需实现/验证；
- 实体版自动印刷寄送作为后续阶段，不能仅因某插件有“Photobook”或“Print-on-demand”标签就视作已完成。

### 明确不在本项目当前范围

- 家族食谱整理成书（另一个独立产品假设）；
- 通用 Canva 替代品或开放式拖拽设计器；
- 首轮即自建大型 AI 编辑系统；
- 在需求和经济性未验证前投放规模化广告；
- 未经确认擅自决定市场、语言、价格、供应商或支付网关。

## 5. 成功标准

### G1 需求验证通过后

- 完成至少一轮目标用户问题访谈/直接需求采样，记录具体场景、触发点、现有替代、异议与反例；
- 有一个可供评估的真实样刊与清晰 Offer；
- 测量从看到样例、深入了解、开始提交素材、进入结账到真实交易的证据；
- Owner 在实验开始前写定样本来源、投入上限和 KEEP / ITERATE / KILL 条件。单个付款只证明至少一次交易成立。

### 可销售 MVP 的验收

- 买家可以在移动端提交必填问答和多张照片，上传资料能与订单准确关联；
- 买家知道价格、预计工期、预览/修改规则、隐私处理和退款边界；
- 每单成品能经质量检查；预览内容与最终文件一致；
- 测试订单完成“支付成功 → 下载/交付授权 → 邮件通知”闭环，未支付订单不能取得文件；
- 失败订单可由运营人员定位、补发或退款，不会丢失素材/订单关系；
- 实体版需另行通过纸张规格、样书、成本、送货区域、地址数据交接、到货时间和异常订单验证。

## 6. 阶段门

| Gate | 要回答的问题 | 通过后允许做什么 |
|---|---|---|
| G0 项目记录 | 目标、范围、现状和未知项是否被记录？ | 进入问题证据收集。本次立项完成 |
| G1 Problem / Offer Evidence | 谁在什么场景有这个问题？什么 Offer 能产生真实购买行为？ | 制作/补足 MVP 方案 |
| G2 Solution Proof | 输入照片与问答能否稳定产出令人满意的完整样刊？工时和失败率是多少？ | 批准最小网站/生产流程实现 |
| G3 Paid MVP | 购买、生产、预览、支付和逐单交付是否可闭环？ | 小批量真实交易 |
| G4 Repeatability + Economics | 在不同买家/订单里能否重复交付，扣除制作、印刷、运费、支付与退款后经济性如何？ | Owner 决定继续、调整或扩大 |
| G5 Scale | 多次重复证据及经济性达到预先约定门槛了吗？ | 才考虑增加预算、自动化和渠道 |

每个 Gate 要有当前事实、证据链接、风险、Reviewer 结论和 Owner 决策。不能用“页面已经做好”替代需求或交易证据。

## 7. 方案候选与实施原则

当前候选为 WordPress + WooCommerce + 免费主题/起步站点。WooCommerce 适合承接商品、订单、支付网关接口与下载品交付；Blocksy/Kadence 等主题只能加快站点外观搭建，不能自动生成个性化杂志。上传、预览、生成、单订单下载授权及实体履约需单独 PoC。

在主题、付费服务和插件定案前，应先把首发国家、交付品类、数据流和供应链约束写清楚。只安装完成当前已验证流程所需要的插件，避免插件重叠。

详细能力矩阵和第三方数据流见 [WordPress 模板与插件候选](./WORDPRESS_STACK_RESEARCH.md)。

## 8. 主要风险与缓解方向

| 风险 | 影响 | 验证/缓解方向 |
|---|---|---|
| 需求只是“觉得有意思”，不转为购买 | 做出网站后没有真实收入 | 在开发前测试 Offer、样刊与真实付款/付费预约 |
| 生日截止日期强，制作或运输延误 | 礼物错过场景，退款与信任受损 | 先用人工流程测实际交付时长，设缓冲，不先承诺不可证明的 SLA |
| 个性化内容质量不稳定 | 买家不满意，反复修改导致人工成本高 | 限定问卷输入和版式，建立人工质检与明确修改轮次 |
| 上传照片涉及个人/第三方隐私 | 信任、数据处理和合规风险 | 说明使用范围、保留/删除规则、访问权限和云服务数据路径 |
| 产品图看起来比最终印刷品好 | 退货/投诉 | 使用真实样书和实际打印色彩/裁切校样，不只依赖浏览器预览 |
| 打印插件依赖外部服务或费用不透明 | 成本、服务连续性、发货地域不确定 | 在小规模承诺前向供应商确认计费、地址流转、产地、运输区域和交期 |
| 支付方式受商户国家限制 | 用户不能结账 | 首发市场确定后再选择和测试支付网关 |
| 运营工时吃掉毛利 | 成交越多亏损越大 | 记录每单素材处理、编辑、客服、打印、运费、退款和支付费用 |

## 9. 当前未决事项

- 首发市场、页面语言和对应支付/税务环境；
- 目标送礼关系/细分人群；
- 电子版与实体版的先后；
- Offer 和价格带、实验投入上限、通过/停止阈值；
- 首版手工/AI 辅助程度与承诺交期；
- 最终 WordPress 主题、上传/版面编辑方案和印刷服务。

Owner 可以在下一阶段开始前集中决定首发范围；在此之前不应将候选技术路线当作实施授权。
