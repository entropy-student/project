## 当前最大瓶颈

**Problem Evidence + Solution Proof。** 目前既没有足够买家原话证明问题优先级，也没有最终成品样品证明“把照片和回忆变成完整生日杂志”的方案确实达到预期。

当前不把“先做完整 WordPress 网站”作为默认增长动作。若样刊尚不可展示，先做出一份真实感足够的示例产品。

## Lite Experiment：样刊 + 单页 Offer 的购买意愿验证

### 初始假设

对于正在准备朋友/家人生日礼物的送礼者，展示一本基于照片和问答生成的个性化杂志，能让他们更愿意购买或提交素材，而不只是表示“好看”。

### 最小实验设计

- Audience / Situation：首发人群与市场由 Owner 在实验前确定；从最近有生日送礼场景的人群开始，不假设某个国家或社媒渠道天然最优。
- Message / Creative：使用一份接近真实交付的完整样刊和实际流程图，突出“代整理、代编辑、代排版”。
- Offer：明确示例页数、输入要求、电子版/实体版、价格或付费预约、修改范围、制作/送达时间及取消/退款规则。
- Channel：先选择一个低成本且能触达目标送礼场景的渠道；记录来源。是否直接外联/内容/小额广告由 Owner 在实验预算内选择。
- Conversion Path：样刊页 → 了解输入与交期 → 加入候补/开始下单 → 真实付款或付费预约。
- Trust：说明样刊是否为演示、用户照片如何处理、什么情况下不能按时交付，展示真实成品证据（制作完成后）。

一次实验优先只改变一个核心变量。不要同时换受众、报价、文案和渠道，否则难以归因。

## 记录模板

```text
当前瓶颈：
原因假设：
本轮只改变的核心 Lever：
样本/渠道/起止时间：
核心行为指标：
Owner 预先写定的成功标准：
Owner 预先写定的 Kill 条件：
真实结果与异常：
用户原话/反例：
Decision：KEEP / ITERATE / KILL / SCALE
```

核心指标应优先覆盖高意向行为与交易（例如合格买家进入结账、真实付费预约或订单），并记录每单承诺交付成本。实验前 Owner 需要确定样本量、预算上限、测试价格与成功/停止阈值；当前资料不足，不预填假精确的百分比门槛。

## 决策规则

- **KEEP**：出现可信正向行为，继续验证同一个细分/Offer；不代表可扩大投入。
- **ITERATE**：人群仍有证据，但核心信息、信任、流程或 Offer 某一项需调整。
- **KILL**：按预设条件未观察到足够购买行为，且访谈与行为证据不支持继续当前组合。
- **SCALE**：交易可在独立用户/时间批次中重复，交付成功，且贡献利润、退款和获客成本达到 Owner 预先确定的门槛后才考虑。
