# 获客与验证计划：Birthday Magazine Studio

依据：[Acquisition Growth Radar](https://github.com/entropy-student/spike.skill/tree/main/acquisition-growth-radar)。采用 Evidence → Bottleneck → Lever → Experiment → Decision，不把公开线索包装成市场验证。

## 当前阶段

**G1：美国英语市场公开桌面研究完成；本项目真实访谈与交易尚未开始。** Owner 于 2026-09-26 选定美国市场和电子 PDF 首轮试点。研究来源和局限见 [G1 桌面调研](./G1_DESK_RESEARCH.md)。

## Validation Spine

| 证据层 | 状态 | 结论 |
|---|---|---|
| Problem Evidence | 公开线索有 | 有相近商品和顾客评价；DIY 单封面/自助照片书是替代。买家首要痛点仍未访谈确认 |
| Solution Proof | 竞品可参考 | 有人工设计、客户预览和 POD 履约流程；本项目 PDF 样刊、输入到成品流程尚未验证 |
| Attention / Interest / Intent | 未测 | 无本项目流量、回复、资料提交、加购或结账数据 |
| Transaction | 未测 | 本项目没有真实付款或付费试点 |
| Repeatability / Economics | 未知 | 无逐单工时、制作/支付成本、返工、退款、CAC 或贡献利润 |

竞品价格和评论只用于定义试验，不等于本项目需求或单位经济成立。

## 当前瓶颈

首轮市场和试点交付形式已定：**美国英语、电子 PDF**。当前瓶颈是证明目标买家愿意为代整理故事/照片与确认预览支付，并确认 PDF 样刊制作与实际交付可控。

实体 POD 自动化是后续路线风险。Lulu 有 WooCommerce POD 集成，但需验证每一单的个性化文件传递；这不阻挡先以人工/AI 辅助的 PDF 试点验证买家行为。

## 首轮 Lever 与 Offer 假设

- 单一 Lever：Offer / Message。
- 定位假设：**“Turn their photos and memories into a birthday magazine. We handle the story structure and layout, then send you a digital proof to approve before delivering the final PDF.”**
- 目标人群：美国、最近一年确实为朋友或家人准备过生日礼物的人。访谈先问实际行为，再展示样刊。
- 交付：首轮测试一个英文 PDF 产品；售价、页数、交期、修改范围和退改条款仍需锁定。
- 完整操作脚本、建议样本与判断门槛见 [美国首轮实验方案](./G1_US_FIRST_EXPERIMENT.md)。

## Lite Experiment 顺序

1. **Problem Evidence**：做 8–12 个合格美国送礼者的一对一访谈（建议定性样本，不用于推算总体比例），先问最近一次生日送礼的真实过程、选择和花费；不先讲产品。
2. **Solution Proof**：制作 1 本可展示的英文 PDF 样刊，检查预览、姓名/照片准确性、导出质量与交付方式。
3. **Transaction**：由 Owner 先选定公开价、投入上限和决策门槛；再向符合条件的买家展示同一个 PDF Offer，使用真实付款和实际交付。询问“喜欢吗”不算交易。
4. **Decision**：区分 attention、interest、intent、transaction；报告样本、来源、原话、实付订单、制作时间、支付成本与异常。一笔订单只证明发生过一次交易，不代表 PMF 或可重复获客。

建议的第一轮判断：成功信号应包含至少一位非亲友买家按公开价格实际付款并收到可接受 PDF；随后还需重复实验才能讨论可重复性。无订单时先看合格曝光、报价、开始结账等漏斗行为，按证据只改一个变量，不能仅凭小样本直接宣告失败。Owner 需在对外招募前确认预算与停止阈值。

## 当前决策

**继续 G1；首测区域和交付形式已定为美国英语 + 电子 PDF。** 下一步是做 PDF 样刊、锁定售价与预算，再访谈并运行一次真实付费试点；暂不进入完整建站、实体 POD 自动化或扩量。
