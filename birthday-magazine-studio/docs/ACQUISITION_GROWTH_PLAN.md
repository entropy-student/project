依据：[Acquisition Growth Radar](https://github.com/entropy-student/spike.skill/tree/main/acquisition-growth-radar)。采用 Evidence → Bottleneck → Lever → Experiment → Decision，不把公开线索包装成市场验证。

## 当前阶段

**G1：US/UK English 市场公开调研部分完成；本项目真实访谈与交易尚未开始。** Owner 已确认英语市场研究范围。完整来源和限制见 [G1 桌面调研](./G1_DESK_RESEARCH.md)。

## Validation Spine

| 证据层 | 状态 | 结论 |
|---|---|---|
| Problem Evidence | 部分公开线索 | 有同类商品和已交付评价；DIY 免费/低价模板也是活跃替代。目标买家的首要痛点未通过访谈确认 |
| Solution Proof | 竞品可参考 | 人工代设计、自动生成、客户预览等竞品流程存在；本项目输入到成品样刊未做 |
| Attention / Interest / Intent | 未测 | 没有本项目样刊流量、回复、预约、素材提交或加购数据 |
| Transaction | 未测 | 本项目无真实付款或付费试点 |
| Repeatability / Economics | 未知 | 无逐单工时、印刷/邮寄成本、返工率、退款、CAC 或贡献利润 |

竞品的 review/sales 只能说明相关商家发生过订单，不能证明我们的 Offer 或经营经济性成立。

## 当前瓶颈

一是 US/UK 中尚未选定单个测试区；二是还没证明买家会为“代整理故事与照片”支付比低价 DIY 模板/自助编辑器更多的钱。个性化产品的姓名、照片、确认稿和最终成品必须一致，也是客户信任和返工成本风险。

暂不把全站开发作为获客动作。先做采访和一个可评审样刊/Offer。

## Lite Experiment：先采访，再测试一个 Offer

### A. 访谈实际送礼行为

- 市场：Owner 已选 US/UK English 范围；开始实验前须定一个国家。
- 人群：最近为朋友或家人准备过生日礼物的人；不要只采访设计师或创业者。
- 询问：最近一次真实购买、为何选择/放弃照片礼物、DIY 时间、照片/故事素材收集、预算、截止日期和交付方式。
- 展示样刊前先问过往行为，避免受概念引导；样刊展示后记录具体异议与愿意采取的下一步。
- 访谈和公开评论区的赞美都不记为 Intent 或 Transaction。

### B. 展示单一 Offer，观察真实行为

待检验的定位假设：**“把你的照片和回忆整理成生日杂志；我们负责内容结构与排版，你确认预览后再定稿。”**

实验前需选定国家、实体/电子形式、价格、页数、交期、素材要求、修改范围和付费 CTA。一次只测一个主要 Lever；真实付款/付费预约为 Transaction。Owner 需提前写定样本/预算上限及 KEEP / ITERATE / KILL 门槛。

| 记录 | 预先定义 |
|---|---|
| 当前瓶颈 / 原因假设 | 依据访谈更新 |
| 本轮唯一 Lever | 市场、人群、Message、Offer、Trust、价格、流程或 Channel 之一 |
| 核心行为指标 | 真实订单/付款；同时记录访问、回复、开始提交、加购和弃单 |
| 成功 / Kill 条件 | Owner 在测试前决定，不根据结果倒改门槛 |
| 结果与决策 | 记录样本、原话、订单、交付成本和异常；KEEP / ITERATE / KILL |
