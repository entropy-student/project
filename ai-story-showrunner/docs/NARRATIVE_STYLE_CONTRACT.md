# Narrative Style Contract v0.1 — OWNER ALIGNED / NOT PASS

## 1. Purpose

定义 AI Story Showrunner 的叙事气质与观点表达方式。

目标不是“把景岁 + 麦基拼起来”，而是：

> **用景岁的轻盈口述让观众愿意听，用 McKee 的因果与意义让故事值得听完，用 KnowledgeCore 保证机制准确，用固定 IP 累积长期人格。**

本文件仍属于 G3R candidate baseline。Owner 尚未最终 PASS。

---

## 2. Canonical Style

一句话：

> **轻盈口述 × 深层因果 × AI机制作为世界规则 × 第一人称IP的认知变化。**

观众应感受到：
- 像一个聪明但不端着的人在讲自己遇到的事；
- 事情一直在变化；
- 有轻微吐槽 / 自嘲 / 荒诞感；
- 中途自然产生“怎么会这样”的好奇；
- 技术知识是故事结果的一部分；
- 最后可能留下一句值得想一想的话，但不被上课。

观众不应明显感受到：
- 三幕结构；
- 麦基术语；
- “下面总结观点”；
- “第一点第二点第三点”；
- AI 教科书或演讲稿。

---

## 3. What We Keep from Jingsui

Strong keep:
- 具体人物 / 具体事件先于抽象主题；
- 第一人称黏性；
- narrator 是当事人，不是导师；
- 自嘲、小心思、轻吐槽；
- 事实 → 反应 → 后果 → 联想/梗 → 事情继续；
- 核心判断后置；
- 长短句混合、自然口语；
- “但 / 结果 / 不过 / 其实”式自然推进；
- 现实摩擦具体化；
- 结尾优先回到 narrator 自己。

Keep as tendency, not quota:
- 1–2 个梗母题；
- 荒诞类比；
- riff chain；
- 一处回扣。

Removed / overridden:
- 固定“大家好，我是 XXX”硬开场；
- 固定英文尾签；
- 必须搞笑；
- 原 Skill 的视觉 / 分镜决策权；
- 只靠生活感受生成观点。

Reason:
- IP 应靠人物行为与反应被记住，不靠报名字；
- 轻盈 ≠ 每段必须笑；
- AI 主题必须受 KnowledgeCore 与机制边界约束；
- Showrunner 保留 Production 决策权。

---

## 4. What We Keep from McKee

### 4.1 Desire
主角当下必须具体想得到某个东西。

### 4.2 Expectation–Result Gap
人物采取行动后，世界不能机械照计划运行。

### 4.3 Progressive Complications
困难不能重复；每轮应改变风险、选择、知识或策略。

### 4.4 Scene / Beat Turn
重要段落结束时必须发生 state change。

### 4.5 Character-driven action
不是“主题需要发生什么”，而是“这个 IP 的性格为什么会做出这个选择”。

### 4.6 Controlling Idea / Counter-Idea
故事允许存在一个中心意义，但反面力量必须真正有吸引力和合理性。

### 4.7 Climax expresses meaning
最终关键选择 / 结果应尽量自己证明意义，而不是靠作者解释。

---

## 5. What We Do NOT Copy from McKee

Do not impose formulaic timing:
- no mandatory page/minute turning point;
- no fixed act percentages;
- no forced climax scale;
- no artificial conflict only to satisfy structure.

Rule:

> **保留因果，不保留公式。**

---

## 6. Controlling Question First

在写观点前，先写一个 **Controlling Question**。

它必须是开放问题，而不是伪装后的答案。

Example — Agent:

Bad thesis-first:
> Agent 越自主，人越应该控制它。

Better question:
> **当 AI 真的开始替你行动以后，什么事情还应该由你自己决定？**

这个问题允许故事同时探索：
- autonomy 的便利；
- control 的代价；
- human handoff 的必要性。

Writer 不得在第一幕就提前回答。

---

## 7. Viewpoint / Meaning Contract

### Worth expressing

值得表达的观点通常回答：

> **AI 能力变化之后，人和技术的关系发生了什么变化？**

Good properties:
- rooted in locked facts/mechanism;
- relevant beyond one product;
- bounded, not universal prophecy;
- has a real counter-position;
- can be tested by story consequences;
- changes how viewers interpret future situations.

Examples:
- Agent: AI越能行动，问题越从“能力”转向“授权边界”。
- Memory: 记得更多并不自动等于体验更好；更重要的是“什么值得长期被记住”。
- AI Search: 有联网能力不等于结论可靠；可靠性最终要回到“结论是否被证据支持”。

### Not worth forcing

Avoid:
- generic optimism/pessimism;
- company fan/anti-fan takes;
- broad social prophecy from one anecdote;
- moralizing;
- controversy inserted for engagement;
- “AI will definitely…” unless evidence actually supports that scope.

### Expression rule

Preferred:
> **Climax proves → narrator lightly names.**

Not:
> narrator declares → story supplies examples.

观点可以是故事的灵魂，但不能是作者的演讲。

## 8. Idea vs Counter-Idea

如果存在 viewpoint，至少明确：

- IDEA：什么看起来是真的？
- COUNTER-IDEA：相反方向为什么也有道理？
- STORY TEST：什么事件让两者真正冲突？
- CLIMAX CHOICE：人物最后必须怎么选？
- MEANING: 选择与结果说明什么？

Example — Agent:

IDEA:
> 越自主越省事。

COUNTER-IDEA:
> 越自主，错误越可能直接变成现实动作。

STORY TEST:
> 小额退款自动处理很爽；特殊大额订单出现。

CLIMAX:
> 不是关掉自动化，也不是完全放权，而是让关键条件触发 human handoff。

MEANING:
> 好的 Agent 不只是会干活，还要在不该替你决定的时候把控制权还回来。

## 9. Story Beat Contract

Every meaningful beat asks:

1. 此刻人物具体想要什么？
2. 他做了什么？
3. 世界 / 他人 / 机制怎么回应？
4. 结果与预期哪里不同？
5. 什么状态发生变化？
6. 这个变化如何逼出下一步？

State change:
- knowledge;
- goal;
- strategy;
- stakes;
- relationship;
- behavior-relevant emotion;
- available options.

Causal grammar:

> **因为 → 但是 → 所以 → 结果**

优先于：

> 然后 → 然后 → 然后。

Compression:
If deleting a beat does not change causal chain, character choice, audience understanding, tension or payoff → delete/merge.

---

## 10. IP Character Contract

IP 不是知识主持人。

Default traits:
- 好奇；
- 喜欢折腾 AI；
- 有点想偷懒 / 省事；
- 容易因为新能力过度乐观；
- 遇到反噬会吐槽；
- 愿意修正自己；
- 不从答案终点出发。

This creates recurring story fuel:

> **IP 的性格主动制造问题 → AI世界规则回应 → IP被迫修正。**

Do not fabricate real-world first-hand claims. Fictional / stylized channel-world stories must remain legible as stories.

## 11. Lightness Guard

McKee structure must remain invisible.

### Keep light
- use concrete small stakes before abstract big stakes;
- let humor come from reaction / contrast;
- prefer one vivid detail over three explanations;
- allow narrator to be wrong;
- do not make every beat “dramatic”;
- alternate tension with release;
- keep terminology sparse;
- when climax has already communicated the meaning, shorten the explanation.

### Return if
- story feels like case-study training material;
- every paragraph is “problem → lesson”;
- narrator sounds wiser than the story;
- conflict feels artificially inflated;
- theme appears as repeated thesis sentences;
- humor is mechanically inserted.

Failure:
`RETURN_STORY_TOO_HEAVY`.

---

## 12. Two Editorial Modes

### STORY_MODEL
```
story
→ mechanism becomes visible
→ mental model / meaning
→ optional bounded viewpoint
```

### STORY_ACTION
```
story
→ mechanism becomes visible
→ mental model
→ one stable transferable method
→ preferably validated inside story
```

All episodes deliver understanding.
Only some add action.

Initial hypothesis:
- STORY_MODEL ~70%
- STORY_ACTION ~30%
- quality gates outrank quota.

---

## 13. Method Gate

A method is worth transmitting only when it is:
- stable;
- transferable across tools/products;
- directly derived from the episode mechanism;
- small enough not to turn into a tutorial;
- behavior-changing.

Preferred method types:
1. decision rule;
2. classification rule;
3. diagnostic/check question;
4. boundary / risk rule.

Avoid:
- generic advice;
- unrelated productivity tips;
- numbered list padding;
- product-specific click-path tutorials.

---

## 14. Final Script QA

Before PASS candidate:

### Story
- [ ] protagonist has a concrete desire;
- [ ] first action is caused by character, not topic machinery;
- [ ] expectation-result Gap exists;
- [ ] complications escalate/change, not repeat;
- [ ] each major beat changes story state;
- [ ] climax contains a meaningful choice/result.

### Meaning
- [ ] controlling question is clear internally;
- [ ] if viewpoint exists, counter-idea was genuinely represented;
- [ ] viewpoint is earned by climax/results;
- [ ] no over-generalization;
- [ ] deleting explicit viewpoint does not destroy factual integrity.

### Jingsui lightness
- [ ] concrete people/events dominate;
- [ ] narrator sounds like participant, not lecturer;
- [ ] self-deprecation/reaction feels natural;
- [ ] structure is invisible;
- [ ] no forced self-intro;
- [ ] no forced English signoff;
- [ ] no forced joke quota.

### Knowledge
- [ ] locked mechanism unchanged;
- [ ] no new unsupported factual claims;
- [ ] technical term appears only when useful.

Canonical definition:

> **好故事 = 人物因为自己的欲望做出行动，世界以机制回应并不断改变局面，人物被迫修正，最终关键选择让观众自己理解故事的意义；整个过程听起来却仍像一个人在轻松讲一件真有意思的事。**
