# Evergreen Bank v0.2.1 — Human-world-first + AI mechanism reserve

> 这些不是待发布标题，而是“可继续加工的人类问题”。进入正式选题前仍需 TopicOpportunity + Duplicate Gate。

## 0. Canonical use

本文件现在有两层供给，二者都只是 **seed bank**，不是 ready-to-publish topic：

1. **Human-world Bank** — 默认优先。从大家原本关心的 X 与 Human Process 出发；
2. **AI Mechanism Reserve** — 保留原 v0.1 的 40 个 AI 使用问题，作为强 AI 题 / fallback / mechanism supply。

默认生成链路：

```text
X Domain
→ Human Process Family
→ Observed Paradox
→ WHY
→ Human Tension
→ Meaning Fingerprint
→ AI Changed Process
→ Mechanism
→ Story
```

禁止直接从 X 名称或 Meaning 名称生成标题。每个 candidate 仍必须走 Evidence / Human Relevance / Mechanism Integrity / One Mechanism / Storyability / Non-trivial Payoff / Audience Fit / D1–D5。

### Domain × Process seed map

| X Domain | Example Human Processes | Candidate WHY direction |
|---|---|---|
| 美食 | 形成口味 / 学做饭 / 家庭传承 / 聚餐 / 身体感知 / 评价 / 探店 / 创新 | 推荐越准为何偏好反而变窄；标准化为何仍复刻不了家传味道；AI 指导为何不等于学会 |
| 恋爱 / 关系 | 表达 / 冲突 / 匹配 / 信任 / 记忆 / 安慰 / 分手 | 沟通越正确为何越不像自己；没有争吵是否等于关系更好；被理解是否替代真实暴露 |
| MBTI / 身份 | 自我理解 / 改变 / 社交判断 / 职业探索 / 自我优化 | 标签何时从理解变成定义；过去画像会不会限制未来选择 |
| 工作 | 新人成长 / 决策 / 委派 / 创意 / 日程 / 知识积累 | 初级任务被 AI 拿走后如何形成专业判断；最优建议出错时谁负责 |
| 娱乐 / 游戏 | 推荐 / 追更 / NPC / 攻略 / 二创 / 共同文化 | 个性化是否削弱共同体验；永远迎合的 NPC 还是不是“他者” |
| 学习 | 做题 / 写作 / 搜索 / 复习 / 反馈 / 自测 | 即时答案如何影响 productive struggle；解释得懂是否等于自己会做 |
| 购物 / 消费 | 搜索 / 比较 / 预算 / 自动购买 / 评价 / 退换 | AI 替你筛选后选择责任如何变化；最优购买是否减少自我判断 |
| 旅行 | 规划 / 闲逛 / 文化理解 / 导航 / 决策 | 行程越完美为何越像任务；翻译掉陌生感后还剩多少发现 |
| 社交媒体 | 推荐 / 发布 / 评论 / 形象管理 / 注意力 | 越相关的内容为何越难停止；AI 代写后表达还是不是自己的 |
| 家庭 / 生活 | 记忆 / 家务 / 照顾 / 仪式 / 自动补货 | 事情都被自动做好以后，关心与参与会不会发生变化 |

### Seed generation rule

同一 X 生成候选时，优先 **先换 Human Process，再换故事表面**。

例如“美食”至少应跨：
`taste formation / skill learning / family transmission / social coordination / bodily sensing / evaluation / restaurant discovery / innovation / grocery planning / culture-authenticity`。

如果连续候选只有 X 不同、Meaning Fingerprint 相同：
`RETURN_TOPIC_MEANING_DUPLICATE`。

## AI Mechanism Reserve — preserved v0.1 bank


## A. Felt-but-unexplained｜已经遇到，但不知道为什么

1. 为什么 AI 刚才还记得你，换个任务却像第一次认识你？
2. 为什么 AI 搜到了正确网页，最后仍然可能答错？
3. 为什么和 AI 聊得越久，有时反而越容易跑偏？
4. 为什么同一句 Prompt，AI 每次回答都可能不一样？
5. 为什么 AI 明明说得特别自信，事实却可能是错的？
6. 为什么给 AI 更多资料，有时答案反而更差？
7. 为什么 AI 能看懂一张图，却可能看漏一个很小的关键细节？
8. 为什么 AI 会记住你的偏好，却不一定记得某次聊天的原话？

## B. Expectation Violation｜和普通人的直觉不一样

9. 为什么模型更大，不代表你每个任务都会做得更好？
10. 为什么 AI 会写代码，却不代表它能把整个项目真正跑起来？
11. 为什么 AI 知道“该怎么做”，却不能自动替你做？
12. 为什么 AI 有工具，也不代表它应该拥有所有权限？
13. 为什么让多个 AI 一起干活，不一定比一个 AI 更强？
14. 为什么 AI 接入更多工具后，反而可能更容易出错？
15. 为什么 AI 自动化有时会让你增加一堆新的维护工作？

## C. Delegation / Control｜什么时候该把事情交出去

16. 哪些工作适合直接交给 Agent，哪些必须让人确认？
17. AI 发邮件、退款、改文件之前，哪一步应该停下来问你？
18. 为什么真正有用的 Agent 不应该“什么都自己决定”？
19. AI 替你操作电脑和 AI 给你操作建议，本质差在哪里？
20. 如果 Agent 做错了，错误到底来自模型、工具还是权限设计？

## D. Tools / Connection / Knowledge

21. 为什么 AI 每接一个新软件都要重新适配？
22. MCP 到底解决了什么，而不是“又一个新名词”？
23. API、MCP、插件看起来都在连接工具，它们到底差在哪一层？
24. 为什么 AI 有搜索能力以后仍然需要 RAG / 知识库？
25. 为什么给 AI 一整个文件夹，不等于它真的理解了你的资料？
26. AI 是怎么决定“这次该查资料还是直接回答”的？

## E. Training / Model Behavior

27. AI 到底是在背答案，还是在现场生成答案？
28. Fine-tuning 为什么不是“把所有资料塞进模型脑子里”？
29. 为什么模型训练结束以后还能通过工具学到新信息？
30. 为什么一个模型可以会很多知识，却不知道今天刚发生的事？
31. AI 为什么会产生幻觉，而不是老老实实说不知道？

## F. AI Work / Social Change

32. 当 AI 能自己连续工作几小时甚至几天以后，真正变化的是什么？
33. 为什么现在越来越多 AI 产品从“聊天框”变成“任务执行器”？
34. AI 开始替人做研究以后，人的工作会先减少哪一部分？
35. 为什么公司真正难的不是买一个更强模型，而是把它接进现有流程？
36. AI 帮你省下执行时间之后，会不会把新的工作变成“审核 AI”？

## G. Risk / Trust / Safety

37. 为什么 Agent 跑错一个目标，比聊天机器人答错一句话严重得多？
38. 为什么 AI 的权限越大，越需要明确“什么时候停下来”？
39. 为什么“AI自己发现错误并停下”不能替代安全边界？
40. AI 生成内容里，哪些错误最容易被人忽略？

## Supply conclusion

仅首轮机制地图就能形成 40 个可加工的人类问题；每个问题还可以被新热点重新激活。

因此长期供给不应依赖“还有多少 AI 名词没讲”，而应依赖：

`mechanism families × human problems × new signals × audience feedback`。

这个池未来由真实评论、搜索和发布表现持续扩展，而不是一次性写死。
