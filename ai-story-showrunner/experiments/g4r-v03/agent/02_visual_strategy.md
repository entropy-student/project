# Agent Case — v0.3 Episode / Sequence Visual Strategy

> Experimental. Not canonical.

## 1. Primary Visual Engine

PRIMARY:
`ACTION_REACTION`

SECONDARY:
- `OBJECT_LED`
- `CONTRAST_COMPARISON`
- local `MONTAGE`

Reason:
This episode is fundamentally about control passing between IP and AI through concrete actions, not about an abstract diagram.

---

## 2. World / Scene System

Use one coherent small-shop back-office world with three stable functional zones:

### ZONE_A — IP desk
- owner seat;
- personal mouse;
- inbox/refund queue;
- later approval windows.

### ZONE_B — AI work station
- AI partner processes orders/tools;
- visible but not futuristic;
- same world, not hologram space.

### ZONE_C — shared decision station / threshold
- final refund/confirmation surface;
- where irreversible action is committed;
- visually becomes the “handoff boundary”.

This solves the old same-desk problem without random scene changes.

Rule:
The room remains spatially stable. Story change comes from **who occupies which zone, who holds the mouse/control, and where work stops**.

---

## 3. Motifs

### Motif A — Mouse / confirmation control
Progression:
```text
IP clicks everything
→ IP removes hand from mouse
→ AI executes
→ IP grabs control back
→ AI returns only the mouse
→ final system stops before the mouse/decision
```

Meaning:
Who owns the final action?

### Motif B — Threshold / handoff
Not a literal diagram.

Progression:
```text
work stays with IP
→ work crosses to AI
→ AI crosses too far
→ IP builds an approval wall
→ boundary is redesigned
→ AI stops at boundary and calls IP
```

---

## 4. Dominant Visual Components

### A. Spatial ownership
Who is physically closest to the decision station?

### B. Frame density
- refund overload = cluttered;
- successful autonomy = cleaner/open;
- approval overcorrection = maximum clutter;
- final boundary design = simplified.

### C. Shot scale
- wider for workflow/control geography;
- closer only at meaningful reversal/reaction/object state.

Do not strongly vary color, line, shape and camera angle simultaneously.

---

## 5. Sequence Visual Intensity Arc

| Sequence | Intensity | Visual Character |
|---|---|---|
| S1 repetitive refund | MEDIUM | clutter, repeated hand/mouse actions |
| S2 plan returned | MEDIUM-LOW comic | cleaner frames, object joke |
| S3 autonomy works | LOW → MEDIUM | open composition, IP physically relaxes |
| S4 wrong refund | HIGH → PEAK | tighter frames, UI/object inserts, compressed space |
| S5 all approvals | HIGH comic overload | maximum frame density, repeated windows |
| S6 redesigned boundary | RELEASE → MEDIUM | cleaner spatial logic, clear handoff |

---

## 7. Camera / Staging Baseline

Default:
- eye-level;
- medium / medium-wide;
- stable screen direction.

Use closer framing only for:
- “回复客户” reaction;
- large amount discovery;
- “已退款”;
- “谁让你点确认了”;
- mouse payoff;
- final accepted handoff.

Use wide/full when:
- showing workflow ownership;
- comparing IP/AI positions;
- approval clutter;
- showing boundary redesign.

---

## 8. Anti-PPT constraints

Never visualize Agent as:
`LLM → Tool → Workflow → Agent`

Instead show:
- AI physically carrying work forward;
- tool use as story action;
- stop/handoff as character blocking;
- UI only when UI state itself changes story.

---

## 9. Episode visual thesis

> **这条片的视觉核心不是“AI 有哪些能力”，而是“控制权在谁手里、工作推进到哪一步、什么时候应该停”。**
