# MCP Case — v0.3 Episode / Sequence Visual Strategy

> Experimental. Not canonical.

## 1. Visual Engine
PRIMARY: REPEATED_FRICTION
SECONDARY: OBJECT_LED / CONTRAST_COMPARISON / local MONTAGE

核心不是“协议架构”，而是：一个很聪明的 AI 员工在不同部门门口不断被本地规则卡住。

## 2. World / Scene System

使用同一家公司世界，不把每个系统画成完全随机风格。

### HUB — 中央办公区
- IP 与 AI 的共同工作区；
- 用于派任务、反应、复盘。

### HALL — 部门走廊
- 库存、财务、合同、客服等门口都在同一走廊逻辑里；
- 门大小、墙体、光线相对统一；
- 差异集中在：门把手、入口装置、本地规则牌、表单/ID 要求。

### DEPARTMENT INTERIOR
- 仅在任务确实需要进入时出现；
- 不是每个部门都单独发展成新世界。

### STANDARDIZED FRONT DOOR STATE
- 后半段仍是原来的部门；
- 只是在门口新增统一格式的服务牌/入口描述；
- 不能让观众误以为所有系统内部都变成一样。

## 3. Motifs

### Motif A — 门把手 / 入口
进程：
陌生入口 → IP 手把手教 → 换部门又陌生 → 多种荒谬门把手 → 标准化门口说明 → AI 自己读牌进入

Meaning:
底层系统不同，但 AI 不应每次都从零学“怎么见面”。

### Motif B — 入职手册
进程：
第一份培训纸 → 第二份 → 一摞 → 新软件又来一本 → 最后整摞手册被放下。

Meaning:
重复集成成本。

## 4. Dominant Visual Components
- repetition / variation：同一种摩擦在不同部门重复；
- prop accumulation：入职手册越来越多；
- spatial predictability：同一走廊结构中，本地入口差异越来越明显。

## 5. Visual Intensity Arc
S1 第一次培训：MEDIUM
S2 摩擦重复：MEDIUM → HIGH
S3 部门方言：HIGH_COMIC
S4 全部培训：HIGH → PEAK_COMIC
S5 标准化见面方式：RELEASE → MEDIUM
S6 MCP 命名与回扣：LOW → RELEASE

## 6. Image-relation Grammar
S1: CONTINUITY
S2: MONTAGE + CONTINUITY
S3: PARALLEL + MONTAGE
S4: MONTAGE + CONTRAST
S5: CONTINUITY + CONTRAST
S6: CONTINUITY + CALLBACK

## 7. Framing Strategy
- 部门走廊与门口规则主要用 medium-wide / wide，让空间关系能被看见；
- “门把手在哪？”用 object/reaction close；
- 大量部门规则不要做成四张 PPT 卡片，而是尽量并置在同一走廊环境；
- 标准化服务牌只有在它本身改变行为时才给 insert。

## 8. Anti-PPT constraints
禁止主视觉：
AI → MCP → Tools → API 的框图。

优先：
任务 → 门口摩擦 → 培训 → 再换门 → 重复 → 统一牌子 → AI 自己发现/使用。

## 9. Knowledge boundary
- 不把 MCP 画成权限系统；
- 不暗示 MCP 替代底层 API / auth / business rule；
- 不把所有部门功能画成一样；
- 标准化的是对外见面/发现/调用协议层。

## 10. Visual Thesis
这条片真正要让观众看到：聪明员工并不等于会自然进入每个系统；标准化的是“怎么见面和办事”，不是把所有系统变成一个系统。
