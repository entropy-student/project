# Context / Memory Case — v0.3 Dramatic Hierarchy

> Experimental rerun under G4 Director Language Rules v0.3.
> Old G4 shotbooks are not used as a design source.

## Sequence 1 — 我为什么讨厌重复交代
Start: IP 不断重复同一类偏好。
End: IP 形成明确欲望：说过一次，AI 以后就应该记得。

Scene 1.1:
- 相同偏好反复出现；
- 重复次数让“需求”变成摩擦；
- IP 产生欲望：别让我说第二遍。
Turn: 问题被定义成“记不住”。

## Sequence 2 — 大桌子看起来像记忆
Start: IP 把“眼前能放很多东西”误认为“记性好”。
End: 当前任务连续成功强化了这个错误模型。

Scene 2.1:
- 建立有限工作桌；
- 当前资料摆上去；
- AI 能回答刚才价格；
- AI 能找回当前文档变化。

Scene 2.2:
- IP 因连续成功产生错误信心；
- 形成策略：桌子还能继续加大。
Turn: 更多当前材料被误诊成更强记忆。

## Sequence 3 — 桌子越来越大，但仍然会满
Start: IP 相信扩容能解决问题。
End: 系统开始整理/压缩/移走旧材料，IP 却仍归因于桌子不够大。

Scene 3.1 — 扩建与堆积:
- 今天资料加入；
- 昨天讨论加入；
- 更旧版本加入；
- 工位变得荒谬巨大。

Scene 3.2 — 容量压力:
- 新资料继续进入；
- 旧页被移开；
- 长讨论被压成摘要；
- 重复要求被合并；
- IP 阻止材料被收走；
- AI 反问“你说哪一个？”；
- IP 自己也不确定。

Scene 3.3 — 错误升级:
- IP 看见重要内容确实曾在桌上；
- 它只是被新内容挤走；
- IP 错误结论：桌子还不够大；
- 继续扩桌、会议桌、地板。
Turn: 当前工作区被扩到荒谬极限，但“以后还能不能找回来”仍未解决。

## Sequence 4 — 新任务把误区一刀切开
Start: IP 认为超级大桌子已经接近解决方案。
End: 新任务暴露当前上下文和跨任务记忆不是一回事。

Scene 4.1 — 空桌:
- 新任务开始；
- 当前桌面干干净净；
- IP 说“按我喜欢的方式来”；
- AI 问“你喜欢什么方式？”

Scene 4.2 — 认知转折:
- IP 看空桌；
- 再看上周超级工位；
- 区分“现在能放多少”与“以后还能找回什么”。
Turn: 容量与持久找回被分离。

## Sequence 5 — 不再买桌子，开始留下值得记的东西
Start: IP 放弃无限扩桌。
End: 新任务里 AI 能主动找回长期偏好。

Scene 5.1 — 长期笔记:
- 桌边出现独立笔记；
- 不是什么都记；
- 只选择长期复用偏好；
- 三个具体偏好写入。

Scene 5.2 — 新任务检验:
- 又一个新任务，桌面仍然是新的；
- IP 说“还是按以前的方式”；
- AI 去翻长期笔记；
- 找回“不喜欢 PPT 风”等偏好；
- IP 不用说第二遍。
Turn: 真正解决问题的是选择性保存 + 以后检索。

## Sequence 6 — Context 和 Memory 正式命名
Start: 观众已经通过故事形成直觉。
End: 获得准确、边界清晰的 mental model。

Scene 6.1:
- 桌子 = 当前工作；
- 笔记 = 以后找回；
- Context 术语出现；
- 当前材料在工作台直接使用；
- 拥挤时需要管理/整理/压缩。

Scene 6.2:
- Memory 不把全部历史永久铺在桌面；
- 保存/提炼/检索值得留下的内容；
- 需要时把相关东西重新带回当前工作区。

Scene 6.3:
- 上下文更长不等于永久记忆更强；
- 但更大的桌子对复杂当前任务仍有价值；
- 最终 payoff：桌子再大还是桌子；真正减少重复的是以后还能把重要内容找回来。
