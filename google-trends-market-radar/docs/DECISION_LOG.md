# DECISION_LOG — Google Trends Market Radar

> 与 `REVIEWER_HANDOFF.md` 区分：此文件记录选择原因和历史边界，不担任当前状态的第二来源。

## 2026-10-15 — 采用 SerpApi MCP 作为采集工具

- **原因**：此前直接访问 Google Trends Explore 遇到代理/限流问题，无法拿到可信的历史时间序列。
- **结果**：完成代理连通性、协议和账户免费额度核验后，在已授权的受限查询内拿到真实历史数值与日期。
- **限制**：技术能取数据 ≠ 存在长期需求增长；正式生产查询额度始终受 Owner 单独授权约束。

## 2026-10-15 — G3 校准后偏向合适密度的12个月周序列

- **原因**：生日杂志等窄词90天日度序列大量日期为0，不能用热度零值直接代表没有市场。
- **结果**：三类词的12个月每周序列可用于**有条件的进一步研究**。
- **保留**：仅有周数据密度并不能证明增长；窗口首末是否完整、归一化和重复采样均需要独立处理。

## 2026-10-15 — G4A PASS，同时认定缓存不等于采样稳定

- **原因**：尽管三词重新请求共六次，Search ID、首次时间与数值均复用；没有取得相互独立的 Google 新样本。
- **结果**：正式接受 G4A 的热点发现、范围控制与缓存审计；不把数值完全相同包装为独立稳定性验证。
- **保留**：45条短期热点（41个独立关键词）作为线索池；不能直接拿它们给商品排序。

## 2026-10-15 — 新建独立项目目录与 GitHub Handoff

- **原因**：`entropy-student/project` 先前没有 Google Trends / SerpApi 的独立项目入口；避免该研究散落在聊天和别的业务项目下。
- **决定**：采用 `google-trends-market-radar/`，当前事实唯一权威文件为 `REVIEWER_HANDOFF.md`，历史执行证据追加在 `EXECUTION_EVIDENCE.md`。
- **边界**：GitHub 同步是脱敏管理记录；它不能替代 Owner Windows 主机的接受记录持久化，也不授权新的 G4B 执行。
