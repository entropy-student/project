# 正式运营与频道品牌草案

日期 2026-10-23。旧品牌/短样片建议已被Owner后续纠正，当前以 FORMAT_REVISION_20261023.md、更新后的章程/G2/提示词为准。“再看一幕”及旧灰色画框视觉是被否决的历史方案，不继续应用。以下未冲突的运营问题保留参考，不代表品牌已确认。

## 品牌与表达

优先候选“再看一幕”，便于覆盖电影、剧集与单场戏，强调重看后的新理解。另有“镜里有话”和“画面有话”。确定后才检查各平台重名/相近名、搜索混淆、名称/图形权利与域名可用性，不作可注册保证。

简介草案保存于 brand/channel-copy.txt，已应用 Human Writing 主技能和短文规则，并运行 check_prose.py，通过硬禁项检查。实际试片旁白仍须重新调用技能，不能以频道简介检查替代。

头像为原创几何标记，两层画框表示重看，一处琥珀色观察点强调值得注意的位置。不使用演员脸、电影海报或原片画面。SVG 为可缩放源文件；PNG 1024 与 48px 用于预览。小尺寸只保留图形，圆裁切要保留边距。字体展示使用本机微软雅黑作概念图，不意味着已冻结可打包分发的商业品牌字体；正式交付选有明确授权的字体。

色板为深灰 #171B20、暖白 #F1E9DA、琥珀 #E9AA53。颜色用于节目外壳与证据标注，不对原片统一套色。主标注每个时刻只指一个观察点；字幕清楚优先，避免像密码破译或玄学侦探界面。

## 统一片头片尾

推荐原创二维图形动效，利用画框叠合、短暂回看、观察点和文字，避免以他人影视片段作常驻品牌资产。固定图形/音色/短音标，多期替换场景不改变标记语法。

片头先用当期真实问题或原速片段吸引观看，再插入 1.5 至 2 秒标识；短版允许只出现角标。不在每期开始播放很长的品牌介绍。静态关键画面见 brand/brand-direction.png，未制作动画。

片尾建议 3 至 5 秒。最后的关键帧先恢复到不标注的状态，留一个与当期证据相关的开放问题，再出现标识和讨论/时间轴入口。不要每期生硬重复同一段总结。平台如需要结束卡，单独按其最新规格适配。

备选为带克制胶片质感的文字排版，或简单的桌面看片笔记感。暂不建议复杂 3D、长电影海报混剪或密集故障效果；首测还无法证明它们带来的制作成本值得承担。

## 下轮输入与输出

最小输入为一段可读的本地影视视频＋EXECUTOR_PROMPT，首测建议完整自足场景。片名/版本/全片位置/SRT为可选补充，缺失就把判断限制在片段内，不反复追问频道定位。独立云端 agent 无法自动访问本机路径，须另外解决素材与运行环境迁移。

主要输出为顺序展开的中文陪伴式拉片，保留所选场景完整原速播放，中间暂停解读/必要回看，成片一般长于所选场景，不设90至180秒限制。附字幕、旁白、时间码与解读证据、来源、渲染源和质检记录。未公开发布，首测不以完成网站为前提。测试重点是连续观看、证据说服力、旁白与画面配合，不强制应用未确认品牌。

## 内存与运行预算

本机物理内存可见量为 16020952KB，约15.28GiB；本轮读到空闲1518824KB，约1.45GiB。这是瞬时快照，不代表长期空闲。

Agent Reach 普通搜索是按次启动的工具；带浏览器的渠道会有额外浏览器进程。没有在本机测出适用于所有渠道的固定内存下限。视频渲染另外涉及 Node、Chrome、解码和编码，应与搜索区分。

首次测试的规划预算为普通搜索先预留0.5至1GiB，浏览器渠道另预留1至2GiB，1080p视频单任务争取空闲6至8GiB。以上是保守规划值，不是官方最低要求或本机峰值实测。当前1.45GiB空闲不足以有把握地承诺顺畅渲染。

16GB机器先通过减少同时运行任务、低内存单worker、3至5秒试渲染来验证；不自动结束用户进程。记录进程树总峰值、渲染耗时、是否换页后再判断是否需要更大内存，不把32GB作为本轮购买要求。百炼TTS在云端推理，本地仅处理请求/音频，不加载语言模型权重。

## 长期运营的主要问题

| 问题 | 运营中的处理办法 | 观察什么 |
|---|---|---|
| 论点越来越像过度解读 | 保留观察/解释/作者确认的区别；每期审最强替代解释；允许结论较小 | 时间码证据覆盖、反例处理、纠错数量 |
| 经典已经被讲过很多遍 | 每期确定具体问题；比较已有解读后寻找实质增量；避免只靠冷门细节 | 熟悉作品的观众是否获得新理解 |
| 热度与定位摇摆 | 经典/剧集场景/跨作品方法三个系列，不按每次热点重做频道定位 | 各系列复看与持续观看表现 |
| 标题许诺超过证据 | 标题和封面只承诺视频实际回答的问题，避免万能“真相揭秘” | 点击后早期流失、评论误解 |
| 生产研究成本失控 | 先做少量完整样片记录工时，复用工具与版式，不复用结论 | 每期研究/写作/剪辑/QA耗时与返工 |
| 更新压力稀释质量 | 初期建议隔周一篇主节目，空档可用独立成立的单场戏内容；以实测工时调整 | 是否有备稿、持续3期是否可承担 |
| AI声音缺少频道性格 | 固定音色但依语境调节停顿，原声让位规则明确；维护读音表 | 长听疲劳、错读、情绪是否合场景 |
| 片源版本不一致 | 保存片源版本/hash/字幕版本，片段时钟与全片时钟独立 | 评论指出的差异是否来自版本 |
| 素材使用与商业化 | 首先建立来源/使用范围/授权和发布限制记录；正式发布前针对平台与地区核验 | 片段/音乐/海报/字体是否可用于目标用途 |
| 播放量无法代表理解 | 同时观察完成观看、回看关键段、具体证据讨论、后续继续观看 | 观众能否复述论点和依据 |
| 交互页成为维护负担 | 先验证读者愿意回查证据，再投入账号/服务器/评论；保留无外链也成立的视频 | 实际打开、节点回查与有效解释数量 |
| 讨论变成站队 | 要求观点绑定片段，解释与人身评价分开；设置纠错/争议记录 | 是否在讨论可核验的观察 |
| 营收影响判断 | 赞助/合作清楚披露，分析意见与商业关系分别审阅；收入建立在原创研究与表达上 | 商业内容是否改变选题与结论 |
| 资料越来越难找 | 每集独立目录，来源可追溯，保留最终音频/渲染源和修订记录，备份与恢复另定 | 更换agent后能否重建同一集 |

在首个完整制作循环结束前，不承诺固定周更、全自动无人审片或一键批量。先验收3份不同类型的样片，再确定生产频率和交互投入。
