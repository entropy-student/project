## 一、唯一核心问题（FROZEN）

**产品怎么做、怎么交付？**

## 二、二级候选总表

本文件每条二级题须值得独立展开；问句尽量采用商家口语表达。右栏是今后要讲清楚的**知识和判断范围**，不是答案，也不属于冻结原文。

### 4.1 我要做网站、软件，还是直接开店？（4题，一级冻结）

**拆分依据：** 先定卖给客户的入口与产品载体，不把所有业务默认成独立站或软件。

| 编号 | 二级问题（候选） | 应覆盖的知识与判断 |
|---|---|---|
| 4.1.1 | **开平台店铺和自建网站，哪种更适合我？** | 平台/独立站的适用业务、控制权、上架限制、客户关系、基础成本；不是市场进入与获客渠道评估。 |
| 4.1.2 | **做软件的话，网页、手机 App 和下载版怎么选？** | SaaS、Web App、原生 App、桌面软件、交付与更新方式、设备依赖。 |
| 4.1.3 | **卖电子资料或会员内容，需要自己建平台吗？** | 文件交付、受控阅读、会员内容、第三方数字商品平台与使用权限要求。 |
| 4.1.4 | **卖实物或提供服务，应该在哪里接单？** | 平台商品页、独立下单页、预约入口、人工接单；形式选择，不展开实际发货/服务履约。 |

### 4.2 第一版先做到什么程度？（5题，一级冻结）

**拆分依据：** 把已决定提供的价值转成有限且能验收的范围，不把‘先做小’当作省掉履约。

| 编号 | 二级问题（候选） | 应覆盖的知识与判断 |
|---|---|---|
| 4.2.1 | **想做的产品，怎么写成具体功能和交付清单？** | 客户场景、交付物、必要输入与输出、用户任务、业务流程与验收口径。 |
| 4.2.2 | **哪些功能必须先做，哪些可以以后再加？** | 基础必需、质量底线、可选增强、依赖关系和首版优先级。 |
| 4.2.3 | **哪些步骤先靠人工做就够了？** | 人工、半自动、全自动的替代条件、吞吐上限、成本与出错风险。 |
| 4.2.4 | **第一版的预算和期限怎么定？** | 开发/工具/内容/测试/运维初始投入、任务切分、资源与时间上限；不重新做市场规模判断。 |
| 4.2.5 | **怎样判断首版已经够用，可以停止加功能？** | 最小可交付门槛、范围冻结、客户关键任务与可接受人工步骤；实际测试证据归4.6。 |

### 4.3 用现成工具，还是自己开发？（6题，一级冻结）

**拆分依据：** 把‘找现成方案→评估→拼接→自研/外包→可迁移’作为同一实现决策链。

| 编号 | 二级问题（候选） | 应覆盖的知识与判断 |
|---|---|---|
| 4.3.1 | **怎么找能直接拿来用的工具和模板？** | 现成电商/网站/软件/会员/预约工具、功能清单、可验证样机与供应商筛选。 |
| 4.3.2 | **免费、开源和付费工具，实际差在哪里？** | 商业许可、托管/插件费用、功能限制、维护成本、锁定风险与总拥有成本。 |
| 4.3.3 | **几个现成工具可以拼在一起用吗？** | 集成边界、数据交接、插件/API/Webhook、故障点、兼容性、数据一致性；不是支付机构教程。 |
| 4.3.4 | **什么情况下才值得自己开发？** | 现成方案无法满足的核心差异、复杂度、安全需求、技术能力、长期维护投入。 |
| 4.3.5 | **需要找人开发，怎样验收才不吃亏？** | 外包交付范围、可运行成果、代码与数据所有权、文档、缺陷责任和移交。 |
| 4.3.6 | **以后想换平台，账户和订单数据能带走吗？** | 可导出性、数据格式、迁移成本、功能替代、账号/订单/权益连续性。 |

### 4.4 怎么让客户顺利购买和使用？（7题，一级冻结）

**拆分依据：** 只处理客户在产品中的‘看清→选择→下单→输入→获取/使用’过程，营销说服另属第五板块。

| 编号 | 二级问题（候选） | 应覆盖的知识与判断 |
|---|---|---|
| 4.4.1 | **客户购买前，必须看清哪些商品信息？** | 产品包含内容、交付形式/时间、限制、适用条件、服务范围和明确条款；不展开获客文案策略。 |
| 4.4.2 | **有规格、套餐或定制选项，怎么让客户选对？** | SKU/套餐、数量、增购、定制字段、可见价格和购买前确认。 |
| 4.4.3 | **从选商品到下单，流程怎么安排更顺？** | 购物车/直接购买、订单确认、信息采集、错误提示、减少不必要步骤。 |
| 4.4.4 | **客户一定要注册账号吗？** | 游客结账、登录/注册、找回账户、会员使用身份与隐私代价。 |
| 4.4.5 | **需要客户填写资料或上传文件，怎样避免出错？** | 表单、上传校验、预览确认、暂存、敏感数据最小收集、失败重试。 |
| 4.4.6 | **客户买完后，怎么找到订单和产品？** | 成功页、邮件/站内消息、账户订单页、下载/访问入口及交付状态可见性。 |
| 4.4.7 | **不同语言和设备的客户，用起来会不会有障碍？** | 移动/桌面适配、时区/语言/格式、易用性与无障碍；性能测试归4.6。 |

### 4.5 客户下单后，怎么确保交付到位？（9题，一级冻结）

**拆分依据：** 按通用订单闭环＋数字/实体/服务差异拆分，保留支付结果与产品权限的边界。

| 编号 | 二级问题（候选） | 应覆盖的知识与判断 |
|---|---|---|
| 4.5.1 | **商品、套餐和库存怎么管理才不乱？** | 商品目录、SKU、价格与可售状态、库存/容量约束、超卖防止；支付费率归第三板块。 |
| 4.5.2 | **订单从创建到完成，需要记录哪些状态？** | 订单生命周期、业务主键、状态变化、取消与交付凭据、人工审核与追踪。 |
| 4.5.3 | **怎么确认客户付款成功了，才能开始交付？** | 产品侧支付事件核验、订单关联、防重复处理、待确认与失败状态；不研究支付渠道、费率或结算。 |
| 4.5.4 | **数字商品、软件权限怎么准确发给客户？** | 授权/下载链接、激活、账号权限、期限/次数、订阅资格与撤销或到期处理。 |
| 4.5.5 | **卖实体商品，怎样把备货、发货和物流接起来？** | 备货、仓储/代发、物流单号、库存扣减、发货与签收证据；不展开②基础设施。 |
| 4.5.6 | **提供定制或服务，怎样安排交付和确认完成？** | 预约/排期、客户素材/要求、人工节点、定制产物、验收与交付记录。 |
| 4.5.7 | **客户资料、订单和交付记录怎么对应起来？** | 账户/顾客/订单/商品/权益的数据关联、最小保存、后台操作角色与审计记录。 |
| 4.5.8 | **怎么让交付自动进行，又不会重复发货？** | 事件触发、任务队列、重试、幂等、失败告警与必要的人工接管。 |
| 4.5.9 | **遇到取消、退款、漏发或重复下单，怎么处理？** | 产品侧权益撤销/恢复、库存回补、履约冲突、客户通知与人工复核；退款资金动作归③。 |

### 4.6 产品上线前，要检查什么？（6题，一级冻结）

**拆分依据：** 验证实际客户结果，而不以页面打开或单项功能正常替代全流程可靠性。

| 编号 | 二级问题（候选） | 应覆盖的知识与判断 |
|---|---|---|
| 4.6.1 | **上线前，怎么像真实客户一样完整买一次？** | 不同业务路径的端到端验收：购买、确认、授权/发货/服务与消息交付。 |
| 4.6.2 | **支付失败、重复请求或交付中断，会不会出错？** | 未付款不交付、同一订单不重复执行、重试恢复与异常负例；对应4.5既有设计的测试。 |
| 4.6.3 | **账号、后台和客户资料，怎样检查是否安全？** | 权限隔离、客户隐私、访问控制、上传安全、必要的商业许可/条款检查；不替代法律专项核验。 |
| 4.6.4 | **海外客户或不同设备无法使用，怎么提前发现？** | 不同语言、设备、浏览器、网络条件、性能和可访问性冒烟测试。 |
| 4.6.5 | **上线出错时，能不能退回上一个正常版本？** | 上线前备份、版本标记、数据兼容、恢复路径与回滚演练。 |
| 4.6.6 | **该先找少量客户试用，还是直接正式上线？** | 分批开放、冒烟测试、首批反馈、明确上线/暂停门槛；不等同于第一板块市场验证。 |

### 4.7 上线后，怎么维护和改进？（8题，一级冻结）

**拆分依据：** 围绕运行、支持、成本、依赖、反馈与生命周期决策，不把上线当终点。

| 编号 | 二级问题（候选） | 应覆盖的知识与判断 |
|---|---|---|
| 4.7.1 | **上线后，日常需要检查哪些地方？** | 可用性、订单/交付失败、后台告警、隐私/异常访问、关键运行指标。 |
| 4.7.2 | **客户说没收到或用不了，怎么定位问题？** | 订单查询、授权/物流/文件核对、复现、客服记录与处理时限。 |
| 4.7.3 | **系统出故障或数据丢了，怎么恢复？** | 备份、恢复验证、停机处理、故障沟通与复盘；运维范围限于产品自身。 |
| 4.7.4 | **产品每个月要花多少钱维护？** | 订阅、托管、插件、外包、客服、异常交付与人工时间的持续成本核算。 |
| 4.7.5 | **平台改规则、插件停更或工具涨价，怎么办？** | 依赖盘点、更新回归、替代和迁移预案、安全修补与供应商风险。 |
| 4.7.6 | **客户提出很多修改意见，怎么决定先改哪个？** | 反馈收集、缺陷/新功能分类、频率与影响、优先级与验证；营销反馈归⑤。 |
| 4.7.7 | **客户越来越多，什么时候该扩容或加自动化？** | 容量、交付瓶颈、质量变化、扩容/简化/自动化的时机与成本。 |
| 4.7.8 | **决定不再卖这个产品，怎么妥善收尾？** | 用户通知、访问期限、订单和权益收尾、资料留存/导出与停用迁移；不决定市场退出投资逻辑。 |

## 四、去重、合并与知识归属自检

| 容易重叠的内容 | 主要归属与处理 |
|---|---|
| 4.1 选载体 vs 4.3 选工具 | 4.1 先决定业务需要哪种对客形式，4.3 再决定怎样用具体方案实现；不把同一平台工具罗列两次。 |
| 4.2 首版够用 vs 4.6 上线验收 | 4.2 定义功能范围与必须兑现的承诺；4.6 用真实流程和异常测试检验是否达标。 |
| 4.3 工具成本 vs 4.7 维护成本 | 4.3 比较采纳前的总拥有成本和锁定风险；4.7 对实际运行成本进行持续核算和治理。 |
| 4.4 下单流畅 vs ⑤获客转化 | 4.4 负责产品内交互与可用性；⑤负责流量、营销说服、销售跟进、成交诊断及增长。 |
| 4.4 购买后入口 vs 4.5 发货授权 | 4.4 管客户能否找到/看懂状态；4.5 管后台是否真的正确发货、授权、留存证据。 |
| 4.5 交付异常 vs 4.6 失败测试 | 4.5 设计现实处理与恢复逻辑；4.6 构造故障场景验证其是否安全。 |
| 4.5 订单退款关联 vs ③支付金融系统 | 4.5 只谈产品业务状态与交付撤销，支付机构、资金流、费率、结算及真实退款调用归③。 |
| 4.6 回滚准备 vs 4.7 故障恢复 | 4.6 上线前预设并演练恢复；4.7 运营中监测、响应、复盘。 |
| 4.5 订单/数据关联 vs 4.6 隐私安全 | 4.5 是如何建业务数据关系与内部使用角色；4.6 是安全和权限的上线验证。 |

**未独立设题但已覆盖：** 网站页面/购物车/会员体系（4.4、4.5）；支付接入回调与权益撤销（4.5.3、4.5.4、4.5.9）；文件上传和资料采集（4.4.5）；自动化与幂等（4.5.8）；备份/回滚（4.6.5、4.7.3）；订阅权限与到期（4.5.4、4.5.9）；商业软件许可与第三方素材适用性（4.3.2、4.6.3）；实体物流/服务履约（4.5.5、4.5.6）。不因这些名词具备技术深度，就机械各新增一章。

## 五、跨板块边界复核

| 相邻板块 | 本板块可以讨论 | 本板块不重新讨论 |
|---|---|---|
| ①机会挖掘与市场判断 | 把已决定的产品需求转成可实现功能与交付物 | 哪个市场值得进入、需求是否真实、商业模式值不值得做 |
| ②网络环境搭建 | 产品对浏览器、服务器和外部服务的功能依赖；面向客户的兼容性测试 | 跨境网络配置、域名、CDN、服务器与代理部署专项教程 |
| ③支付税务经营主体（CLOSED） | 产品如何接收已核实付款结果，联动订单、交付、撤权和回补 | 支付渠道选型、费率、清结算、税务、金融退款/拒付机制 |
| ⑤获客与用户增长 | 产品界面是否可使用、客户能否完成下单与获取产品 | SEO、广告、获客、营销转化策略、复购与推荐运营 |

## 六、场景覆盖与进一步审核的争议点

| 场景 | 已有主归属 | 建议重点检查 |
|---|---|---|
| 平台实物店铺 | 4.1.1、4.1.4、4.4.1–4.4.3、4.5.1、4.5.5 | 平台承包了哪些功能、哪些仍是商家责任？ |
| 独立站与可定制商品 | 4.1.1、4.3.1–4.3.3、4.4.2、4.4.5、4.5 | 上传、定制、人工审核与物流/数字交付链能否连接？ |
| SaaS、App 与订阅 | 4.1.2、4.3、4.4.4、4.5.4、4.5.7–4.5.9 | 权限、取消订阅后的资格、数据迁移是否足够具体？ |
| 数字资料与内容会员 | 4.1.3、4.4.6、4.5.4、4.5.8 | 文件访问、下载/有效期与资源盗用边界是否完整？ |
| 服务和人工定制 | 4.1.4、4.2.3、4.4.5、4.5.6 | 预约、排期、验收、返工与人工工时能否涵盖？ |
