## 二、T2｜ICP优先级卡、渠道准入和第一周行动

### 2.1 最小ICP/合格线索卡（第一章、T2/T4）

| 字段 | 应填写的内容 | 可以拒绝联系的信号 |
|---|---|---|
| 生意与使用场景 | 客户实际想完成的任务或采购规格 | 只讨论泛兴趣，没有实际使用场景 |
| 产品适配 | 必需功能、单量、地区、语言、交货限制 | 自家无法提供关键条件 |
| 真实意图和触发 | 询价/试用/补货/招标/业务节点 | 只为收集免费方案或身份无法核实 |
| 决策人、使用者 | 谁试用、谁签约、谁批准预算 | 无法找到决策链下一环 |
| 能力和时点 | 可接受的价位范围、审批/交付时间 | 超出最低经济性且暂无后续可能 |
| 证据 | 有明确来源的公开采购需求或自愿交流 | 联系方式未经必要核验/不可合法使用 |
| 下一步与停点 | 发样品/邀请演示/询问规格/退出联系 | 明确拒绝或要求停止营销 |

**示例（MODEL_ASSUMPTION）：** 有10个潜在线索时，不用自造绝对正确的综合分数；先排除3个不可履约与2个不可合规触达的对象，再从5个合格候选中优先选择有明确采购时点、愿意回复规格问题的3个。**没有真实证据时，列UNKNOWN，不把人标成必买客。**

### 2.2 渠道选择与资格表（第二章、T2/T5）

| 经营形式 | 首选尝试入口（不代表必须采用） | 准入、投入与验证点 |
|---|---|---|
| B2C独立站实物商品 | 商业意图关键词/商品页、符合资格的商品Feed免费展示、合规内容社区 | 核商品数据、目标国配送和退换、平台批准；看有效访问→支付→履约贡献 |
| Micro-SaaS / 插件 | 产品功能相关社区、适用应用/扩展市场、生态集成目录 | 必须先核商店/开发者准入与审核条款；看安装→激活→付费，不把安装=成交 |
| B2B外贸服务 | 合规行业目录、采购项目、专业社区、伙伴介绍与许可联络 | 看预算时点、使用/采购角色、合格商机→报价→真实订单，不以回复率=收入 |

**渠道入场五问：** ①客户正在那里解决什么购买问题？②我的主体/商品有资格进入吗？③第一个可完成动作是什么？④需要多少现金和本人时间？⑤观察哪个真实信号，何时决定继续/停？不要只因“免费曝光”就忽略制作与维护时间。

### 2.3 首周可填写行动计划（MODEL_ASSUMPTION）

| 日次 | 动作 | 交付物与验收 |
|---|---|---|
| D1 | 选一个产品与一个具体购买场景 | ICP卡；排除条件；对应实际法域/平台 |
| D2 | 核三条候选渠道资格及同类真实案例 | 最多选一条主路及一个保留路 |
| D3 | 准备真实样品/试用入口/可解释的价格和交付条款 | 从陌生买家角度完成访问与购买走查 |
| D4 | 符合许可和社区规则地发布/联系/上架 | 记录触达次数、渠道、合法基础、实际费用和工时 |
| D5 | 修复前端明确障碍，勿一边改多项一边声称因果 | 记录改动时间、客户反馈、失败类型 |
| D6 | 核支付/询盘/试用事件是否能与源系统对账 | 不把重复提交、机器人、未付款订单当转化 |
| D7 | 决定继续、停、修改假设或延长观察 | 写下投入、证据质量、下一次动作和停点 |

**禁止从一周内零成交推断市场不存在。** 需结合到达真实买家的机会、样本量和长周期滞后。

## 三、T5｜应用生态、商品Feed、AI搜索与平台排序边界

| 入口 | 可先核的官方资格/内容 | 经营者最小动作 | 不可推断 |
|---|---|---|---|
| 浏览器扩展/应用生态 | 目标应用市场开发者政策、审核/支付机制、数据收集要求 | 实际可用的演示、可信权限说明、落地页与激活事件 | 商店上架不保证被推荐/盈利 |
| Google Merchant Center免费商品展示 | 目标国家/商品政策、唯一商品数据、库存价格、运费退换 | 核真实商户是否有资格，提交合格商品数据、查曝光→站点订单 | “免费展示”不等于免费获取订单、全主体可用 |
| B2B行业采购与集成目录 | 平台供应商资格、地域及验证要求、采购条件 | 查采购意图与联系人资格，完成一次真实报价 | 目录收录不代表订单、无条件合法采集邮箱 |
| AI Overviews / AI Mode | Google Search Central既有索引和SEO技术要求 | 写可信的行业事实、针对搜索意图的页面、可验证转化，查看Search Console与真实付款 | 没有专属AI索引捷径、排名保证或通用“GEO”技巧 |
| Amazon/Etsy等平台内曝光 | **逐平台核官方帮助文档及当期账号权限** | 区分排名、广告位、服务表现与实际搜索词报表 | 不把不同平台统一成固定权重算法，不把广告视为必然提高自然排名 |

核对：Google AI搜索仍依基础SEO，没有额外专属技术要求 [官方](https://developers.google.com/search/docs/appearance/ai-features)；商品免费展示要求品类与商户符合资格、配送及退换信息符合要求，且**不保证展示** [官方](https://support.google.com/merchants/answer/13889434?hl=en)；Etsy具体搜索机制按[官方文章](https://www.etsy.com/seller-handbook/article/how-etsy-search-works/375461474487)并核更新日期。平台政策是**动态规则**，不能把本页当作已通过账户实际资格审查。

**内容低精力SOP：** 发现1个真实客户疑问→基于事实回答/演示→在允许的1至2个渠道分发→用实际咨询/激活/订单衡量而不是只看浏览→按变动信息更新。若内容渠道长期无法在有限工时内贡献目标结果，应停止或缩减，而不是为了“持续更新”硬做。

## 四、T7｜跨国访客的10项下单走查

把目标国家/设备/语言固定为一个**具体用户场景**，从陌生设备完成下列检查；记录“实测/无法实测/需交技术或法务”。

| 核验项 | 买家实际需要看到的证据 |
|---|---|
| 1 真实检索词 | 当地行业原生表达，而非机械英文直译 |
| 2 页面可到达 | 用户所在区域可打开、内容清楚；技术修复交第四板块 |
| 3 适配信息 | 功能、规格、使用限制、必要材料 |
| 4 价格与币种 | 实际结算币种、优惠条件，不隐藏额外成本 |
| 5 运费和税费 | 运输方式、适用的进口税/买方责任说明 |
| 6 库存或服务容量 | 真有货、交期是否可履约、数字服务可开通 |
| 7 信任材料 | 可核身份、有效支持联系、真实用户资料及限制 |
| 8 购买/咨询下一步 | 明确行动按钮、报价/预约步骤及确认机制 |
| 9 支付结果 | 真正成功支付才是实付订单；技术与财税交对应板块 |
| 10 退款/取消与售后 | 地区适用条款、客服处理路径、必要撤销和退订 |

**反例：** 某工艺配件的英文直译词吸来大量DIY内容读者，却没有采购询价。应用本地语种行业术语到当地SERP/商贸目录验证，记录真实采购页面与询盘再决定，不根据热搜结果直接判存在付费意愿。

## 五、T4｜SaaS首次价值与B2B商机漏斗

### 5.1 Micro-SaaS经营侧激活流程（MODEL_ASSUMPTION）

| 阶段 | 记录的真实事件 | 不可替代的含义 |
|---|---|---|
| 注册 | 有效账号创建（去重、合法数据处理） | 不是激活，更不是付款 |
| 核心行为 | 例如“成功生成一次有用的账单摘要” | 比单纯登录更接近产品价值，实际行为须按产品选择 |
| 首次价值 | 用户获得并确认一个可用结果 | **TTFV（Time to First Value）**：从起点到首次完成价值事件的时间；不设跨产品通用目标 |
| 付款 | 支付确认，排除失败/退款/重复订单 | 与注册/核心行为使用同群窗口 |
| 留存/续费 | 下一周期真实使用或成功续费 | 看有价值的留存，不因未退订自动认定活跃 |

**分组处理：** 已注册未完成关键事件→先检查入门障碍，按营销许可决定是否触达；已完成价值但未付费→查限制与价格适配；付款失败→区别支付摩擦与真正主动流失；申请取消→尊重取消与法定保留例外。产品埋点和登录/支付实现交第四板块。

### 5.2 B2B最小商机看板

| 阶段 | 进入证据 | 退出/下一步证据 |
|---|---|---|
| 新询盘 | 真实需求/来源记录 | 是否满足基本规格/交付国 |
| 合格商机 | 匹配产品、角色、时点或预算的可核线索 | 下一次样品/报价/演示约定 |
| 报价/样品 | 可交付的价格、数量、期限 | 买方反馈、技术/采购验收 |
| 审批/谈判 | 对方明确内部审核或合同议程 | 决策角色与预计时间更新 |
| 赢单 | 正式订单/合同及按定义核实付款 | 后续履约和复购 |
| 输单/休眠 | 明确拒绝或无合法持续联系条件 | 记录原因，尊重退出或约定再联系 |

“已发邮件”“已接电话”只是动作，不自动等于商机推进。B2B付款回流可能跨月，不以注册/询盘总数冒充实际获客客户。

## 六、T3｜共用最小数据字典、历史账与同群留存

### 6.1 最小事件和唯一标识

| 事件 | 商业定义 | 最少关联字段与核验 |
|---|---|---|
| `visit` | 有意义访问（机器人/重复浏览排除依实际工具） | 渠道、时区、观察窗口 |
| `lead` | 有效询盘/合规收到的采购需求 | lead_id、资格状态及同意基础 |
| `signup` | 唯一注册账户 | customer_id，不能当付费 |
| `activation` | 明确定义的价值事件 | customer_id、事件时间、事件版本 |
| `purchase_paid` | **经支付来源确认的实际付款** | order_id、customer_id、币种、金额、结算状态 |
| `refund` | 已退款或部分退款，含原订单映射 | refund_id、order_id，防止双重统计 |
| `repeat_purchase` | 同一客户下一笔有效实付订单 | customer_id、订单日期，定义同群窗口 |
| `unsubscribe` | 已选择停止相关营销 | 来源、时间、范围、同步状态 |

**核对顺序：** 广告报表→网站事件→订单系统→支付/退款源记录，先对齐日期、币种和唯一订单再讨论CAC。Google GA4按`transaction_id`的**重复购买去重只适用于网站数据流，不适用于App数据流**；同一客户不应把多个有效订单粗暴去掉。详见[Google官方](https://support.google.com/analytics/answer/12313109?hl=en)。同意模式/增强型转化仅在具备账户资格、合法数据处理和正确配置时参考，**加密或哈希本身不等于获得法律许可**。

### 6.2 财务双账（MODEL_ASSUMPTION）

| 经营问题 | 需要记录的成本 | 不可混淆 |
|---|---|---|
| **回顾：过去这一渠道真实花了多少** | 已花广告、失败试验、素材、佣金、工具、人力及必要售后成本；识别固定与可变 | 可用于历史全口径CAC与渠道复盘，不能抹除历史失败支出 |
| **前瞻：下一笔新客值不值得再投** | **未来将发生且可避免**的广告/变动履约/新增人工/佣金及增量支持成本 | 已发生且不可收回的历史成本不应在下一次决策再扣一次，但也不代表旧亏损消失 |

**示意**：过去实验已花$200且不能追回；下一轮计划再花$60获取2位新客，每位有效新客在扣商品及履约后提供$45贡献。若没有新增其他成本，则下一轮示意增量`2×$45−$60=+$30`。历史整期账**仍应计入此前$200真实消耗**，不能拿下一轮+$30把历史亏损抹掉。

### 6.3 同群（Cohort）留存与情景

以首购月份/注册来源组成明确可追溯群组；例如“2026年10月首购有效客户100名”，第1、2月分别记录**实际**再次付费人数、净营收、退款后贡献和客户流失。数据尚未收齐则留UNKNOWN，**不能直接把期望曲线当历史事实**。

| 业态 | 重点看什么 | 不能推导什么 |
|---|---|---|
| B2C实物 | 二单率、首到次购买天数、扣退款/售后贡献 | 不能假定所有商品每月复购 |
| SaaS | 活跃/付费客户留存、收入留存、账号取消与支付失败分离 | 不能用注册人数当付费LTV基数 |
| B2B | 同一账户再次签单、采购周期、合同后续成本 | 不能拿30天没再买证明“流失” |

**三情景（MODEL_ASSUMPTION）**：只调整客户续费概率/毛贡献/支持成本的保守、基准、乐观假设；固定当前CAC不变做敏感性检查。没有实际支付同群数据时，LTV应表达为假设范围而非确定未来现金。

## 七、T6｜实验登记卡、自动化抑制与放量闸门

### 7.1 最小试验卡

| 字段 | 填写标准 |
|---|---|
| 目标决策 | 为什么要改变，成功后要做哪个经营选择 |
| 主要假设 | 目标客群、哪个机制变、预期提升哪种实际行为 |
| 实验/观察单位 | 用户、账户、流量来源、渠道；是否有同期可比分组 |
| 唯一主KPI | 支付有效新客/合格商机/真实激活等 |
| 观察窗口 | 结合周内波动、转化时滞、季节性、样本可得性 |
| 最小有用差额 | 经营上值得行动的改善量，不冒称统计显著阈值 |
| 不确定性 | 样本不足、分流偏差、其它同期改动、平台归因差异 |
| 继续/停止规则 | 根据现金容忍度、投诉、履约与真实证据预设 |
| 复盘结果 | 改善/变差/暂时无法下结论；记录下一轮验证 |

**重点：** 一次只提出清晰假设，不等于“其它环境可完全恒定”；简单前后对比不自动证明因果。“未显著”也不是“证明两版完全相同”。

### 7.2 生命周期消息与禁止发送条件（T6/T8）

| 情形 | 可否发送/要核对什么 |
|---|---|
| 订单确认、真实物流通知 | 以必要交易服务为目的，内容不得夹带不符资格的广告 |
| 复购/补货优惠提醒 | 商业营销：核用户法域、接收者类型、合法基础、退订、平台许可 |
| 已退订该类营销 | **禁止再发送同范围营销**；交易服务必需通知按当地法律分别判断 |
| 已退款/正在投诉 | 暂停与当前争议不相容的“求好评/促复购”，允许必要问题处理 |
| 已复购/已兑换权益 | 取消重复邀请与重复奖励，防订单重复触发 |
| 重试失败/异常队列 | 按唯一message_id去重、检查抑制名单实时状态、设置频率和上限，超阈值人工接管 |
| 退信/投诉异常 | 暂停对应活动，复核名单来源、认证、节奏与内容后再决定恢复 |

**发送前控制七字段：** 联系方式的合法取得来源／国家与渠道／营销目的与许可范围／许可时间与状态／退订与抑制记录／消息唯一键与最近发送时间／人工负责人。只保留合规必要记录，不长期囤积超额个人资料。技术Webhook重试幂等实现归第四板块；Gmail发件认证与发送者规则见[官方](https://support.google.com/mail/answer/81126)，不能把任何投诉百分比当作可安全逼近的目标。

### 7.3 联盟与推荐奖励边界

销售转介绍佣金、真实评价奖励、广告证言是三种不同机制，**必须逐渠道核平台规则**；不得以“FTC允许某些中立激励”推论Amazon等平台允许以报酬换评论。推荐计划需检查介绍人真实身份、自荐/刷单、重复订单、优惠码外泄、实际退货与退款后佣金冲回、利益关联公开披露和归因窗口，不把老客复购记为两个新客户。

### 7.4 放量与回退闸门

| 放量观察 | 应核验的真实证据 | 回退信号 |
|---|---|---|
| 新增客户经济性 | 订单扣变动成本后的可验证增量贡献、全口径CAC与实际现金 | 贡献持续为负且没有可信改善路径 |
| 履约/客服 | 订单峰值、可用库存、支持处理时延、质量与退款 | 客诉积压、退款争议、逾期发货 |
| 现金与结算 | 周转期、已冻结储备金、供应商账期及退款需求 | 现金无法覆盖确定义务 |
| 平台依赖 | 单平台集中度、第二渠道实付新增客户及真实运维成本 | 两条渠道实质同源/成本过高 |
| 人工治理 | 哪些高风险动作能停止与回滚 | 自动营销异常或未经许可群发 |

任何`70/30`预算份额、两倍冗余或资金周数只能按实际经营风险自定义，**不是行业统一法定义务或平台保证。**

## 九、T2/T3/T4｜三条完整经营闭环样例（全部MODEL_ASSUMPTION）

### 案例A｜独立站实物商品：从搜索意图到真实首单

- **产品/ICP**：特定尺寸的非易损办公配件，买家在目标国搜索具体型号的兼容性，明确拒绝卖家不能满足的型号。
- **渠道与动作**：选一个已核商品资格的自然商品展示入口+一个客户问答页面；商品Feed、运费及税费透明；访问必须落入对应兼容型号产品页。实际资格未知则不发布“已免费上架”。
- **事件/数据**：第一周示意100次有效商品页访问、5次加购、2个真实付款（2个新客），净实收每单$80；订单号唯一，扣退款后核净额。**这里2/100只是教学观测，不代表可推广的真实转化率**。
- **历史获客账**：示例制作/工时摊销$40、符合资格的自然展示直接广告花费$0、已产生的其它必要经营成本另记录；不得称免费流量完全零CAC。
- **单笔成本与阶段决策**：假设每单商品采购/发运及预计售后$52，则两单已列贡献`2×($80−$52)=$56`，扣本例$40历史营销资源消耗只剩`$16`的示例差额；未含其它固定/法定费用，不是净利润。
- **停/继续**：若无法在目标国合规履约或无真实购买入口，就先改兼容性与履约承诺；若有实付却真实贡献长期为负，调整渠道/售价/成本而非立即倍增广告。

### 案例B｜Micro-SaaS：从安装到首次价值再付费

- **产品/ICP**：用于整理小团队重复报价的轻量软件，目标是实际每周需要报价的用户，而非泛泛好奇下载者。
- **渠道与动作**：在合适的插件/应用生态核开发者身份及政策，提供真实演示和试用；一周只发布与目标问题有关的可复核内容，禁止超范围私信营销。
- **事件/数据**：示例`20 signup → 8 activation（真正完成1份可用报价）→ 3 purchase_paid`。**激活率8/20=40%；注册转付费率3/20=15%**；未激活先检查引导和价值是否可达。
- **贡献口径**：假设每位实付首期实收$20、扣首期直接交付/服务成本$6；3个付款客户首期已列贡献`3×($20−$6)=$42`。假设推广花费$24，则扣示例推广后的差额$18，仍未扣全部费用。若3名均为新客，示例广告CAC=`$24/3=$8`，但不等于全成本CAC。
- **留存与停止**：下期实际成功续费、退款和服务成本才是留存证据；试用激活很低先排查首次价值，未付费可能是价格/产品问题而非必须狂投广告。

### 案例C｜小型B2B外贸：从合格商机到正式订单

- **产品/ICP**：允许小批量定制的工业零部件服务商，目标是有明确尺寸、订单量、交期、技术决策人和审批时点的采购团队。
- **渠道与动作**：合规行业目录与自愿询价渠道；初次联络需核具体法域、收信者类型、合法基础与平台规则。销售阶段按`询盘→已合格→已报价/送样→采购批准→赢单/输单`记录。
- **事件/数据**：假设15份原始询盘→5份资格合格→2份正式报价→1笔最终有效订单；**不可将15条询盘当成15个付费客户**；若2个月之后才收款，按相同会计/经营期间复盘。
- **财务决策**：假设1笔有效订单实际收入$1,200，扣采购/检验/交付等直接变动成本$850，先得已列贡献$350。历史获客外包与拜访工时合计$180，则示例阶段差额$170；未扣未列费用和税。下一笔订单的边际决策不能把已经花完的历史$180重复扣第二次。
- **扩量与失败**：若当前交付返工率高，即使有新询盘也先稳住质量；若买方合规审批尚未结束，不能按短视频7天投放周期定义“死线索”。
