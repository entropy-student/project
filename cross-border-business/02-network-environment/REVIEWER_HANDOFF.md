## 一级模块的拆分逻辑（Owner已要求记录）

**唯一主线：以跨境卖家真实经营生命周期的行动、认知顺序组织知识；以功能职责划分模块，尽量减少交叉并覆盖全流程。** 不按技术名词、工具、协议或服务商硬性分章。

| 阶段 | 一级模块 | 解决的问题 | 与下一阶段的关系 |
|---|---|---|---|
| 准备：判断业务需求 | ① 经营环境规划 | 开始跨境生意，我需要准备哪些技术环境？ | 确定需要哪些环境 |
| 经营者侧：网络、设备与账号 | ② 海外工作环境 | 如何在国内稳定、安全地使用海外平台和账号？ | 建立可使用的平台与账号工作台 |
| 业务资产：建立地址与通信 | ③ 域名与企业通信 | 如何建立并管理业务域名、网站地址和企业邮箱？ | 准备对外的业务地址和通信 |
| 承载业务：计算、数据与任务 | ④ 业务部署与数据服务 | 网站、数据库和自动化程序应该放在哪里运行？ | 部署网站、程序及数据服务 |
| 上线门槛：预防风险 | ⑤ 上线安全与风险 | 上线之前，如何保护账号、系统和数据？ | 形成对外开放前的安全基线 |
| 对外上线：客户侧体验 | ⑥ 客户访问与性能 | 怎样让海外客户顺利、安全地访问我的网站或服务？ | 验证海外客户能否正常访问 |
| 日常运营：发现、修复和恢复 | ⑦ 监控与故障恢复 | 运行后如何及时发现故障、保护数据并恢复业务？ | 运行后监控并恢复故障 |
| 长期经营：费用、扩展与替换 | ⑧ 成本与持续发展 | 如何控制成本，并随着业务发展升级和迁移？ | 按实际业务和费用决定后续演进 |

**递进主链：** 先准备 → 再搭建 → 安全上线 → 稳定运营 → 持续发展。细分为**规划① → 卖家工作环境② → 业务资产③ → 部署和数据④ → 上线前安全⑤ → 客户侧可访问⑥ → 监控与恢复⑦ → 成本与扩展⑧**。

**三个审查原则：**

1. **递进性：** 优先按普通卖家认识需求、做决定、动手、验证、运营的顺序排列；但这是教学顺序而非每家商户必须执行的固定采购/施工顺序。③和④可以并行，基础安全、准入合规及费用意识从第一步就开始。
2. **独立性与推荐合并：** 把原九章的“海外网络连接＋设备账号管理”合并为②；把“服务器运行＋数据库/对象存储”合并为④；客户访问/CDN保留为⑥。安全⑤与故障恢复⑦不合并，因为预防和恢复回答不同问题。
3. **完整性：** 从技术需求与准入到工作端、业务承载、客户侧、保护、恢复及可持续成本形成闭环。纯平台卖家、独立站、SaaS等分流阅读，任何技术都不默认每家必买；第二板块不越权研究第三板块已冻结的支付、税务、主体正式内容。

**二级拆分内在规则：** 每章优先遵循“需要什么 → 为什么/如何工作 → 选择方案 → 搭建/使用 → 验证 → 异常处理”。允许因主题性质跳过某一步、章节间交叉引用，但避免相同知识被重复讲成两个主要问题。
