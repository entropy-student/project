# SPW API — 冰川折光设计与实施方案

版本：v5，2026-10-27。基于 upstream v1.0.0-rc.46，revision `7d8b91268dab69d7150f345c448b5e250163146a`。

状态：G「冰川折光」整站方案及后续 Workbench 改造已获用户批准，现已实施并部署到本地。下文保留设计规格，第 14 节为上一轮记录，第 15 节为本轮实际交付与验证；未修改后端版本和业务逻辑。

## 1. 目标与现状

面向外部用户提供 API 服务，保留现有业务功能，以 SPW API 为默认展示品牌。v1 只有品牌标识、冰川首页和基础主题；本轮在该基础上完成下述共享外壳与页面展示改造。

下一轮完成信息层级、导航、页面布局、表格、表单、图表、反馈与移动端的一致设计，而非继续增加配色覆盖。采用三种用途明确的表达：

- 首页：冰川建筑光感、透明 S 形雕塑、简短文字和明确行动。
- 控制台：冷白底、深蓝灰文字、细分隔线，表格和表单使用稳定实色背景；折光只用于品牌与少量强调。
- 登录与注册：一侧品牌画面，一侧专注表单；移动端以表单为主。

深色模式沿用同样的信息层级，转换为深冰蓝背景；尊重用户已有主题和自定义偏好。文字、数字、按钮均由真实 HTML 渲染，不烘焙进图片。

## 2. 本次确认的删减

### 首页内容

删除截图对应的整个 `.spw-path-section`：标题「从模型到应用，每一步都清晰」、说明、模型广场按钮和右侧三步指南。移除它留下的间距；只清理确认为它独用的样式和翻译。

保留主视觉区域中的真实快捷入口：模型广场、API 密钥、余额与充值。移除大块品牌宣传式页脚，将法律链接、版权与上游归属收成底部小行。保留项目许可证和应有的上游 attribution。管理员配置的自定义首页和自定义页脚仍按原有机制工作。

目标结构：

```text
SPW 标识  首页 / 模型广场 / 控制台                 语言 / 主题 / 账户

简短标题、服务说明、主要行动              冰川 S 主视觉

模型广场                    API 密钥                    余额与充值

版权、法律链接与项目归属
```

桌面 1280×800 时主要行动可直接发现；不为凑满屏幕添加说明区。移动端按标题、行动、主视觉、快捷入口排列。

### 导航入口

「排行榜 / 文档 / 关于」解释为三个首页导航入口。下一轮从默认公共导航的桌面与移动版本中隐藏，页脚也不重新添加；相应页面、路由和后端能力保留，本轮不设计它们。

采用模块标识过滤，不能通过中文标题比较或 CSS 隐藏。`use-top-nav-links` 会读取后端动态配置，必须在动态与默认入口合并后应用展示策略，避免仅修改默认数组而无效。控制台顶栏也不重复展示这三项；后端 `HeaderNavModules` 配置不改写。其他管理员自定义链接、权限要求、外链属性保持原义。

## 3. 不可变的业务边界

1. 不修改 relay、渠道调度、模型映射、接口协议、任务插件、限流或数据库结构。
2. 不修改金额、余额、汇率、折扣、订阅、充值最低额、计费公式、支付回调及提供商行为。金额和时间继续使用现有格式化函数。
3. 不修改登录、注册开关、OAuth、Passkey、验证码、2FA、会话、跳转和法律同意流程。面向外部用户不等于开启被管理员关闭的注册。
4. 不放宽 Root/Admin/普通用户、侧栏模块、数据范围和任何按钮的显隐、禁用与确认条件。
5. 保留已有筛选、URL 状态、分页、列设置、选中、批量操作、导出、复制、详情、编辑和危险操作确认。
6. 保留管理员自定义品牌、首页 HTML/Markdown/iframe、页脚 HTML 和既有主题偏好；默认品牌才使用 SPW API。
7. 保持后端与 Nginx 代理规则，特别是未知路径、非 GET/HEAD、上传、任务插件、WebSocket 与 SSE。

首页不放代码框；模型详情「API 接入」中的协议、语言切换和可复制示例属于真实功能，必须保留。禁止用虚构模型、价格、订单、性能数字或假实时图表装饰生产界面。

## 4. 视觉规范

### 色彩与材质

下列为默认浅色主题基准，实施时集中映射到现有语义变量，不散布组件内硬编码。

| 用途     | 基准      | 使用规则               |
| -------- | --------- | ---------------------- |
| 页面背景 | `#F8FBFC` | 冷白主底               |
| 次级背景 | `#EDF5F8` | 分组和辅助面板         |
| 数据表面 | `#FFFFFF` | 表格、输入框和主要表单 |
| 主文字   | `#101E2B` | 标题、数字和重要操作   |
| 次文字   | `#536875` | 解释与次级标签         |
| 边界     | `#CEDFE7` | 精细分隔，不依赖大阴影 |
| 选中背景 | `#DCEFF3` | 导航、选择与轻提示     |
| 强调     | `#286687` | 链接、焦点及少量高亮   |

成功、警告、错误保留独立语义色，不全部改成蓝色。透明材质只用于首页与轻量导航，不覆盖数据正文。避免每个统计块都加渐变、玻璃和厚阴影。

### 字体、间距与形状

- 沿用现有字体加载方案；品牌区使用 Public Sans 与系统中文回退，不额外引入多套字体。
- 首页标题桌面 56–72px、移动 34–40px；控制台页标题 24px、区块标题 16–18px、正文及表格 14px、辅助信息 12px。移动输入框至少 16px。
- 以 4px 为间距单位，页面桌面边距 24px、移动 16px；用 16/24/32px 建立区块关系，不堆叠大块空白。
- 常规按钮高 36px，移动主要触控区域至少 44px；表格基础行高约 44px，已有紧凑模式继续可用。
- 输入与按钮圆角 8px，卡片 12px，抽屉和大面板约 16px。首页主要 CTA 可以更圆，控制台不全面胶囊化。
- 数值按既有格式与单位输出，数值列右对齐，标识符可使用等宽字体；不混淆累计和当期指标。

## 5. 控制台外壳与导航

```text
固定侧栏 224–240px       上下文 / 面包屑        搜索、通知、语言、主题、账户
品牌、动态权限菜单       ------------------------------------------------
                        页标题、必要说明                 主要操作
                        统计或状态（有真实数据时）
                        搜索、筛选、视图设置
                        主内容 / 表格 / 表单
                        固定分页与批量操作（适用页面）
```

使用现有 `Main`、`SectionPageLayout`、侧栏和顶栏组件落实结构。顶栏承担上下文与工具，侧栏承担业务导航，减少重复；保留原有通知、更新提示和账户能力，可调整位置。

菜单来源继续使用 `use-sidebar-data` 与现有配置权限，个人偏好不能超出管理员允许范围。系统设置继续使用上下文侧栏和返回入口，不同时堆放根菜单与完整设置树。

每个页面原则上一个主要操作；筛选和次级动作降级为轻按钮。详情与编辑优先复用现有抽屉，不增加无必要的页面跳转。保留 `min-h-0`、内部滚动、固定内容、分页 portal 与宽表滚动机制，避免全局 CSS 破坏布局。

## 7. 共享组件与状态

优先修改现有布局及业务包装组件，复用项目 shadcn/Base UI 与现有依赖，不另建第二套组件系统。

- 表格：继续使用原 DataTable core/layout/toolbar/static API；统一标题、筛选、行、选择、批量区与分页；保留列宽、固定列和用户列偏好。
- 移动：复用 `ApiKeysMobileList`、`UsageLogsMobileList` 和已有筛选抽屉；不能单纯把桌面宽表缩小。
- 抽屉：普通详情/编辑以 560–720px 为参考；复杂渠道表单按原字段需求加宽，不强塞统一窄宽。
- 表单：标签与说明层级固定，必填/校验/提交反馈清楚；继续复用现有 schema、表单和业务 hooks。
- 空态：说明当前状态及可执行动作；无数据、筛选无结果、加载失败分开；不放营销大插画占用数据区。
- 完整覆盖：首次加载、后台刷新、正常数据、空数据、筛选无结果、局部错误、提交中、禁用、批量选中、过期、支付确认等现有状态。
- 复制、导出、删除确认和通知继续使用现有封装，避免视觉改造产生重复业务逻辑。

## 8. 响应式、动效与可访问性

- 320–640px：单列，侧栏抽屉，紧凑顶栏；优先使用移动列表，必要宽表在组件内滚动。
- 641–1024px：收窄侧栏与图表网格；筛选允许换行，按钮不溢出。
- 桌面：内容自适应，阅读型表单限宽；1920px 不将短表单无限拉长。
- 控件反馈约 120–160ms，抽屉约 160–220ms，首页首次入场约 400–600ms；以 transform/opacity 为主。
- 不增加循环漂浮、数据区持续发光或假实时动画；尊重 reduced-motion，取消新增的入场和非必要过渡。
- 明确键盘焦点；正文目标对比度至少 4.5:1；状态同时有文字/图标；触控区域至少 44px。被隐藏菜单项不留可聚焦残影。
- 图表保持原数据与交互，只统一文字、网格、图例和语义配色；图例不能仅靠颜色辨识。

## 10. 下一轮实施顺序

同一轮按以下顺序推进，不在每批后重新开展主题选择；遇到业务边界问题再缩小展示改动。

1. 首页删减、三入口隐藏、紧凑页脚；建立外壳、排版与间距规则。验证动态导航与移动菜单一致。
2. 密钥与渠道先做两种复杂列表样板，验证表格、筛选、抽屉、批量操作和移动卡片。
3. 完成概览、日志、模型广场/详情、钱包、登录/注册、个人与安全页的信息重排。
4. 将样板规范应用到其他管理页、设置与工具；逐项对照权限和条件动作。
5. 运行针对性回归、类型检查、lint/format 和生产构建；在可预览结果通过后备份并按原部署方案更新，运行代理对照与页面验收。

如实际实现暴露未预期的业务耦合，优先保留原业务组件，仅调整其外围布局；不借机重写核心逻辑。交付说明必须区分已完成、未完成与未测项目，不能只凭首页截图宣布整站完成。

## 11. 验收标准

### 用户可见

- 截图所示引导区确实消失，其下不残留大块占位；页脚明显收紧。
- 首页桌面与移动导航均没有排行榜、文档、关于入口；其原有直达路由仍可用。
- 不止颜色变化：侧栏/顶栏分工、概览优先级、钱包布局、筛选工具条、表格、表单和详情抽屉有可辨认的重排。
- 首页、概览、密钥、日志、模型广场与钱包形成同一品牌语言；深色、空态、长文本与弹层没有明显割裂。
- 页面只展示真实数据；空账户不伪造用量、余额、成功率和订单。

### 工程与行为

- 检查 1440、1280、768、390px 视口，以及 320px 边界；浅/深色、移动菜单、长表格、加载/空/错误状态和键盘焦点。
