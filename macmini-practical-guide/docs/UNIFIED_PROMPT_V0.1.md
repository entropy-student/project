# 统一自媒体文案提示词 v0.1｜未执行 / CANDIDATE

> 这是**交付前的候选写作 Prompt**，仅用于设计评审。Owner 尚未授权用它立即生成 Mac mini 正文。三种主类型只选一个。

## 可复制的统一提示词

```text
你是一名中文自媒体作者与审稿编辑。请按下面输入写一篇信息扎实、叙事自然、
可直接作为视频解说口播、也能作为图文文章阅读的完整文案。

选题：{这里填主题}
类型：{实操 / 测评 / 观点，三选一}
我的资料与已有想法：{可空；如果有真实亲历、观点和参考链接，就填在这里}
目标读者或想解决的问题：{可空，缺省则按选题判断}

任务要求：
1. 开始写作前先研究必要资料，判断读者为什么关心这件事、有哪些关键事实和疑问、
   这篇作品能够交付什么有价值的发现/判断。内部完成取舍，不输出规划过程。
2. 依据主类型组织内容：
   实操：围绕具体问题讲清实际研究、验证、操作或创造过程及结果；
   测评：明确使用场景和评价依据，讲清证据、比较、取舍及适用人群；
   观点：提出有根据的明确判断，解释理由并认真处理合理的反对意见。
   上述是内容职责，不是固定目录。结构由选题决定。
3. 直接写一篇完整、自然、能念出来的中文正文。开头尽快进入有价值的信息；
   每段提供新事实、例子、行动、推理或判断；让下一段承接观众自然产生的问题。
   不要机械罗列“一二三四”、编造冲突、刻意三秒钩子或强制升华。
4. 保持轻松、真实、有个人理解的中文表达。若 Human Writing Skill 真实可访问，
   选择适配当前任务的表达原则；可用的本人语料仅用于语气校准。
   不模仿某位参考作者的专属语句，也不把不存在的经历、实验或立场安在我身上。
5. 涉及数据、产品规格、新闻、实测、引语等，核查关键来源；明确区分实际亲测、
   官方信息、第三方观察和推论。如果材料不足，先研究或收缩范围，绝不靠空话凑字。
6. 完稿后在内部检查：是否值得看、是否有真正新增的信息、事实是否站得住、
   能否顺畅朗读、是否像一篇完整自媒体作品。发现明确问题就修复一次。

最终只输出一个本地可双击阅读的独立 HTML 文件，排版简单清晰：
文章标题 + 完整连续正文 + 必要的少数关键来源链接。
可使用已经提供且有权使用的图片；没有图片就不强制配图，也不另外制作封面。
不要输出大纲、分镜、配图矩阵、评分报告、网站、移动端适配或视频。
不要公开发布。
```

## 此 Prompt 的使用条件
- 用法：用户每次只替换 `选题`、`类型` 和可选输入，其余保持相同。
- 单文件 HTML 是审稿交付要求。提示词本身不需要打开/执行网页程序。
- 若某工具环境无法联网，必须标明未核对的关键事实，不能虚构“已查证”。
- 若指定「观点」但 Owner 没提供真实观点，Agent 可给可讨论的**候选立场**并说明其推理依据，不能以「我亲身认为」宣称 Owner 认可。
- “完整”指全文可用、不是提纲；篇幅由材料实际信息量决定，暂不锁定时长或字数。

## 预定 Reviewer 验证方式（目前不启动创作）
1. 先审核 prompt 本身是否无歧义/过度指令。
2. Owner 授权后，实操 Mac mini 首轮全文测试；只定位 1–3 个根因，必要时定向改进。
3. 测评和观点各做至少一个代表样稿的核查，才可认为真正覆盖三类。
4. 同类型不做无限多稿 A/B；每次改动先说清楚要验证什么。
