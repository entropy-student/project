## Core Reviewer decision: fix transport *invocation* in the same allowed boundary
`MethodInvocationException` is a PowerShell wrapper. Without an inner exception stack, it does not prove wrong argument types, broken pipe, Docker receiver failure, permission issue, Secret leak, or platform denial. No actual policy rejection was reported. Correct the **existing** `System.Diagnostics.ProcessStartInfo` anonymous binary stdin transport only. Do not switch to clipboard, docker exec/cp, temp plaintext, host environment/arguments, shell pipe with credentials, another agent/remote host or modified global settings.

Official .NET contract:
- `Process.StandardInput` returns a `StreamWriter` and requires `ProcessStartInfo.UseShellExecute=false` plus `RedirectStandardInput=true`: https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.standardinput?view=net-10.0
- `FileStream.CopyTo(Stream)` copies binary bytes to an existing destination `Stream`, supported on .NET 10: https://learn.microsoft.com/en-us/dotnet/api/system.io.stream.copyto?view=net-10.0
- For the receiving Docker CLI process, `ProcessStartInfo` must have `FileName` set to the verified exact existing docker CLI, `UseShellExecute=false`, `RedirectStandardInput=true`, `RedirectStandardOutput=true`, `RedirectStandardError=true`, `CreateNoWindow=true`; use `ArgumentList.Add` for reviewed **non-Secret** args, no shell interpolation of bytes. Docker command must specify `run -i`, one exact project-owned volume, pinned existing image, `--network none`, a collision-checked unique retained container name and fixed benign receiver, with no host port and no `--rm`. Reuse the **same mechanism and code** for fixture and synthetic credential.
- After successful `Process.Start()`, binary copy only via `([System.IO.FileStream]$source).CopyTo([System.IO.Stream]$process.StandardInput.BaseStream)`; close stdin for EOF, bounded WaitForExit, check exact child/container ID, exit and file status. Do not use `StreamWriter.WriteLine` (potential newline/encoding change) or ambiguous `Write(byte[])` overloads for real Secrets. Do not dump PowerShell pipeline output, raw stderr, `Exception.Message` (may include a private source path), Docker inspect source, or any Secret.
- For error evidence, capture only `STAGE`, `PROCESS_STARTED=YES/NO`, `CONTAINER_CREATED=YES/NO/UNKNOWN`, sanitized exception **type**, `GetBaseException().GetType().FullName`, `HResult`, exit code if known, child container ID, and destination file-exists/empty/unknown. Preserve error evidence, not inner message or Secret path. If process started and outcome ambiguous, read-only classify destination **before** any retry.
